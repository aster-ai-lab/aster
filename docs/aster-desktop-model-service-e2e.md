# Aster 桌面「设置 → 模型服务」端到端用例

本文只规划用例，不执行。对象是租户 `aster` 的桌面宿主（`apps/studio`，产品名 Aster）。设置侧栏「模型服务」进入 `/settings/provider`，页面是本地服务商列表加右侧详情。ToYou 的「模型市场」不是这一页。

密钥、令牌和线上地址只写占位符：`<API_KEY>`、`<API_HOST>`、`<ACCOUNT>`。不要把真实值写进步骤或截图说明。

每条用例都在已经打开的 Aster 桌面窗口里由人操作。起始状态写的是这一条开始前窗口应处的样子。可观察结果是做完步骤后窗口上能直接看到的变化。

Aster 设置侧栏同时还有「通用」「网络搜索」「文档处理」「快捷键」「归档」「关于」。它们出现在同一扇窗口里，但不属于模型服务，本目录不测那些页面。

## 打开页面与整页状态

### MS-01 从设置打开模型服务

- 功能：从主窗口进入设置，再打开模型服务。
- 起始状态：Aster 主窗口已打开，当前不在设置。
- 步骤：
  1. 点主窗口侧栏底部的「设置」。
  2. 在设置左侧点「模型服务」。
- 可观察结果：地址落到模型服务。左侧是服务商搜索框和一份服务商列表，右侧是当前选中服务商的详情。页内标题不是「模型市场」。

### MS-02 列表仍在加载

- 功能：服务商列表加载中。
- 起始状态：刚进入模型服务，服务商数据尚未返回。
- 步骤：在列表出现之前看主区域。
- 可观察结果：主区域是「加载中...」，还没有服务商详情。加载结束后列表和详情一起出现。

### MS-03 列表加载失败后重试

- 功能：首次加载失败时的错误和重试。
- 起始状态：进入模型服务时，服务商列表请求失败，并且本地还没有成功加载过列表。
- 步骤：
  1. 看主区域的错误提示。
  2. 恢复可访问的本地数据后点「重试」。
- 可观察结果：失败时能看到「错误」和失败说明，以及「重试」。重试成功后错误消失，出现服务商列表和一份详情。

### MS-04 用已知 id 深链选中服务商

- 功能：`?id=` 选中列表里存在的服务商。
- 起始状态：模型服务未打开。准备一个列表里一定存在的服务商 id，记为 `<PROVIDER_ID>`。
- 步骤：用应用内入口或地址打开 `/settings/provider?id=<PROVIDER_ID>`，等列表加载完。
- 可观察结果：右侧详情是该服务商。地址上的 `id` 参数随后被去掉。再点开别的设置项又回到模型服务时，仍保持这次选中的服务商。

### MS-05 未知 id 在列表加载后回退

- 功能：`?id=` 在列表已经加载后对不上任何服务商。
- 起始状态：模型服务未打开。
- 步骤：打开 `/settings/provider?id=<UNKNOWN_ID>`。`<UNKNOWN_ID>` 不在已加载的可见服务商里。等列表加载完。
- 可观察结果：加载过程中不会先跳到别的服务商。列表加载完成后，详情落到可见列表的第一项，地址上的 `id` 被去掉。页面不是空白，也不是「模型市场」。

## 服务商列表

### MS-06 搜索服务商

- 功能：按名称或模型名搜索列表。
- 起始状态：模型服务已打开，筛选是「全部服务商」，搜索框为空。列表里至少有两项。
- 步骤：
  1. 在占位符为「搜索模型平台...」的搜索框输入一个已存在服务商名称中的连续片段。
  2. 再改成一个该服务商下某个模型的名称片段。
  3. 输入一个列表和模型名都对不上的词，例如 `nomatch-provider-query`。
- 可观察结果：前两步列表只留下匹配项，不匹配的行消失。第三步列表区显示「无结果」，右侧仍停留在进入搜索前选中的服务商详情。

### MS-07 清除列表搜索

- 功能：清空搜索并恢复列表。
- 起始状态：搜索框里已有文字，列表被收窄或显示「无结果」。
- 步骤：点搜索框里的「清除」，或在搜索框按 Esc。
- 可观察结果：搜索框变空，「清除」按钮消失。列表回到当前筛选下的全部服务商。

### MS-08 筛选全部服务商

- 功能：筛选「全部服务商」。
- 起始状态：模型服务已打开。先把筛选改成「仅已启用」或「仅已禁用」，使列表比全量短。
- 步骤：点搜索框右侧「筛选服务商」，再点「全部服务商」。
- 可观察结果：菜单在「全部服务商」上打勾并关闭。已启用和已禁用的服务商都回到列表。离开模型服务再回来，筛选仍是「全部服务商」。

### MS-09 筛选支持 Agent

- 功能：筛选「支持 Agent」。
- 起始状态：筛选是「全部服务商」，列表里有可对话的服务商。
- 步骤：点「筛选服务商」，再点「支持 Agent」。也可以直接打开 `/settings/provider?filter=agent`。
- 可观察结果：菜单在「支持 Agent」上打勾。当前实现里这项与「全部服务商」显示同一批服务商，因为非 Anthropic 对话模型走本地 API 网关，不会把网关可达的服务商藏掉。用地址进入时，`filter` 参数随后被去掉，筛选仍停在「支持 Agent」。

### MS-10 筛选仅已启用

- 功能：筛选「仅已启用」。
- 起始状态：列表里同时有已启用和已禁用的服务商。已启用行上有状态点。
- 步骤：点「筛选服务商」，再点「仅已启用」。
- 可观察结果：只留下已启用的服务商。已禁用的行不在列表里。若当前详情对应的服务商被筛掉，右侧详情不跟着切换。

### MS-11 筛选仅已禁用

- 功能：筛选「仅已禁用」。
- 起始状态：列表里同时有已启用和已禁用的服务商。
- 步骤：点「筛选服务商」，再点「仅已禁用」。
- 可观察结果：只留下已禁用的服务商。已启用行和它的状态点不在列表里。

### MS-12 选中服务商并保持选中

- 功能：点选服务商，并在再次进入时保持。
- 起始状态：模型服务已打开，列表至少有两项。
- 步骤：
  1. 点列表中不是当前详情的一项。
  2. 点设置侧栏的「通用」，再点回「模型服务」。
  3. 关掉设置，再从主窗口「设置」进来，再点「模型服务」。
- 可观察结果：第 1 步后被点的行是选中态，右侧标题换成该服务商。第 2 步和第 3 步回来后，仍是该服务商，而不是列表第一项。

### MS-13 展开或折叠服务商分组

- 功能：同一预设下有多个实例时的分组。
- 起始状态：列表里至少有一个预设拥有两个及以上实例，因此出现分组头。
- 步骤：点分组头。再点一次。搜索框输入能命中组内某一实例的文字，然后清空。
- 可观察结果：第一次点击展开组内实例，分组头是展开态。第二次收起，组内行不可见；若选中项在组内，收起的分组头仍标出含有选中项。搜索时该组强制展开并能看到命中的实例。清空搜索后，组回到搜索前的折叠或展开状态。

## 添加服务商

### MS-14 添加服务商

- 功能：打开添加服务商。
- 起始状态：模型服务已打开，没有正在拖拽的行。
- 步骤：点列表底部「添加服务商」。
- 可观察结果：出现添加抽屉。里面有提供商名称、提供商类型，以及可选的「从预设创建」。名称留空时不能提交，并提示需要名称。

### MS-15 添加时填了密钥，下一步是选模型

- 功能：新建自定义服务商时已经提供 `<API_KEY>`。
- 起始状态：添加抽屉已打开。
- 步骤：
  1. 名称填一个列表里没有的名字。
  2. 在密钥栏填 `<API_KEY>`，不要填真实密钥。
  3. 提交。
- 可观察结果：新服务商出现在列表并被选中。接着自动打开配置，当前步是「选择模型」，而不是先要求再填一次密钥。可以全选、取消全选、手动添加模型、跳过或保存并关闭。关闭后详情停在这个新服务商。

### MS-16 添加时没填密钥，下一步是填 API 密钥

- 功能：新建自定义服务商时不提供密钥。
- 起始状态：添加抽屉已打开。
- 步骤：只填一个新名称，密钥留空，然后提交。
- 可观察结果：新服务商被选中。自动打开的配置停在「添加 API 密钥」。密钥为空时不能进入下一步。填入 `<API_KEY>` 并继续后，才进入「选择模型」。

## 行上的编辑、实例、删除和排序

### MS-17 编辑服务商

- 功能：编辑已有服务商。
- 起始状态：选中一个允许管理的服务商（自定义服务商，或同一 id 出现多次的行）。
- 步骤：点该行右侧更多按钮，或在该行右键，点「编辑」。改名称后保存。再点取消路径：重新打开编辑，改一个字后关闭且不保存。
- 可观察结果：保存后列表行和右侧标题都变成新名称。不保存的那次，名称保持打开编辑前的值。

### MS-18 在提供「添加实例」时复制服务商

- 功能：从预设再加一个实例。
- 起始状态：选中的行不是 `aster`，它有预设来源，并且这个预设还没有因为多个实例被收成一组。行菜单里能看到「添加实例」。
- 步骤：打开行菜单，点「添加实例」。在抽屉里确认后保存。
- 可观察结果：菜单文案是「添加实例」。保存后列表多一行同一预设的实例，并选中新行。若该预设因此达到两个实例，它们收成一个可折叠分组。`aster`、已经分组的预设、以及菜单里没有「添加实例」的行，不出现这个动作。

### MS-19 删除服务商并确认

- 功能：删除前提示确认。
- 起始状态：选中一个允许管理、且允许删除的服务商。记下它的名称。
- 步骤：
  1. 打开行菜单，点「删除」。
  2. 在确认框点取消。
  3. 再次点「删除」，在确认框点删除。
- 可观察结果：确认框标题是「删除提供商」，正文是「确定要删除此模型提供商吗？」。取消后该行还在。确认后该行消失。若它是当前详情，详情改到剩余列表中的一项。不允许管理的系统行不提供删除。

### MS-20 拖拽调整顺序

- 功能：拖拽服务商或分组改变顺序。
- 起始状态：筛选为「全部服务商」，列表至少有两项。搜索框为空。
- 步骤：按住某一行左侧的拖拽把手，把它拖到另一项的上方或下方后松开。对分组则拖分组头的把手。
- 可观察结果：松开后新顺序留在列表里。拖拽过程中搜索、筛选和「添加服务商」不可用。离开页面再回来，顺序仍是松开时的顺序。若保存失败，出现「调整服务商顺序失败」，顺序回到拖之前。

### MS-21 服务商备注

- 功能：行菜单里的备注。
- 起始状态：模型服务已打开，任一服务商行可选。
- 步骤：打开该行菜单，点「模型备注」。写一句备注并保存。再打开一次。
- 可观察结果：弹出标题为「模型备注」的编辑框。保存后再次打开能看到刚才的备注。这不改变服务商名称。

## 详情头部

### MS-22 服务商名称

- 功能：详情标题显示当前服务商名称。
- 起始状态：已选中一个服务商。
- 步骤：看详情顶部标题。再点列表另一项。
- 可观察结果：标题是当前服务商名称。换选后标题跟着变，不保留上一个名称。

### MS-23 有官网时的名称链接

- 功能：名称上的官网链接。
- 起始状态：选中一个带官网地址的服务商。名称是链接，辅助说明里带「官方网站」。
- 步骤：点标题上的服务商名称。
- 可观察结果：系统浏览器打开该官网。Aster 窗口仍停在这个服务商详情。没有官网的服务商，名称是普通文字，点它不会打开浏览器。

### MS-24 API 设置

- 功能：打开 API 选项。
- 起始状态：选中的服务商标题旁有「API 设置」按钮。没有这个按钮的服务商不适用本条。
- 步骤：点「API 设置」。逐项查看并切换可见开关，然后关闭。再打开一次。
- 可观察结果：抽屉标题围绕 API 设置。可见项按该服务商而定，可能包括「支持 Developer Message」「支持 enable_thinking」「支持思考摘要」「支持 stream_options」，以及 Anthropic 缓存相关的「缓存系统消息」「缓存最后 N 条消息」「缓存时长」「缓存 Token 阈值」。关闭再打开，刚才保存的开关状态还在。

### MS-25 启用开关

- 功能：启用或禁用当前服务商。
- 起始状态：详情已打开。看列表里该行是否有启用状态点，记下开关当前方向。
- 步骤：点详情右上角的开关。等它结束。再点一次拨回去。
- 可观察结果：拨到开启后，该行出现启用状态点；拨到关闭后状态点消失。在「仅已启用」或「仅已禁用」筛选下，行会按新状态进入或离开列表。保存失败时出现「保存失败」，开关回到拨动前。

## 连接：地址、密钥、请求头和检测

登录型服务商（Claude Code、Codex、Grok CLI 等）不显示下面的通用密钥和 API 地址，改走对应的条件面板。

### MS-26 API 地址

- 功能：查看、修改、复制和重置 API 地址。
- 起始状态：当前服务商显示「API 地址」。
- 步骤：
  1. 看地址栏。空的时候占位是「未配置」。
  2. 把地址改成 `<API_HOST>` 后离开输入框。
  3. 点复制。
  4. 点「重置」。
  5. 再输入一段不是 http 或 https 的文字并离开输入框。
- 可观察结果：合法地址会留下，并在有预览时显示「预览：」。复制后剪贴板是该地址。重置回到这个服务商的默认地址。非法地址不会被当成有效配置，并出现「API 地址不合法」或等价的无效提示。需要 Azure 版本的服务商另外有「API 版本」字段。

### MS-27 添加 API 密钥

- 功能：为当前服务商新增一把密钥。
- 起始状态：详情显示「API 密钥」。可以是还没有密钥，或已经有一把。
- 步骤：点「添加 API 密钥」，输入 `<API_KEY>` 并保存。再试一次空字符串，以及一把已经存在的相同密钥。
- 可观察结果：合法新密钥出现在密钥区，输入框清空。空密钥提示「API 密钥不能为空」。重复密钥提示「API 密钥已存在」。不要让真实密钥留在窗口或文档里。

### MS-28 密钥列表

- 功能：打开多密钥管理。
- 起始状态：当前服务商至少有一把密钥，密钥区有「API 密钥管理」。
- 步骤：点「API 密钥管理」。
- 可观察结果：抽屉标题是「API 密钥管理」，说明是管理当前服务商的多个 API Key。每行能看到掩码后的密钥。没有密钥时，抽屉里是无密钥说明，而不是一份空白表。

### MS-29 显示或隐藏密钥

- 功能：切换密钥明文。
- 起始状态：密钥栏或密钥抽屉已打开，当前是掩码。
- 步骤：点「显示密钥」。看完后点「隐藏密钥」。
- 可观察结果：显示时能看到完整占位密钥。隐藏后回到掩码。按钮的名字在「显示密钥」和「隐藏密钥」之间切换。

### MS-30 复制密钥

- 功能：复制某一把密钥。
- 起始状态：密钥行上有「复制」。
- 步骤：点「复制」。
- 可观察结果：剪贴板变成这把密钥的文本。界面上的密钥行还在，不会因为复制而被删掉。

### MS-31 密钥标签

- 功能：给密钥写标签。
- 起始状态：「API 密钥管理」已打开。
- 步骤：编辑一行，在占位符为「标签」的输入里写一个标签并保存。关闭抽屉再打开。
- 可观察结果：该行显示这个标签，而不是只有默认的「API Key」。取消编辑则标签不变。

### MS-32 启用或禁用单把密钥

- 功能：密钥行上的启用开关。
- 起始状态：密钥管理里至少有一把密钥。
- 步骤：拨动该行的开关。关闭抽屉再打开。
- 可观察结果：开关状态被记住。禁用的密钥不参与后面的「所有密钥」检测。抽屉顶部的「已启用」计数跟着变。

### MS-33 自定义请求头和图像端点

- 功能：请求配置里的自定义头，以及图像端点。
- 起始状态：API 地址旁有请求配置入口，提示为「请求配置」。
- 步骤：
  1. 打开请求配置。
  2. 在键值列表里点「添加请求头」，名称填 `X-Test-Header`，值填 `<HEADER_VALUE>`，保存。
  3. 切到 JSON 编辑，确认能看到刚写的头，再切回键值列表。
  4. 若该服务商有图像端点，填写「图像生成 Base URL」和「图像编辑 Base URL」为 `<API_HOST>` 后保存。
  5. 用非法 JSON 试保存。
- 可观察结果：合法请求头保存后再打开仍然在。JSON 和键值列表是同一份头。图像端点只在这个服务商提供该栏时出现；非法地址不能保存。非法 JSON 提示「JSON 格式错误」，已保存的头不被改掉。

### MS-34 连接检测

- 功能：检测当前连接和单个模型。
- 起始状态：当前服务商已有至少一把启用的密钥，或该服务商允许无密钥检测，并且模型列表里至少有一个可检测模型。密钥区有「检测」。
- 步骤：点「检测」。在对话框里保持「单个」，选一个模型和一把密钥，开始检测。
- 可观察结果：按钮在检测过程中变为「检测中」且不能重复点。对话框给出成功、失败或跳过。失败时能看到「连接失败」一类说明。没有任何模型时，若服务商还缺模型，「检测」会改去继续「选择模型」，而不是假装检测成功。

### MS-35 检测所有密钥

- 功能：一次检测全部已启用密钥。
- 起始状态：当前服务商至少有两把启用的密钥，检测对话框可以选密钥范围。界面文案是范围里的「所有」，不是单独一颗「检测所有密钥」按钮。
- 步骤：点「检测」。把密钥范围从「单个」改成「所有」，然后开始检测。
- 可观察结果：检测按每把已启用密钥分别给出结果，而不是只报第一把。被禁用的密钥不在这次结果里。只有一把启用密钥时，不需要也不展示多密钥切换。

## 模型列表

### MS-36 模型列表标题

- 功能：详情里的模型区标题。
- 起始状态：已选中一个非托管的服务商。
- 步骤：看详情中部的小节标题。换一个服务商。
- 可观察结果：标题是「模型」。换服务商后标题仍是「模型」，下面的行换成新服务商的模型。

### MS-37 有文档时的文档链接

- 功能：模型文档外链。
- 起始状态：选中一个提供了模型文档或模型列表网址的服务商。标题旁有「模型文档」。
- 步骤：点「模型文档」。
- 可观察结果：浏览器打开该文档或模型列表页。没有文档地址的服务商不显示这个图标。

### MS-38 搜索模型

- 功能：在模型区搜索。
- 起始状态：当前服务商有多个模型，搜索是收起的放大镜。
- 步骤：点「搜索」。输入一个已有模型的名称片段。再改成对不上的词 `nomatch-model-query`。
- 可观察结果：搜索框占位是模型搜索提示。匹配时只留下匹配的模型，分组会展开以便看到命中项。对不上时模型区显示「无结果」。

### MS-39 清除模型搜索

- 功能：清空模型搜索。
- 起始状态：模型搜索框里有文字。
- 步骤：点搜索框内的「清除」。再点一次「搜索」后不输入，让输入框失焦。
- 可观察结果：清除后全部当前类型的模型回来，搜索框收起。空输入框失焦后也会收起。有文字时失焦不会把文字清掉。

### MS-40 按类型筛选模型

- 功能：模型类型筛选。
- 起始状态：当前服务商至少有两种类型的模型。
- 步骤：点「筛选模型」。在出现的类型条上依次点「全部」和一个具体类型，例如「文本」「图片」「嵌入」「音频」「视频」「重排」「语音」「转录」中列表里实际有的那一个。
- 可观察结果：类型条上每一项带数量。选中某一类型后只显示该类型。选「全部」恢复。没有模型时「筛选模型」不可点。类型条超出宽度时可以左右滚动。

### MS-41 展开或折叠模型分组

- 功能：模型分组的全部展开和全部折叠。
- 起始状态：当前服务商的模型分成至少两组，分组是展开的。
- 步骤：点「全部折叠」。再点「全部展开」。然后在搜索框输入一个位于某一组内的模型名。
- 可观察结果：折叠后组内模型不可见，按钮变成「全部展开」。再次点击后组内模型可见。搜索时分组被展开，从而能看到命中项。没有模型时这个按钮不可点。

### MS-42 手动添加模型

- 功能：打开手动添加模型。
- 起始状态：当前服务商不是 OVMS，模型工具条上有「手动添加模型」。没有正在进行的检测。
- 步骤：点「手动添加模型」。
- 可观察结果：打开添加模型抽屉。OVMS 这一位换成模型下载，而不是这个加号。检测进行中时按钮不可点。

### MS-43 编辑模型身份

- 功能：改模型 ID、名称和分组。
- 起始状态：模型行上有「设置」。点它打开编辑抽屉。
- 步骤：改「模型名称」。看「模型 ID」。能改分组时改分组。保存或等自动保存完成，然后关闭再打开。
- 可观察结果：列表行显示新名称。模型 ID 按该模型是否允许修改：不允许时输入框不可编辑。非法或空的必填 ID 不能被保存成空名称。未改的价格和窗口值保持原样。

### MS-44 编辑模型分类

- 功能：改模型主类型、能力和输入模态。
- 起始状态：模型编辑抽屉已打开，能看到分类。
- 步骤：切换主类型（文本、图片、嵌入、重排之一）。再切换能力（推理、函数调用）和输入模态（视觉、音频、视频）中该抽屉提供的项。关闭再打开。
- 可观察结果：选中的类型和能力保持。列表上的类型标记与新分类一致。类型筛选里的数量跟着变。

### MS-45 编辑上下文窗口

- 功能：改上下文窗口和最大输出。
- 起始状态：模型编辑抽屉已打开。
- 步骤：把「上下文窗口」改成一个正整数并离开输入框。把「最大输出 Token」清空并离开。再试输入 0 或带小数。
- 可观察结果：合法整数被保存。清空的上限变成未设置，而不是 0。低于最小值的输入会在离开输入框时收到纠正或校验提示，不会把窗口存成 0。

### MS-46 编辑端点类型

- 功能：改模型端点类型。
- 起始状态：编辑抽屉里有「端点类型」。
- 步骤：换一个端点类型，或在多选芯片里增减一项。
- 可观察结果：选择被保存。没有可用端点时，该栏给出需要选择端点的提示，而不是静默成功。

### MS-47 编辑价格

- 功能：改币种和价格档。
- 起始状态：编辑抽屉里有价格区。
- 步骤：
  1. 改「币种」。
  2. 填写「输入价格」和「输出价格」。
  3. 点「添加价格档位」，给新档一个比上一档更大的起始 Token，并填价格。
  4. 试一个非数字，以及一个与上一档相同的起始 Token。
- 可观察结果：币种切换后各档都使用新币种。合法价格保存后再打开仍在。缓存读、缓存写可以留空。非数字不能输入进去。重复或倒序的档位边界出现校验提示，并且不会保存这一档。

### MS-48 编辑模型用途

- 功能：改模型用途。
- 起始状态：添加或编辑抽屉显示「模型用途」。添加自定义模型时才会要求选择用途；编辑已有模型时若没有这一栏，本条跳过。
- 步骤：选择一个用途。若有「对话协议」一类选项，切换它。保存。
- 可观察结果：用途被记住。未选用途时不能完成添加。用途不改变模型 ID。

### MS-49 删除模型

- 功能：从行上删除模型。
- 起始状态：有一个不是默认模型的行，行上有「删除模型」。
- 步骤：点「删除模型」。再对一个被标成默认、删除按钮不可用的模型看它的说明。
- 可观察结果：可删除的模型从列表消失。默认模型的删除不可用，并说明原因。删除失败时出现错误提示，模型还在。检测进行中时删除和行上的「设置」都不可点。

### MS-50 同步模型

- 功能：从服务商拉取模型并勾选同步。
- 起始状态：工具条有「同步模型」。当前服务商的地址和密钥足够发起一次拉取；测试时使用 `<API_HOST>` 和 `<API_KEY>`，不要写真实值。
- 步骤：
  1. 点「同步模型」。
  2. 等列表出现后，用抽屉里的搜索过滤。
  3. 勾选一个本地还没有的模型并添加。
  4. 对一个本地已有、且允许移除的模型执行移除。
  5. 若出现过期模型，点清理过期模型。
  6. 在拉取失败时点刷新或重试。
- 可观察结果：抽屉列出远端模型。搜索无命中时显示「无结果」。添加后该模型出现在详情的模型列表。移除后它从本地列表消失。默认模型和纯本地自定义模型不能被批量移除。拉取失败时抽屉给出失败说明和重试，不清空已经显示的本地模型。没有模型时，空列表文案是「请选择模型」，提示去点「同步模型」。

### MS-51 健康检查

- 功能：对模型做健康检查并看到状态。
- 起始状态：已完成一次 MS-34 或 MS-35 的检测，或准备再跑一次。
- 步骤：在检测对话框查看单个模型的结果。再对多个模型发起检查，并打开或关闭并发。看模型行上的状态。
- 可观察结果：每个被检查的模型有成功、失败或跳过之一。跳过的模型带有原因，不能被选去检查。并发开关只影响这一轮怎么发，不改变最终每条结果仍落在对应模型上。关掉对话框后，行上的状态还在，直到模型被删或重新检查。

### MS-52 模型区为空或没有匹配

- 功能：没有模型，以及搜索不到。
- 起始状态：准备两个服务商，或同一服务商的两种时刻。一个没有任何模型。另一个有模型。
- 步骤：
  1. 打开没有模型的服务商。
  2. 打开有模型的服务商，搜索 `nomatch-model-query`。
  3. 若服务商已有启用密钥但还没有模型，看空状态上的继续配置。
- 可观察结果：没有模型时看到「请选择模型」和「点击上方的“同步模型”添加模型」。搜索无匹配时看到「无结果」，而不是空状态引导。已有启用密钥却没有模型时，出现「API 密钥已保存。请选择至少一个模型以完成配置。」以及继续选择模型的入口。全部密钥都被禁用时，不提供这个继续配置。

- 功能：保持活跃时间。

- 起始状态：该服务商的请求配置已打开。
- 步骤：两个地址都填 `<API_HOST>` 并保存。再把其中一个改成不是网址的文字并保存。
- 可观察结果：合法地址保存后再打开仍然在。非法地址不能保存，并指出是哪一个图像端点。没有这两栏的服务商跳过本条。

## 不在 Aster 这一页

下列能力属于 ToYou 构建，或被 Aster 设置侧栏拿掉。在租户 `aster` 上不要把它们当成模型服务的用例。

| 表面 | 为什么不算 |
| --- | --- |
| 模型市场 | ToYou 打开「模型服务」时渲染模型市场，标题是「模型市场」。Aster 这一页是本地服务商列表。 |
