# Native OCR plugin migration — 2026-11-02

The complete OCR capability is now `aster/aster-ocr`: native executable, ONNX
Runtime, PP-OCRv6 detection/recognition models, notices, stdio MCP and the canonical
`aster-use-ocr` Skill. The archive is produced and checked by the native AIX SDK;
OCI, catalog and executable planning bytes are also generated by that SDK.

Studio uses the existing `McpManager`, retains the native package lease, preserves
host-owned source evidence, and starts OCR only on demand. Its provider-neutral
OCR dependency has no engine feature. The document component contains PDFium and
fonts. The default macOS packaging path consumes released pins and defers large
components. Unchanged versions/digests reuse the same native generation.

The old OCR repository was deleted and HTTP 404 verified after backing up its Git
history and all four release assets, checking their published lengths/digests,
and qualifying real recognition and the replacement GHCR archive. The verified
backup remains at `target/ocr-migration`; its identities are recorded in
`ocr-repository-migration.json`. Active Rust and desktop build paths no longer
fetch from that repository.

## Distribution gate

All four official GHCR packages are private. Anonymous token requests return
HTTP 401, and a real native installation-plan request returns
`use.extension.registry_oci_invalid` for that reason. GitHub's package settings
show Public disabled by organization policy. Enabling the organization's public
package policy needs the user's pending approval. Anonymous installation and the
slim desktop release gate remain unqualified; no desktop Release or channel
manifest was published. The README states this limitation.

Only macOS ARM64 was runtime-qualified. Linux/Kylin, Windows, other CPUs, and a
complete new signed desktop archive were not qualified by this task.
