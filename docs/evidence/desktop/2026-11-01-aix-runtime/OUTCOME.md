# Native AIX desktop runtime components

Date: 2026-11-01–02. Host: macOS ARM64. Rust: pinned 1.97.1.

## Behavior

Sandbox, Document (including ONNX Runtime) and Office use the native Aster AIX
builder, TUF catalog and extension lifecycle. First entry installs missing required
components. Office downloads on first use in a slim installation. Enabled receipts
with the same version, expanded-package digest and manifest digest reuse their
existing immutable generation. Storage is scoped to the desktop tenant profile.

A base-only release consumes a published component lock and does not invoke the
component builder. Two consecutive base version changes preserve component pins.
The complete bootstrap imports its bundled native assets through that same SDK
lifecycle, including offline adoption for later slim updates. Final archive checks
derive required membership from the owning source contract.

The first migration release remains complete by default because older desktop
updaters require the bundled native files. Slim stable releases require a verified
public registry and the complete component-aware bridge release first.

## Native artifact provenance

The initial three AIX candidates wrap the already published desktop v0.1.11
macOS ARM64 resources. The source ZIP is 275,433,346 bytes and SHA-256
`952707ed923cbd5665b42f1df7bf2315de658ba1a10e5ad6bb5067455476e08e`,
matching the official GitHub release asset. A second extraction from that verified
archive reproduces each plugin's content version, manifest and expanded-package
digest, file membership and permissions. The two CLI builds produce different
compressed ZIP bytes; released archives and their locks stay immutable.

The existing app contains 562,850,115 logical bytes. The assembly-only slim
candidate contains 211,038,664 logical bytes after deferring the three runtime
components and removing the duplicate external renderer assets. This is a size
measurement, not a newly signed, runnable or published desktop release. Embedded
embedding models retain their existing offline contract.

## Official trust and publication

The official source is https://github.com/aster-ai-lab/plugins. Public root SHA-256:
`e1cf8be656c072939721b765eef12a597c668fe9c33cc0de2379370d3879ae9b`.
Root signing uses the local macOS Keychain; only the separate targets, snapshot and
timestamp keys are repository secrets. Public metadata passes the native client's
TUF verification. The daily online-signing workflow passed:
https://github.com/aster-ai-lab/plugins/actions/runs/41321817117.

GitHub package publication and anonymous access are recorded in the accompanying
publication evidence. New GHCR packages default to private. Public visibility and
fresh anonymous installation must pass before enabling slim stable distribution.
The browser connection was unavailable, so the user was asked to set the three
runtime packages public. No personal GitHub credential is embedded in the product.

Native CLI installation currently reaches GHCR and refuses HTTP 401, matching
the recorded private package visibility. Release qualification also exposed that
the first 70-character component versions exceed the frozen 64-character plugin
selector limit. Compatible candidates use a 46-character content version while
retaining full SHA-256 integrity fields. The frozen SDK tool schema is unchanged;
the original candidate archives remain intact pending the compatible publication.
