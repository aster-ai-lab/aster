# Desktop native alignment

Implemented within the 23 source/test paths frozen in [native-source-final.json](native-source-final.json). Desktop keeps its existing organization gateway admission and independent application identity. No Work development credentials, default model seed, or new public ACP method were introduced.

## Root causes and repairs

| Boundary | Before | Repair |
| --- | --- | --- |
| Approval ownership | Native receiver map carried only a boolean sender; attach/reconnect lacked an authoritative live approval tuple. Stop could leave a receiver available until settlement. | Bind session plus execution, anchor, assistant message, approval and tool call. Check the complete tuple under the live lock, consume once, publish authoritative `pendingApprovals` (including empty), and withdraw synchronously on Stop. Historical rows do not recreate receivers. |
| Owned forms | A retained form with the same assistant anchor could cross a changed execution/attempt; generic permission/form RPCs did not check their ACP session. | Require current execution and attempt as well as anchor and cancellation state. Require the request's explicit `sessionId` to equal the active prompt's ACP session; foreign/missing sessions receive `-32602`, without creating controls. This uses the active worker session, not an assumed primary runtime session. |
| Planning | Per-turn planning intent and independent permission posture were not carried on the native prompt wire. | Strict boolean `turnContext.planFirst`, `_meta.a3sTurn.planFirst`, and independent `_meta.permissionPosture`. Reject malformed planning input before turn admission and refuse planning through nonlocal lanes. The actual workspace ACP enforces the write restriction. |
| Stops | Successful transport completion could be treated as successful task completion despite incomplete/refused stop reasons. | Only explicit `end_turn`, or scoped typed `read_only_evidence` with `max_turn_requests`, can succeed. Preserve cancellation. Tool budget, truncation, missing/unknown stop reasons, conflicting outcomes, and malformed/unknown forced outcomes fail. `InvalidOutcome` is a private failure sentinel, not a new public terminal reason or an asserted budget fact. |
| Goal authority | Desktop had no complete typed native snapshot path. A retained local process could otherwise expose an old goal after a nonlocal admission; concurrent reads could publish out of order. | Existing ACP state RPC adds read-only preview `tick`. Desktop projects required typed fields and actual ACP binding to GET, attach and SSE. Per-runtime reads serialize through publication; a single one-second deadline includes registry-lock wait, read-lock wait, RPC and final registry reacquisition. Runtime, owner and admission are rechecked after awaits. Missing fields/old agents fail closed. |
| Raw ACP framing | Handwritten stdio transport used an internal extension method name as a raw request and did not decode extension notification prefixes. This was exposed by the actual companion, beyond permissive fake coverage. | Send raw `_a3s/goal/state` for internal `a3s/goal/state`. Decode exactly one notification prefix, preserving standard `session/update`, refusing unprefixed nonstandard notifications and extension impersonation of that standard name. Requests retain their existing raw dispatch names. Actual raw notifications are `_a3s/turn/outcome` and `__a3s/execution/observe`; decoded consumers keep their internal names. |
| RPC acknowledgement | A reply containing neither result nor error became `Ok(null)` and could acknowledge an unconfirmed mode. | Require JSON-RPC 2.0 and exactly one result/error. Explicit `result:null` remains valid. Dropped/timed-out reads remove their pending callback through ownership, without retaining an abandoned waiter. |
| Model defaults | Provider defaults and the three device model preferences could diverge; persistence failure could leave in-memory defaults changed. | Synchronize all three device model values, retain member scope for other preferences, restore defaults on synchronous persistence errors, and preflight merged revision overflow before either preference file changes. Preserve managed/disabled-model rejection and explicit packaged tenant/instance identity. |

## Evidence classification

The original [native-before-direct-r4.log](native-before-direct-r4.log) compiled the complete real Desktop test crate, then recorded 13 failures: nine direct assertion failures and four bounded transport deadlines. Those four deadlines are not claimed as proof of their eventual intended assertions. The earlier Cargo compilation/pre-main diagnostics and lock delays were infrastructure evidence, not behavioral failures.

Small additional before cases independently demonstrated concurrent goal reads (`max=2`), mixed preference revision overflow after writes, an unbounded initial registry lock, same-anchor form ownership crossing, missing nullable plan revision acceptance, unknown forced-stop acceptance, missing notification decoding, foreign permission admission, and an incomplete reply acknowledged as null. Logs retain those distinct failures. The initial actual companion run also exposed the missing raw RPC prefix. A subsequent execution timeout was fixture failure to answer a legitimate live approval; phase/route tracing showed the receiver and a healthy loopback server. The test now supplies a correctly bound approval and does not relax permission policy or the ten-second per-event deadline.

Final results and binary/source identities are recorded in [native-final-validation.json](native-final-validation.json). Suite counts overlap; the receipt deduplicates passed test names. The final direct compilation is [native-final-freeze-compile.log](native-final-freeze-compile.log). This is the actual Desktop `lib.rs` test crate with exact Cargo-fingerprint dependency snapshots, not extracted functions or substitute implementations. Root's canonical `just build-desktop`, release/package, Linux and GUI gates remain separate evidence.

The actual workspace ACP regression uses only a private loopback OpenAI-compatible provider and an isolated child environment. It verifies per-turn planning rejects the provider's write; the next normal turn receives a real bound approval, rejects a wrong execution, accepts once, writes and reads the marker; typed goal state is known, then a real explicit native goal progresses through active/needs_input, paused/paused and cancelled/null tick. Bounded test-only tracing records method names only and proves native Run observations reach status. See [native-freeze-real-acp.log](native-freeze-real-acp.log). Actual `toolCallId` values are unique per model stream.

The separate root-workspace Cargo ACP goal suite is [native-goal-acp-private-after.log](native-goal-acp-private-after.log): 7 passed, 2 explicitly live-model tests ignored. Its maintained read-only preview test holds the turn queue and compares the actual workspace fact log before and after state inspection. Scoped Rust formatting and diff checks pass in [native-scope-format.log](native-scope-format.log).

## Scope and limits

- Goal inspection does not start a runtime, execute a goal tick, append facts, or recover a host after restart. A renderer reconnect can inspect a still-live bound runtime; no runtime returns explicit unavailable. No goal authority is inferred from prose, `/goal` text, history or the configured display label.
- The existing independent provider JSON and preference ACL stores have synchronous rollback; no power-loss transaction across those stores is claimed.
- GUI fixture data is entirely synthetic, created only in a new owned Desktop instance; no real member session was copied. The native library tests already kept member-session storage in memory before this change; the new spawn seam makes gateway/environment dependencies deterministic and is not presented as a repair for a demonstrated prior credential leak.
- The GUI mock's managed provider can be enabled and its known model listed; organization-managed `set_defaults` remains refused. The fixture seeds the three device ACL values explicitly and supplies the exact synthetic organization-model catalog. No real authentication or external model service is exercised.
- The maintained native tests and actual ACP regression do not by themselves certify complete native GUI, updater installation or physical input behavior. Root owns those independent acceptance runs and cleanup of its own GUI profiles/processes.
