## Findings closed

1. Same-runtime goal RPC replies could arrive out of order. The [before case](native-goal-order-before.log) observed two concurrent RPCs and failed. The private per-runtime `goal_read` mutex now serializes RPC plus publication; runtime pointer, live owner and admission checks remain after awaits. Its maintained test and the delayed response across idle nonlocal admission pass.
2. The goal deadline began after acquiring the runtime registry lock. The [held-lock negative](native-goal-lock-before.log) exceeded the observation deadline. One one-second deadline now covers the registry, per-runtime queue, RPC and final registry revalidation. Timeout returns typed unavailable without publishing stale authority.
3. The raw goal extension name was wrong. An actual workspace companion rejected the bare internal spelling. Product stdio now sends `_a3s/goal/state`; the strict peer and actual companion prove known active, paused and cancelled goal states. Internal/shared public method names remain unchanged.
4. Raw outcome and observation notifications bypassed the pinned library’s decoding boundary. The final native adapter keeps standard `session/update`, strips exactly one underscore only from extension notifications, preserves remaining underscores, drops bare custom names and forbids `_session/update` impersonating a standard message. Actual companion traces contain `_a3s/turn/outcome` and `__a3s/execution/observe`; native terminal/Run consumers now act. [The complete mechanism map](ux-acp-wire-map.md) records every production method and direction.
5. Matching incomplete responses could count as acknowledgements. The adapter now requires JSON-RPC 2.0 and exactly one explicit result/error field. Explicit `result:null` remains valid; missing, conflicting and wrong-version responses fail their callback and cannot update posture caches. Actual stdio negatives pass.
6. Ordinary permissions and forms did not check the current prompt’s ACP session. The common dispatch now refuses missing/foreign `sessionId` before receiver registration, using the `run_prompt` argument so review workers retain their own session binding. The maintained real peer confirms no UI authority and reads the actual `-32602` response. Typed question/document protocols retain their own existing identity checks; the query-only encyclopedia protocol is not given a guessed session field.
7. Closed protocol handling admitted incomplete goal/stop values. Goal `plan_revision` must now be explicitly nullable; missing or zero refuses projection. Present unknown/nonstring forced stops become failure, while absent/null retains ordinary semantics. Conflicting terminal notifications cannot turn a budget failure into success; foreign session/prompt/epoch is ignored. Form submit also checks execution/attempt, preventing same-anchor reuse.
8. Approval authority had incomplete executable negatives. Strict DTO missing/extra fields, all five incorrect binding fields, foreign session, exact single use, abort withdrawal and reconnect now have passing maintained cases. Saved rows alone never grant authority.
9. Native boolean permission receivers could not transmit advertised rejection notes. Native `allowRejectionReason=false` hides the note action and excludes a previously typed note after capability withdrawal. Default true preserves other transports and existing IME handling. [The actual UI negative](ux-permission-capability-before.log) and its 46-case [after suite](ux-permission-capability-after.log) cover the capability boundary.
10. A merged device/member preference commit could overflow its revision after a partial write. Capacity is checked before either write; stale CAS conflicts and synchronous compensation remain. Three declared model defaults share device scope without broadening model eligibility or tenant fallback.
