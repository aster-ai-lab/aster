# 摘要生成限额候选已拒绝并撤回

将摘要正文额度直接用于现有 `LlmClient::with_output_cap`，虽然能够限制生成请求，却破坏了真实长程任务的完成能力。两项原始任务均失败，候选没有作为有效优化发布；原 checkout 和已批准的隔离 worktree 中三个候选文件均恢复到精确前像。用户现场删除验收修复 `bef171d2c` 保留。

## 固定条件与检查

使用原 `./.aster/config.acl` 的 `glm-01/glm-5.3`，只核对配置 hash。原始任务、输入、提示、grader、40 请求、4096 全局输出、holdout 24576/feed 16384 上下文、600 秒 prompt 与 1800 秒 workflow 截止均保持原值；候选改变的是两个内部摘要调用的生成上限。

复用同一个已授权 worktree，未创建额外 worktree。CLI、ACP 及三个测试器一起构建、冻结，五个成员身份一致：`aster-cli-pair-v1:15e67cdf9f0e22ca50f1140b7531dda96111387c:aarch64-apple-darwin`。完整构建、冻结及逐阶段日志保留在本地相邻目录。

生成请求回归先有 0/2 通过，修复后 2/2 通过；五种实际 provider 客户端均保持原有更低上限及父客户端配置。Core default/CLI JSON/minimal 各 333 通过、1 忽略，ACP 控制 33 通过，Core/ACP all-target Clippy exit 0。组合已发布删除修复后，最终 CLI JSON 回归 335 通过、1 忽略，进程 123.582705 秒；不同选择和构建条件下的效率百分比为 N/A。重复配置复用同一批测试，不相加为独立场景。

这些检查使用 `cargo test --locked --offline -p aster-core --lib` 的 compaction/carry/fact-control/上下文/后台子智能体/provider 公平性/output-cap 选择；具体命令及本地 target-dir/profile 参数在本地 `connected-status.json`、`final-compat-status.json`。候选源码格式通过，工作区格式另有 63 个未修改路径失败，本次三个文件交集为零。
