# 摘要输入可容纳时保留完整观察

事实循环的摘要入口原先直接按工具输出保护额度裁剪，没有先判断完整摘要请求是否能放入模型窗口。一个可容纳的较早观察会在摘要模型看到它之前被删除；这与模型算错、提供方输出截断是不同问题。

现在先构造完整摘要请求，复用 estimate_prompt_tokens 计算系统指令和正文，并沿用原有约四分之一窗口的回复余量。能够容纳时完整交付观察；超出时继续使用原有工具输出裁剪。没有增加配置、依赖、调度器、计量器或每次压缩的模型调用，没有改变 provider 输出额度、摘要正文上限或义务封装。

## 红绿证据

同一个 RecordingSummaryClient 捕获实际 summarize_folded_prefix 传入的模型输入。新增用例使用独立 UTF-8 观察，完整输入明显低于原有预算，要求所有原始字节进入摘要模型。原有超预算用例仍要求裁剪旧工具输出。没有本题字段、答案、公式或任务专用分支。

两项检查 1/2→2/2 通过，通过率增加 50 个百分点。进程 82.346→74.705 秒（−9.28%），包含构建缓存差异，不是任务提速；模型请求为零。首次 green 构建有 E0308/E0599，41.358 秒，未执行测试；改用既有构造接口和共享估算器后重新完成全部检查，原始失败记录保留。
