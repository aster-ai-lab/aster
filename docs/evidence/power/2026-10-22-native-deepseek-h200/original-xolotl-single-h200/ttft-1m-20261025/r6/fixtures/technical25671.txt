# Aster Development Standards

Migrated from the A3S OS standards in the sibling `a3s` repository and
restated for this workspace. The rules below describe how Aster is
built and verified. Each section states the rule, the rationale, and
the enforcement mechanism.

This repository has three Cargo workspaces and one constitution.
The regime of a change is the regime of its path. Crate names that
still start with `a3s-` stay; they are API identifiers, not the
product name.

This is one of three governance surfaces, each with a distinct job:

- **This document** — the full rationale and enforcement mechanisms.
- [`.specify/memory/constitution.md`](../.specify/memory/constitution.md)
  — the enforceable distillation the spec-kit phases read. A
  NON-NEGOTIABLE mark may not be waived by any spec, plan, or task.
- [`Agents.md`](../Agents.md) — the quick reference for this
  workspace, including what must stay local and what must not be
  replaced by an upstream binary.

The spec-kit phase mapping lives in
[`docs/spec-driven-development.md`](spec-driven-development.md).

## Regimes

### Product regime

Paths: `apps/aster`, `apps/studio`, `crates/code`,
`crates/terminal`.

New behavior has a small hermetic test. Aster desktop tenants use
Tauri commands and stay in the root Cargo workspace. Members keep
`publish = false`.

### Control-plane regime

Paths: `apps/cloud`, `apps/api`, `apps/auth`, `apps/billing`,
`apps/config`.

A module keeps bounded contexts. A cloud migration bump includes
`CLOUD_MIGRATION_COUNT`. An HTTP surface uses `#[controller]` with
a guard and `auth.scopes`. A repository proof is a dual-adapter
proof against the in-memory adapter and live PostgreSQL.
`apps/api` and `apps/cloud` keep their own workspaces.

## 1. Repository layout

**Rule.** Three Cargo workspaces live in this repository. The root
workspace serves the product paths. `apps/api` and `apps/cloud` keep
their own workspaces and lockfiles, and they are not root members.

- `apps/aster` is the `aster` terminal binary. `crates/code/acp` is
  its `a3s-code-acp` companion. Build and distribute both together.
- `crates/code/core` is the embeddable Rust SDK and harness. Do not
  add Node, Python, or Go bindings, SDKs, or package publishing jobs.
- `apps/studio` is the shared desktop host. Build it with
  `just build-studio`. Its default `aster` tenant is Aster.
  Keep tenant identities and data isolated. See `specs/004-desktop-default-aster`.
- Office uses the root `packages/office` and `crates/office` sources. The
  retired app is removed after migration. Do not copy
  old user state or add another Cargo workspace or lockfile.
- `crates/` holds Rust libraries, including internalized upstream
  trees. `packages/` holds TypeScript and React libraries (`ui`,
  `office`, and the other workspace packages).
- All members have `publish = false`. Internal `a3s-*` dependencies,
  including optional ones, resolve to a path inside this repository.
  `tests/workspace_dependencies.py` guards that.

**Rationale.** A second workspace, lockfile, or published crate
becomes a second source of truth. The binary that ships must be the
tree people edit.

**Enforcement.** `Agents.md`, `tests/workspace_dependencies.py`, and
the root `Cargo.lock`. The user-authorized private desktop submodule at
`apps/studio` remains part of that workspace; its sources are committed only
to `git@github.com:kense-labs/studio.git`. Other new remotes or sibling
checkouts created for Aster work violate principle XIII. A second checkout of
this same repository is a git worktree.

**Structural migrations commit whole.** A rename or relocation that
moves a tree must land as one commit. A partially staged crate (the
`Cargo.toml` without its `src/`) is a non-building intermediate.
Stage the complete migration, verify `git diff --cached --name-only`
covers every piece, then commit.

## 2. Language, toolchain, configuration

**Rule.** Rust on toolchain `1.97.1`. Build from the repository root
with the pinned toolchain. Product configuration is ACL (`.acl`),
parsed and generated only with `a3s-acl`. Do not create, restore,
document, or parse another product configuration format.

**Rationale.** One configuration language with one parser keeps
resource limits and stable error codes. A second format drifts.

**Enforcement.** `Agents.md`. Host and workspace trust stay separated.
Sandbox enforcement and bounded reads stay in place.

**Extension pattern.** Per-transport settings live in nested ACL
blocks, not flat fields named after a transport. Adding a backend
extends a closed set plus its own parse arm. The selected provider's
transport block is required. Unknown or duplicate transport blocks
are refused.

## 3. Architecture by regime

**Rule.** Library code does not depend on a desktop shell. Cross-crate
data crosses the public Rust API of the owning crate. Preserve those
public APIs and the upstream package names unless a task explicitly
requires a rename.

On a product path, Aster desktop tenants stay in the root workspace.
On a control-plane path, each module is a bounded context with
`domain/`, `application/`, `infrastructure/`, `presentation/`, and
`published/`. Domain code does not import presentation or
infrastructure. `apps/api` and `apps/cloud` stay out of the root
member list.

**Rationale.** The receipt of an internalized library is its public
API. The control plane's receipt is the published fact, not a
private import. A second root member list for api or cloud would
merge three lockfiles.

**Enforcement.** Workspace membership, path dependencies, and review.
Shrink-only ratchets that already exist (the native-dropdown list,
dialog motion, the crate-drift baseline) may only shrink. Fix the
condition. Do not edit the allowlist to pass.

## 4. Error handling

**Rule.** Fail closed. Denied and missing share the not-found
contract where a caller must not learn which one occurred. An unset
required value refuses activation instead of defaulting. A
misconfigured optional surface degrades to disabled with an
error-level log. It does not take down the process that is still
able to serve.

**Refinements.**

- Idempotency is by fact identity. A replay is the same fact. Only a
  divergent owner or digest conflicts.
- Production paths do not call `unwrap()` or `expect()` unless a
  comment states why that construction cannot fail.

**Enforcement.** Review and the tests for the refusal. There is no
repository-wide unwrap census in this tree. A new production
`unwrap()` still needs the infallibility comment.

## 5. Naming

- Closed sets use an enum plus `parse()` / `as_str()`. The parse
  error names the set it refused.
- Crate and package identifiers that already start with `a3s-` stay,
  including `a3s-acl` and `a3s-code-acp`. Do not rename them in
  passing.
- The default user-visible product name is Aster (desktop tenant branding remains explicit). Do
  not describe this product as A3S OS or as a Grok release.
- Files are snake_case. Rust modules are snake_case. Types are
  CamelCase. ACL attributes are snake_case.
- Example domains use `.example`. Do not reintroduce retired brand
  strings as if they were the product name.

## 6. Persistence

- Prefer the typed query API of the crate that owns the store.
  Values are bound parameters. SQL text that is fixed is
  `&'static str`.
- A raw query is allowed only when the typed builder cannot express
  it. Document that reason at the call site. Keep values
  parameterized.
- Schema changes stay inside the crate or app that owns them.
- On a product path, the change stays with that owner. Ordinary
  desktop or CLI work does not require a live PostgreSQL campaign.
- On a control-plane path, cloud migrations stay a contiguous chain.
  Registering one bumps `CLOUD_MIGRATION_COUNT` and
  `LATEST_CLOUD_MIGRATION_VERSION`. A store with two adapters proves
  the same scenario on both.

## 7. Commands and controllers

On a product path, Aster desktop tenants expose behavior through
Tauri commands.

- A new command is registered on the host and allowed by a
  permission that the calling window's capability includes. Applet
  windows do not receive host permissions they do not need.
- Command inputs are typed. Unknown fields are rejected at the
  boundary that parses them.

On a control-plane path, an HTTP surface uses `#[controller]` with
a guard and `#[metadata("auth.scopes", ...)]`. Body DTOs reject
unknown fields. A new metadata key is a platform decision.

Tests for a command or a controller live in a sibling module. Do
not append thousands of inline test lines to a production file.

## 8. Testing

- On a product path, new behavior gets a small hermetic test.
  Prefer `cargo test` for the owning package, or the app's existing
  Vitest project, over a live external service.
- On a control-plane path, a repository or authority proof is a
  dual-adapter proof. PostgreSQL harnesses use
  `A3S_CLOUD_TEST_POSTGRES_URL` and `--test-threads=1`.
- Whole-file test modules start with `#![cfg(test)]`.
- After a run with many failures, re-run each distinct failure alone
  before treating it as a product defect. Parallel runs can fail
  because of shared fixtures or another session's files.
- A failed assertion on an error message is triaged before it is
  "fixed". The implementation that refuses with a precise reason is
  often right. The expected wording is what drifts.
- Every landing that changes behavior records
  `docs/evidence/<domain>/<date-slug>/OUTCOME.md` with the commands,
  the counts, and an Explicitly not claimed section. Evidence
  directories are not deleted to make a tree look tidy.

## 9. Security

- Compare bearer secrets in constant time.
- A foreign resource is indistinguishable from a missing one when
  the caller must not learn that it exists.
- No hardcoded credentials. Do not copy user session state into the
  repository.
- Fail closed on security surfaces. Degrade, with a signal, on
  convenience surfaces.
- Updates must not replace Aster with an A3S or Grok release.
- Preserve host and workspace trust boundaries and sandbox
  enforcement.

## 10. Git and delivery

- Stage files individually. Do not `git add -A` or sweep a directory
  another session is editing. Verify `git diff --cached
  --name-only` immediately before committing.
- The exception is a migration's own new tree: a relocation commits
  whole (§1).
- Commit subjects are imperative. Write the message with `-F` when
  the body contains backticks.
- Do not commit unless the user asked.
- A slice that changes behavior lands with its tests and, when the
  landing is recorded, its `OUTCOME.md`.

## 11. Documentation

- `OUTCOME.md` states the result, what landed, and what is explicitly
  not claimed. The last section is mandatory.
- Record abandoned alternatives when a decision would otherwise be
  re-derived.
- A dangling reference is a defect. When a document moves, the same
  change updates every pointer to it.
- `DESIGN.md` owns product chrome. This document owns engineering
  rules. Do not add a second design spec.

## 12. Governance

- A rule change lands here with the evidence that the rule was
  followed, then distills into the constitution. One amendment
  path, two views.
- A NON-NEGOTIABLE principle cannot be waived by a spec, a plan, a
  task, or a deadline. The only move is a constitution amendment
  with evidence.
- Independent judgment and adversarial review are verified in
  practice, not by a scanner.

## 13. Names are not guessed

**Rule.** A name, entity, or alias comes from an explicit source:
the model writes it in an entity list, the author writes it inside
quotes, or the string is already stored and a later query matches
that string exactly.

Do not infer a name from capitalization, a character class, a lead
character, a verb list, a stop list, a prefix or suffix ratio, or a
regular expression tuned to one example sentence. When a sentence
is missed, leave it missed.

Lexical tokens used only to rank text, secret redaction by a known
token prefix, and a short closed product word list that classifies
a sentence already stored are not name extraction. Those lists do
not grow to cover one missed sentence.

**Enforcement.** Constitution principle XIV. Review rejects a new
matcher of this kind.

## 14. Meaning is not matched

**Rule.** A decision about what the user means — a request to
remember, a preference, an intent, an importance judgment — is made
by the model or by a typed closed set the host declared. A regex, a
substring, a verb list, or a character class must not make that
decision.

Pattern matching may narrow fail-closed (secret redaction,
credential refusal), rank candidates for the model, or parse a
mechanical form. It may not classify intent. A missed phrasing uses
the model path. Matcher vocabularies do not grow to cover it.

**Enforcement.** Constitution principle XV.

## 15. Pickers are drawn

**Rule.** A product dropdown is drawn by the design system. Native
`<select>`, `<datalist>`, and `document.createElement('select')` do
not ship. Use `SearchSelect` from `@a3s-lab/ui`, `Combobox` when the
trigger must read as a text field, or the same anatomy drawn where
React is not available. The contract is `DESIGN.md` §6 "Picker
(dropdown)". The Radix `Select` list only shrinks.

**Enforcement.** Constitution principle XVI.
`apps/studio/src/renderer/__tests__/noNativeSelect.test.ts` fails on
a native dropdown in Aster's renderer and holds the Radix `Select`
list shrink-only. Component tests open the trigger and choose a
`role="option"` row.

## 16. Dialogs stay in place

**Rule.** A modal dialog, including a desktop side panel with
`role="dialog"`, appears and disappears where it rests. It fades
and scales in place. It does not slide in from outside the window,
and its motion does not animate `transform` or `filter`. An
anchored menu may rise at most 0.5rem. That rise composes with the
positioning transform and does not set `filter`. A phone-width
bottom sheet is the only edge travel. Durations and the rest of
the contract are `DESIGN.md` §6 "Dialogs".

The existing class names `.a3s-dialog-scrim`, `.a3s-dialog-surface`,
`.a3s-popup-rise`, `.a3s-row-enter`, and `.a3s-row-leave` stay.
They are implementation identifiers.

**Enforcement.** Constitution principle XVII.
`packages/ui/src/components/primitives/__tests__/dialog.test.tsx`
and `popup-motion.test.tsx` lock the in-place dialog and popup
motion.

# Aster Constitution

Distilled from the engineering practice of this repository. The full
rationale lives in
[`docs/development-standards.md`](../../docs/development-standards.md).
This document is the enforceable distillation the spec-kit phases
read. A principle marked **NON-NEGOTIABLE** may not be waived by any
spec, plan, or task.

One constitution covers this repository. A change follows the regime
of the path it edits. Crate identifiers that start with `a3s-` remain.

## Regimes

### Product regime

Paths: `apps/aster`, `apps/studio`, `crates/code`,
`crates/terminal`.

Obligations: a small hermetic test for new behavior; Tauri commands
for Aster desktop tenants; membership in the root Cargo workspace;
`publish = false`.

### Control-plane regime

Paths: `apps/cloud`, `apps/api`, `apps/auth`, `apps/billing`,
`apps/config`.

Obligations: bounded contexts (`domain/`, `application/`,
`infrastructure/`, `presentation/`, `published/`). Cloud schema
changes stay contiguous and bump `CLOUD_MIGRATION_COUNT` together
with `LATEST_CLOUD_MIGRATION_VERSION`. HTTP surfaces use
`#[controller]` with a guard and `auth.scopes`. A repository proof
is a dual-adapter proof: the same scenario runs on the in-memory
adapter and on live PostgreSQL. PostgreSQL harnesses use
`A3S_CLOUD_TEST_POSTGRES_URL` and `--test-threads=1`.

`apps/api` and `apps/cloud` keep their own Cargo workspaces. They
are not members of the root workspace.

### Shared-crate copies

Paths: `crates/acl`, `crates/boot`, `crates/orm`, `crates/event`,
`crates/lane`, `crates/flow`, `crates/sms`, and the same package
names under `apps/api/crates` and `apps/cloud/crates`.

A one-sided edit that grows the drift set fails
`tests/crate_drift_report.py`. Copies stay separate until a named
reconcile. A package is not moved across workspaces.

## Core Principles

### I. Fail Closed

Every refused condition names its reason. Denied and missing share
the not-found contract where the caller must not learn which one
occurred. An unset required value refuses activation instead of
defaulting. A misconfigured optional surface degrades to disabled
with an error-level log. It never takes down a process that can
still serve. **NON-NEGOTIABLE.**

### II. Evidence Retained

A landing that changes behavior records
`docs/evidence/<domain>/<date-slug>/OUTCOME.md` with the commands,
the counts, and an Explicitly not claimed section. Evidence
directories are not deleted, and a claim is not made without the
record. **NON-NEGOTIABLE.**

### III. Tests Follow the Path Regime

On a product path, new behavior has a small hermetic test in the
owning package. Ordinary desktop or CLI work does not require a
live PostgreSQL campaign.

On a control-plane path, a repository or authority proof follows
the control-plane regime: the same scenario runs on both adapters.
After a mass-failure run, re-run each distinct failure alone before
believing it. **NON-NEGOTIABLE.**

### IV. Closed Sets

Enums with `parse()` / `as_str()` pairs. Parse errors name the
refused set. Unknown values are refused at the boundary, never
coerced. **NON-NEGOTIABLE.**

### V. Workspaces and Published APIs

Library code does not depend on a desktop shell. On a product path,
Aster desktop tenants share the root Cargo workspace and lockfile
and do not grow another workspace. Cross-crate use goes through the
owning crate's public API. Preserve upstream package names and
public Rust APIs unless a task explicitly requires a rename.

On a control-plane path, `apps/api` and `apps/cloud` keep the
workspaces named in the control-plane regime. Domain code does not
import presentation or infrastructure. Cross-context data crosses
`published/` types.

### VI. Schema Changes Follow the Path

A schema change stays in the crate or app that owns the store.
Values are bound parameters. A raw query needs a documented reason
that the typed builder cannot express it.

On a product path the change stays in that owner. On a
control-plane path the migration identity follows the control-plane
regime. Do not add a second root Cargo lockfile.

### VII. Shrink-Only Ratchets

An existing allowlist (native dropdowns, facade debt, or any other
ratchet in this tree) may only shrink. Fix the underlying
condition. Never edit the allowlist to pass. **NON-NEGOTIABLE.**

### VIII. Replaceable Transports

A library that offers more than one transport keeps the choice out
of consumers. Transport fields do not leak into a shared envelope.
Product configuration of a transport is an ACL block.

### IX. One Configuration Language

ACL (`.acl`), parsed only by `a3s-acl`, is the only product
configuration language. Never create, restore, document, or parse
another product configuration format. **NON-NEGOTIABLE.**

Feature-consumed definition files are data, not configuration, on
the same terms as `SKILL.md`: closed-set fields, content shared
like source, and authority that the loading feature only narrows.
A definition must not name a provider, alter permission policy, or
join layered configuration discovery. Any new surface that answers
"how does the product behave" is configuration and goes in ACL.

### X. Commands, Controllers, and Test Files

On a product path, a Tauri command is registered and allowed by a
permission on the calling window's capability. Applet windows do
not receive host permissions they do not need.

On a control-plane path, an HTTP surface follows the control-plane
regime for `#[controller]`, the guard, and `auth.scopes`.

Tests live in sibling files behind `#[cfg(test)]`. Do not append
thousands of inline test lines to a production file.

### XI. Independent Judgment

Disagree when the evidence supports disagreement, and say so with
the reasoning. Do not implement a request that the evidence
contradicts without first stating the contradiction and the
corrected approach. Changing position requires new evidence, not
pressure. **NON-NEGOTIABLE.**

### XII. First-Principles Understanding and Adversarial Review

Before implementing, understand why the user needs the change.
A fix that leaves the cause in place is not done. After
implementing, try to break the change and look for what the tests
miss. A disproven finding stays recorded. A confirmed finding that
is not fixed names the exact follow-up. **NON-NEGOTIABLE.**

### XIII. One Repository

New Aster code lands in this repository. Do not create a Git
repository, a GitHub project, or a sibling checkout beside `aster`
for a library, product, or tool. Rust libraries go under `crates/`,
applications under `apps/`, and TypeScript or React libraries under
`packages/`. A second checkout of this repository is a git worktree.
The user-authorized desktop source boundary is the private submodule at
`apps/studio` (`git@github.com:kense-labs/studio.git`, `main`). It remains in
the root Rust workspace and uses the root lockfile; the parent tracks only
its gitlink, never desktop source files.
**NON-NEGOTIABLE.**

### XIV. Names Are Not Guessed

A name, entity, or alias comes from a model-supplied entity list,
a quoted span the author wrote, or an exact string already stored.
Do not infer names from capitalization, character classes, verb or
stop lists, or a regular expression tuned to an example sentence.
A missed example is not a reason to grow a matcher. Ranking tokens,
secret redaction by a known prefix, and a closed product word list
are not name extraction. Those lists do not grow to cover one
missed sentence. **NON-NEGOTIABLE.**

### XV. Meaning Is Not Matched

A decision about what the user means is made by the model or by a
typed closed set the host declared. A regex, substring, verb list,
or character class must not make that decision. Pattern matching
may only narrow fail-closed, rank candidates, or parse a mechanical
form. A missed phrasing uses the model path. **NON-NEGOTIABLE.**

### XVI. Pickers Are Drawn

No product surface ships an operating-system dropdown: no native
`<select>`, `<datalist>`, or a script-built `select` element. A
choice list is the picker in `DESIGN.md` §6. The Radix `Select`
list is shrink-only. A test fixture that exists to exercise a
native control is not a product surface.

### XVII. Dialogs Stay in Place

A modal dialog, including a desktop side panel with `role="dialog"`,
fades and scales in place. It does not slide in from outside the
window, and its motion does not animate `transform` or `filter`.
An anchored menu may rise at most 0.5rem. A phone-width bottom
sheet is the only edge travel. The contract is `DESIGN.md` §6
"Dialogs" and development-standards §16.

## Constraints

- Rust toolchain `1.97.1`. The root workspace, `apps/api`, and
  `apps/cloud` each keep their own lockfile. `publish = false`.
- Internal `a3s-*` crates resolve to a path in this repository.
- Do not restore an upstream binary update that replaces Aster with
  an A3S or Grok release.
- Production paths carry no `unwrap()` or `expect()` without a
  construction-level infallibility argument in a comment.
- Bearer comparisons use constant-time equality.
- Never commit another session's in-flight edits. Stage files
  individually and verify `git diff --cached --name-only` first.
  Do not commit unless the user asked.

## Development Workflow

A behavior change lands with its hermetic test and, when recorded,
`docs/evidence/<domain>/<date-slug>/OUTCOME.md`. A structural
migration lands as one commit. Bounded epics may use the spec-kit
phases under `specs/<NNN-slug>/`. The implementation evidence still
lands in `docs/evidence/`. Planning and acceptance are not two
copies of the same record.

## Governance

The constitution is amended through the same evidence discipline.
The behavior change lands first. The principle text follows.

# Spec-Driven Development (spec-kit integration)

This repository applies [github/spec-kit](https://github.com/github/spec-kit)
in adapted form. The house templates, constitution, and commands live
in this tree. They do not call spec-kit's installer.

Reference revision at adoption in the sibling A3S OS repository:
`e1fa857a`. This copy is the Aster adaptation of that integration.

## What was adopted

- The **phase structure**: constitution → specify → clarify → plan →
  tasks → analyze → implement. Grok Build runs the procedures from
  `.grok/skills/speckit-*/SKILL.md`, which read
  `.claude/commands/speckit.*.md`. Codex runs them from
  `.agents/skills/speckit-*/SKILL.md`. Cursor runs them from
  `.cursor/skills/speckit-*/SKILL.md`.
- The **planning surface**: `specs/<NNN-slug>/` holding `spec.md`,
  `plan.md`, `research.md`, `data-model.md`, `contracts/`, and
  `tasks.md` for a bounded epic.
- The **constitution**: `.specify/memory/constitution.md`.

## What was adapted

- **Templates carry this repository's discipline.** The plan
  template's Constitution Check uses the regime of the epic's paths.
  A product-path epic uses hermetic tests. A control-plane epic
  under `apps/cloud` or `apps/api` uses the control-plane regime,
  including dual-adapter proofs.
- **No script dependency.** The commands read
  `.specify/templates/`, `.specify/memory/constitution.md`, and
  `Agents.md` directly.
- **Acceptance stays in `docs/evidence/`.** The spec directory is
  planning. It is not a second acceptance record.

## Grok surface

Slash names use hyphens:

| Phase | Grok command |
| --- | --- |
| constitution | `/speckit-constitution` |
| specify | `/speckit-specify` |
| clarify | `/speckit-clarify` |
| plan | `/speckit-plan` |
| tasks | `/speckit-tasks` |
| analyze | `/speckit-analyze` |
| implement | `/speckit-implement` |

When a procedure names `/speckit.<phase>`, use the hyphen form.
Do not run `specify init` or an upstream installer in this tree.

## Codex surface

| Phase | Codex invocation |
| --- | --- |
| constitution | `$speckit-constitution` |
| specify | `$speckit-specify` |
| clarify | `$speckit-clarify` |
| plan | `$speckit-plan` |
| tasks | `$speckit-tasks` |
| analyze | `$speckit-analyze` |
| implement | `$speckit-implement` |

Resolve paths from the Git repository root. Read the owning tree's
notes, then `Agents.md`, before editing. Enforce the constitution.
Where a shared procedure is less strict, follow `Agents.md`. Keep
analyze read-only. Do not commit unless the user asked. Stage only
this task's files and inspect the staged list before committing.

## Cursor surface

Cursor loads a skill when the user names it. The phase names match
the Grok hyphen form (`/speckit-specify` and the rest). Apply the
same path, constitution, and staging rules as the Codex surface.

## When to use it

- **Bounded epics** that span more than one session: run the full
  phase set. `specs/` is the epic's memory.
- **Single-slice fixes**: tests plus, when the change is recorded,
  `OUTCOME.md`. Do not scaffold a spec directory for a one-commit fix.
- **Design-decision items**: change the behavior with evidence first,
  then amend the constitution.

## Phase-to-house-process mapping

| speckit phase | House process | Artifact |
| --- | --- | --- |
| constitution | constitution + development standards | principles with NON-NEGOTIABLE marks |
| specify | acceptance design | `specs/<NNN>/spec.md` |
| clarify | decisions, including abandoned alternatives | marker-free spec |
| plan | Constitution Check | `specs/<NNN>/plan.md` |
| tasks | task breakdown with test obligations | `specs/<NNN>/tasks.md` |
| analyze | read-only consistency check | findings table |
| implement | code + hermetic tests + evidence | `docs/evidence/...` |

## Non-negotiables the phases cannot waive

Fail closed. Evidence retained. The test obligation is the regime
of the epic's paths. Closed sets. Shrink-only ratchets. One ACL
language. One repository.
Names are not guessed. Meaning is not matched. A phase that needs to
violate one stops and escalates to a constitution amendment with
evidence.

# Aster

**Rust 编写的智能体执行内核与终端编程工具。**

Aster 连接你配置的模型，在项目中读取文件、修改代码并调用工具。
权限策略控制执行，事实日志记录过程，验证证据约束任务何时可以完成。
你可以直接使用 Aster CLI，也可以把内核嵌入自己的 Rust 应用。

[下载官网](https://aster-ai-lab.github.io/aster/) · [开始使用](#开始使用) · [运行机制](#运行机制) · [当前限制](#当前限制) · [参与开发](#参与开发)

## 从一个任务开始

在项目目录启动 Aster，输入你的目标，例如：

```text
修复配置解析的边界错误，只修改相关文件。
先说明计划，再完成修改并运行相关测试。
最后列出改动、验证结果和仍未解决的问题。
```

完成编程任务，需要把模型的建议接入实际执行，并保留可检查的结果：

| 任务中的问题 | Aster 的处理方式 |
| --- | --- |
| 哪些操作可以执行？ | 工具调用先经过权限判定，需要确认时等待用户回答。 |
| 执行过什么、结果如何？ | 模型、工具和控制事件写入同一份事实日志。 |
| 修改是否满足完成条件？ | 内核检查对应本次修改的验证报告，或宿主显式豁免，再判定能否完成。 |

## 开始使用

### 1. 下载 CLI

从 [最新发布页](https://github.com/aster-ai-lab/aster/releases/latest)下载对应系统的归档，或使用安装脚本（自动发现最新版本并校验 SHA-256）：

```bash
curl -fsSL https://raw.githubusercontent.com/aster-ai-lab/aster/main/scripts/install.sh | bash -s -- --prefix "$HOME/.local/bin"
```

Windows 使用 [install.ps1](https://github.com/aster-ai-lab/aster/blob/main/scripts/install.ps1)。

解压后，将 `aster` 和 `a3s-code-acp` 放在同一目录；Windows 对应两个 `.exe` 文件。
CLI 默认启动同目录的 ACP 伴随进程。需要指定其他位置时，设置 `A3S_ACP_AGENT_BIN`。

Linux 归档分两个 glibc 世代：`linux` 需要 glibc 2.32 及以上；`kylin` 是同样的一对
x86_64 二进制，针对 glibc 2.31 构建，适用于银河麒麟 V10 SP1、Ubuntu 20.04、
Debian 11 等较旧系统。安装脚本按本机 glibc 自动选择，`aster update` 使用同一规则。

已安装的 CLI 从 v0.1.2 起支持自我更新：`aster update` 会从本仓库的
channel manifest（`latest.json`）发现最新版本，校验归档摘要后原子安装
`aster` 与 `a3s-code-acp` 成对二进制；`aster update --check` 只报告不改动，
`aster update --version X.Y.Z` 安装指定版本。v0.1.1 的旧安装不含该通道，
请先用上面的安装脚本重装一次。

该版本为未签名构建。

### 2. 配置模型

创建或编辑 `~/.a3s/config.acl`。以下示例使用 OpenAI 兼容接口，
请把接口地址和 `your-model` 替换为服务实际提供的值：

```acl
default_model = "openai/your-model"

providers "openai" {
  base_url = "https://your-api.example/v1"
  api_key = env("OPENAI_API_KEY")
  models "your-model" {}
}
```

密钥通过环境变量提供。更多配置见 [ACL 示例](crates/code/agent.example.acl)；
`A3S_CONFIG` 可以指定其他配置文件，终端内的 `/config` 用于管理模型配置。

### 3. 启动项目

在解压目录执行，并将项目路径替换为实际路径。

macOS / Linux：

```sh
export OPENAI_API_KEY="你的 API 密钥"
./aster --cwd /path/to/project
```

Windows PowerShell：

```powershell
$env:OPENAI_API_KEY = "你的 API 密钥"
$env:A3S_CONFIG = Join-Path $HOME '.a3s/config.acl'
.\aster.exe --cwd C:\path\to\project
```

需要在任意目录使用 `aster` 时，将两个程序所在目录加入 `PATH`。

### 更新与卸载

更新时下载新的发布归档，并一起替换同目录的两个程序。
卸载时删除这两个程序即可；`~/.a3s` 中的本地配置与数据可保留。

## 运行机制

Harness 负责把模型调用接入一个受控的任务过程。
Aster 的 **Meta Harness** 允许 Rust 宿主组合系统指令、工具、预算、上下文压缩和调度组件，
同时由内核维持权限与完成条件。

```text
用户任务 → 模型提案 → 权限判定 → 工具执行 → 结果记入事实日志
                          │                         │
                          └─ 等待确认或拒绝          └─ 更新上下文，继续执行

发生修改 → 收集与本次修改对应的验证证据 → 完成判定
```

组件根据事实日志计算状态和下一步可执行操作。需要确认或补充信息时，
运行等待对应回答；计时器不能代替用户授权。
事实重放用于恢复控制状态，外部副作用的崩溃恢复仍需单独验证。

进一步阅读：

- [Meta Harness](crates/code/manual/META_HARNESS.md)：组件组合与 Rust 嵌入接口。
- [持续工程与目标](crates/code/manual/DURABLE_ENGINEERING.md)：长期目标、预算和等待条件。
- [持久记忆](crates/code/manual/DURABLE_MEMORY.md)：记忆隔离、修订与激活边界。

## 当前限制

- 需要自行配置可用的模型服务及相应凭据。
- macOS 原生 Shell 工具目前仍会因 `native_process_lifetime_unqualified` 被拒绝；依赖 Shell 的完整编程流程尚未通过平台资格验证。详见[验证记录](docs/validation.md)。
- 指定项目目录不等于隔离所有本机进程。实际执行边界由宿主策略和沙箱共同决定。
- 本页的运行机制说明对应当前源码；已发布版本的能力以对应发布说明为准。

## 参与开发

源码构建需要固定 Rust 工具链及仓库内私有组件的读取权限。
准备方式、构建约定和检查要求见 [仓库约定](AGENTS.md)与[开发规范](docs/development-standards.md)。

报告缺陷请提交到 [Issues](https://github.com/aster-ai-lab/aster/issues)，
附操作系统、复现步骤、预期结果及去除凭据后的日志。

# Harness migration

## Native Power integration, 2026-10-22

The existing `crates/power` submodule is integrated into the root Cargo
workspace for the native DeepSeek optimization work in
`specs/009-power-native-deepseek-h200`. Its source ownership remains in that
submodule; the parent tracks the gitlink. Power uses local ACL and Runtime,
and the model-owned `a3s-deepseek` crate depends on local Power without
enabling an external inference backend by default. The nested Power lockfile
is reconciled into the root lockfile rather than retained as a second lock.

The pinned ONNX Runtime 2.0.0-rc.10 remains aligned with BGE/OCR. Its SmallVec
2 alpha.10 pin conflicts with the optional Mistral backend's serde-saphyr
0.0.16 and saphyr-parser-bw 0.0.605 dependencies on SmallVec 2 alpha.12.
Both published sources are retained locally with their licenses and packaged
tests; private container annotations use the stable SmallVec 1.x API
(minimum 1.15.2). Parser logic, inline capacities and public APIs are preserved.
The resolver selects compatible annotate-snippets 0.12.5 without changing
the terminal's unicode-width pin. This is dependency reconciliation,
not a new product configuration format. Provenance is in
`source-manifest.json` and the native H200 evidence directory.

Existing uncommitted Cargo/BGE/Power changes were snapshotted before this
integration and remain separate from the native work. Build and test evidence
is recorded as it completes; workspace membership alone does not establish
DeepSeek model support or GPU performance.

The model owner also contains effective-weight RMSNorm and an explicit-cache
rotary tensor transform following the pinned DeepInfer contract. The rotary
source's Apache/vLLM notices are retained in
`crates/deepseek/licenses/Rotary-Apache-NOTICE.txt`. No upstream Python runtime
is imported. The resumed implementation adds an FP32 cache-frequency factory;
complete model/runtime integration and CUDA numerical qualification remain
unfinished obligations.

The resumed 2026-10-23 implementation retains the interrupted 281-test
decoder/state checkpoint and adds exact official base-text weight bindings.
All 40 layers' 93,415 declared tensor descriptors match independently audited
official headers. Small effective BF16/F32 parameters use bounded Power-owned
reads; FP8/MXFP4/Engram matrices retain explicit raw/scale layouts and row
loading. The fixture is metadata only, not product configuration. Complete
model composition, CUDA qualification and native deployment remain unfinished;
the native H200 evidence records 287 passing CPU tests and existing workspace
gate failures separately.

The next T007 slice adds raw matrix upload in independently bounded,
scale-block-aligned reads, actual official layer composition, sequential
cross-layer top-k/candidate sharing and `forward_pending` execution through
the complete backbone transaction. Model values remain on the selected
device; bounded integer selection metadata is explicit host control. A
failed layer poisons both the step plan and the uncommitted transaction.
The 302-test CPU acceptance closes the task's operator/layer/state scope;
SM90 kernels and GPU qualification remain T008, and the complete model
loop, capacity placement and H200 model validation remain T009.

T008 now adds original model-owned CUDA implementations for group-32 FP8
MMA and a separately selected raw-quantized FP32 scalar control. The latter
retains extreme checkpoint exponents without a BF16 intermediate. MXFP4
nibbles convert losslessly to E4M3 only in registers. No SM100 kernel source
was transplanted. The fragment coordinates follow CUDA 12.6 PTX ISA 8.5,
section 9.7.15.4.10. Candle 0.10.2 and its existing cudarc/NVRTC dependency
provide the stream/storage bridge; Power's F32 API and dependencies stay
unchanged. Receipts identify the selected profile, source/PTX, compile flags
and actual driver allocation attributes. Unsupported architecture, scale
envelope or workspace refuses rather than selecting another profile.
The 305 CPU tests, CUDA feature check, and SM90 assembly checks do not close
T008's actual H200 numerical and adapter qualification. No native service
or performance result is claimed from those checks.

The sparse-index tensor control and packed group-32 FP4 encoder/decoder also
remain model-owned Rust code. Scale rounding and E2M1 RNE/packing follow the
fixed TileKernels contract; candidate selection follows DeepInfer. The index
packed-scale boundary refuses zero/padding and nonfinite bytes, and does not
change the general checkpoint E8M0 decoder. DeepSelect/DeepGEMM sources were
audited without importing their kernels; GPU and complete-model proof remain
unfinished. Exact references and format distinctions are retained in the
native H200 evidence directory.

The 2026-10-18 import copies the required Rust source snapshots from
`../a3s` into a standalone Aster workspace. The OS/backend checkout remains separate; the later Desktop cleanup is
recorded below. Package-level provenance is recorded in
[`source-manifest.json`](source-manifest.json). Local snapshots include
working-tree changes; repository revisions do not imply release certification.

## Product and dependency boundaries

`aster` directly runs the existing pager composition root. It starts the
sibling `a3s-code-acp` process, which owns the Code Core harness. There is
no umbrella CLI or second agent loop. The old A3S umbrella CLI, cloud,
gateway, other desktop apps, web sites, distribution installers, and Code's
Node/Python/Go SDKs are outside this product.

The imported support crates cover the harness fact log, ACL parser,
native sandbox, memory, lexical retrieval, search/browser contracts,
extension reconciliation, OKF, optional workflows, and typed decisions.
Terminal support remains in its upstream directory structure to retain
resource paths, test fixtures, protocol definitions, and third-party notices.
The PTY controller and harness remain available for terminal regression tests.

All imported Rust packages and Work are members of one Cargo workspace with resolver 3,
shared dependency declarations, one checked-in `Cargo.lock`, one build
directory, and Rust 1.97.1. This follows the
[Cargo workspace model](https://doc.rust-lang.org/cargo/reference/workspaces.html).
The two default members build the terminal and ACP companion together.
Retained package names and Rust module paths keep the embeddable SDK stable.

## Compatibility decisions

- **Flow:** Code 9.1.4 uses Flow 1.1 contracts removed in the sibling's
  Flow 2.0 tree. The exact Code-pinned Flow commit
  `2948ad51a1395177764766c3ddf7e44338f9e374` is copied from the existing
  Cargo source cache. It is a local workspace dependency. Flow's optional
  Boot, Event, and ORM integrations now resolve to in-tree sources too.
- **Small support libraries:** Common 0.1.1, Lane 0.5.1, and Updater 0.2.0
  have no source project in the sibling tree. Their exact cached crate
  sources are included locally, with original licenses and provenance.
  Updater is retained for the standalone Search package; Aster's own
  automatic and explicit binary-update entry points are disabled.
- **ACL:** all imported consumers use the sibling's ACL 0.3.0 locally.
  Host-authoritative configuration remains protected from repository
  overrides. Workspace MCP trust and sandbox checks remain in place.
- **SQLite:** ACP and Memory move from rusqlite 0.32 to 0.37, matching
  the terminal crates, because Cargo permits only one `sqlite3` native
  linkage. Both memory adapters use sqlite-vec 0.1.7-alpha.10. Existing
  database schemas and migrations remain intact.
- **Runtime:** Tokio Util requires at least 0.7.19 for cancellation-token
  identity comparisons already used by Core.
- **Vector test utilities:** Vec's old exact tempfile 3.14 dev pin is
  widened to 3.27 to share the workspace's temporary-file library.
- **Configuration and state:** existing `.a3s` / `.a3s-code` paths and
  `A3S_*` environment variables remain compatible. The migration copies
  no personal credentials, session stores, browser profiles, or build outputs.
- **macOS native execution:** the source Core deliberately refuses native
  shell execution with `native_process_lifetime_unqualified` until descendant
  lifetime and settlement are qualified. This guard remains intact. The two
  shell-dependent PTY success tests are skipped only on macOS; native refusal
  tests cover the guard. Launching, model chat, and file tools remain available.
- **SDK-independent fixtures:** evaluation/research wire fixtures move
  from `sdk/` into `crates/code/fixtures/protocol`; Rust protocol tests
  point at the new paths. No foreign-language bindings are retained.
- **Release tests:** Search's standalone upstream release-workflow test is
  retired with that release pipeline. Root workspace CI and Aster's
  migration tests replace the obsolete publication-layout assumptions.
- **Memory tests:** the legacy ACP `v912_remember_before_stream_close`
  oracle expects a raw-input fallback and JSON files even when the extraction
  model returns no memories. Current Core explicitly forbids that fallback
  and uses Vec snapshots. The historical test remains ignored with its reason;
  Core's current memory-retention tests verify the supported contract.
- **Hardware and linking:** retain Apple Silicon's 16 KiB jemalloc page
  calibration, Linux ARM64 page settings, static MSVC CRT settings, and
  musl linker hardening. Python-extension dynamic lookup flags are removed.

# Aster Development Standards

Migrated from the A3S OS standards in the sibling `a3s` repository and
restated for this workspace. The rules below describe how Aster is
built and verified. Each section states the rule, the rationale, and
the enforcement mechanism.

This repository has three Cargo workspaces and one constitution.
The regime of a change is the regime of its path. Crate names that
still start with `a3s-` stay; they are API identifiers, not the
product name.

This is one of three governance surfaces, each with a distinct job:

- **This document** — the full rationale and enforcement mechanisms.
- [`.specify/memory/constitution.md`](../.specify/memory/constitution.md)
  — the enforceable distillation the spec-kit phases read. A
  NON-NEGOTIABLE mark may not be waived by any spec, plan, or task.
- [`Agents.md`](../Agents.md) — the quick reference for this
  workspace, including what must stay local and what must not be
  replaced by an upstream binary.

The spec-kit phase mapping lives in
[`docs/spec-driven-development.md`](spec-driven-development.md).

## Regimes

### Product regime

Paths: `apps/aster`, `apps/studio`, `crates/code`,
`crates/terminal`.

New behavior has a small hermetic test. Aster desktop tenants use
Tauri commands and stay in the root Cargo workspace. Members keep
`publish = false`.

### Control-plane regime

Paths: `apps/cloud`, `apps/api`, `apps/auth`, `apps/billing`,
`apps/config`.

A module keeps bounded contexts. A cloud migration bump includes
`CLOUD_MIGRATION_COUNT`. An HTTP surface uses `#[controller]` with
a guard and `auth.scopes`. A repository proof is a dual-adapter
proof against the in-memory adapter and live PostgreSQL.
`apps/api` and `apps/cloud` keep their own workspaces.

## 1. Repository layout

**Rule.** Three Cargo workspaces live in this repository. The root
workspace serves the product paths. `apps/api` and `apps/cloud` keep
their own workspaces and lockfiles, and they are not root members.

- `apps/aster` is the `aster` terminal binary. `crates/code/acp` is
  its `a3s-code-acp` companion. Build and distribute both together.
- `crates/code/core` is the embeddable Rust SDK and harness. Do not
  add Node, Python, or Go bindings, SDKs, or package publishing jobs.
- `apps/studio` is the shared desktop host. Build it with
  `just build-studio`. Its default `aster` tenant is Aster.
  Keep tenant identities and data isolated. See `specs/004-desktop-default-aster`.
- Office uses the root `packages/office` and `crates/office` sources. The
  retired app is removed after migration. Do not copy
  old user state or add another Cargo workspace or lockfile.
- `crates/` holds Rust libraries, including internalized upstream
  trees. `packages/` holds TypeScript and React libraries (`ui`,
  `office`, and the other workspace packages).
- All members have `publish = false`. Internal `a3s-*` dependencies,
  including optional ones, resolve to a path inside this repository.
  `tests/workspace_dependencies.py` guards that.

**Rationale.** A second workspace, lockfile, or published crate
becomes a second source of truth. The binary that ships must be the
tree people edit.

**Enforcement.** `Agents.md`, `tests/workspace_dependencies.py`, and
the root `Cargo.lock`. The user-authorized private desktop submodule at
`apps/studio` remains part of that workspace; its sources are committed only
to `git@github.com:kense-labs/studio.git`. Other new remotes or sibling
checkouts created for Aster work violate principle XIII. A second checkout of
this same repository is a git worktree.

**Structural migrations commit whole.** A rename or relocation that
moves a tree must land as one commit. A partially staged crate (the
`Cargo.toml` without its `src/`) is a non-building intermediate.
Stage the complete migration, verify `git diff --cached --name-only`
covers every piece, then commit.

## 2. Language, toolchain, configuration

**Rule.** Rust on toolchain `1.97.1`. Build from the repository root
with the pinned toolchain. Product configuration is ACL (`.acl`),
parsed and generated only with `a3s-acl`. Do not create, restore,
document, or parse another product configuration format.

**Rationale.** One configuration language with one parser keeps
resource limits and stable error codes. A second format drifts.

**Enforcement.** `Agents.md`. Host and workspace trust stay separated.
Sandbox enforcement and bounded reads stay in place.

**Extension pattern.** Per-transport settings live in nested ACL
blocks, not flat fields named after a transport. Adding a backend
extends a closed set plus its own parse arm. The selected provider's
transport block is required. Unknown or duplicate transport blocks
are refused.

## 3. Architecture by regime

**Rule.** Library code does not depend on a desktop shell. Cross-crate
data crosses the public Rust API of the owning crate. Preserve those
public APIs and the upstream package names unless a task explicitly
requires a rename.

On a product path, Aster desktop tenants stay in the root workspace.
On a control-plane path, each module is a bounded context with
`domain/`, `application/`, `infrastructure/`, `presentation/`, and
`published/`. Domain code does not import presentation or
infrastructure. `apps/api` and `apps/cloud` stay out of the root
member list.

**Rationale.** The receipt of an internalized library is its public
API. The control plane's receipt is the published fact, not a
private import. A second root member list for api or cloud would
merge three lockfiles.

**Enforcement.** Workspace membership, path dependencies, and review.
Shrink-only ratchets that already exist (the native-dropdown list,
dialog motion, the crate-drift baseline) may only shrink. Fix the
condition. Do not edit the allowlist to pass.

## 4. Error handling

**Rule.** Fail closed. Denied and missing share the not-found
contract where a caller must not learn which one occurred. An unset
required value refuses activation instead of defaulting. A
misconfigured optional surface degrades to disabled with an
error-level log. It does not take down the process that is still
able to serve.

**Refinements.**

- Idempotency is by fact identity. A replay is the same fact. Only a
  divergent owner or digest conflicts.
- Production paths do not call `unwrap()` or `expect()` unless a
  comment states why that construction cannot fail.

**Enforcement.** Review and the tests for the refusal. There is no
repository-wide unwrap census in this tree. A new production
`unwrap()` still needs the infallibility comment.

## 5. Naming

- Closed sets use an enum plus `parse()` / `as_str()`. The parse
  error names the set it refused.
- Crate and package identifiers that already start with `a3s-` stay,
  including `a3s-acl` and `a3s-code-acp`. Do not rename them in
  passing.
- The default user-visible product name is Aster (desktop tenant branding remains explicit). Do
  not describe this product as A3S OS or as a Grok release.
- Files are snake_case. Rust modules are snake_case. Types are
  CamelCase. ACL attributes are snake_case.
- Example domains use `.example`. Do not reintroduce retired brand
  strings as if they were the product name.

## 6. Persistence

- Prefer the typed query API of the crate that owns the store.
  Values are bound parameters. SQL text that is fixed is
  `&'static str`.
- A raw query is allowed only when the typed builder cannot express
  it. Document that reason at the call site. Keep values
  parameterized.
- Schema changes stay inside the crate or app that owns them.
- On a product path, the change stays with that owner. Ordinary
  desktop or CLI work does not require a live PostgreSQL campaign.
- On a control-plane path, cloud migrations stay a contiguous chain.
  Registering one bumps `CLOUD_MIGRATION_COUNT` and
  `LATEST_CLOUD_MIGRATION_VERSION`. A store with two adapters proves
  the same scenario on both.

## 7. Commands and controllers

On a product path, Aster desktop tenants expose behavior through
Tauri commands.

- A new command is registered on the host and allowed by a
  permission that the calling window's capability includes. Applet
  windows do not receive host permissions they do not need.
- Command inputs are typed. Unknown fields are rejected at the
  boundary that parses them.

On a control-plane path, an HTTP surface uses `#[controller]` with
a guard and `#[metadata("auth.scopes", ...)]`. Body DTOs reject
unknown fields. A new metadata key is a platform decision.

Tests for a command or a controller live in a sibling module. Do
not append thousands of inline test lines to a production file.

## 8. Testing

- On a product path, new behavior gets a small hermetic test.
  Prefer `cargo test` for the owning package, or the app's existing
  Vitest project, over a live external service.
- On a control-plane path, a repository or authority proof is a
  dual-adapter proof. PostgreSQL harnesses use
  `A3S_CLOUD_TEST_POSTGRES_URL` and `--test-threads=1`.
- Whole-file test modules start with `#![cfg(test)]`.
- After a run with many failures, re-run each distinct failure alone
  before treating it as a product defect. Parallel runs can fail
  because of shared fixtures or another session's files.
- A failed assertion on an error message is triaged before it is
  "fixed". The implementation that refuses with a precise reason is
  often right. The expected wording is what drifts.
- Every landing that changes behavior records
  `docs/evidence/<domain>/<date-slug>/OUTCOME.md` with the commands,
  the counts, and an Explicitly not claimed section. Evidence
  directories are not deleted to make a tree look tidy.

## 9. Security

- Compare bearer secrets in constant time.
- A foreign resource is indistinguishable from a missing one when
  the caller must not learn that it exists.
- No hardcoded credentials. Do not copy user session state into the
  repository.
- Fail closed on security surfaces. Degrade, with a signal, on
  convenience surfaces.
- Updates must not replace Aster with an A3S or Grok release.
- Preserve host and workspace trust boundaries and sandbox
  enforcement.

## 10. Git and delivery

- Stage files individually. Do not `git add -A` or sweep a directory
  another session is editing. Verify `git diff --cached
  --name-only` immediately before committing.
- The exception is a migration's own new tree: a relocation commits
  whole (§1).
- Commit subjects are imperative. Write the message with `-F` when
  the body contains backticks.
- Do not commit unless the user asked.
- A slice that changes behavior lands with its tests and, when the
  landing is recorded, its `OUTCOME.md`.

## 11. Documentation

- `OUTCOME.md` states the result, what landed, and what is explicitly
  not claimed. The last section is mandatory.
- Record abandoned alternatives when a decision would otherwise be
  re-derived.
- A dangling reference is a defect. When a document moves, the same
  change updates every pointer to it.
- `DESIGN.md` owns product chrome. This document owns engineering
  rules. Do not add a second design spec.

## 12. Governance

- A rule change lands here with the evidence that the rule was
  followed, then distills into the constitution. One amendment
  path, two views.
- A NON-NEGOTIABLE principle cannot be waived by a spec, a plan, a
  task, or a deadline. The only move is a constitution amendment
  with evidence.
- Independent judgment and adversarial review are verified in
  practice, not by a scanner.

## 13. Names are not guessed

**Rule.** A name, entity, or alias comes from an explicit source:
the model writes it in an entity list, the author writes it inside
quotes, or the string is already stored and a later query matches
that string exactly.

Do not infer a name from capitalization, a character class, a lead
character, a verb list, a stop list, a prefix or suffix ratio, or a
regular expression tuned to one example sentence. When a sentence
is missed, leave it missed.

Lexical tokens used only to rank text, secret redaction by a known
token prefix, and a short closed product word list that classifies
a sentence already stored are not name extraction. Those lists do
not grow to cover one missed sentence.

**Enforcement.** Constitution principle XIV. Review rejects a new
matcher of this kind.

## 14. Meaning is not matched

**Rule.** A decision about what the user means — a request to
remember, a preference, an intent, an importance judgment — is made
by the model or by a typed closed set the host declared. A regex, a
substring, a verb list, or a character class must not make that
decision.

Pattern matching may narrow fail-closed (secret redaction,
credential refusal), rank candidates for the model, or parse a
mechanical form. It may not classify intent. A missed phrasing uses
the model path. Matcher vocabularies do not grow to cover it.

**Enforcement.** Constitution principle XV.

## 15. Pickers are drawn

**Rule.** A product dropdown is drawn by the design system. Native
`<select>`, `<datalist>`, and `document.createElement('select')` do
not ship. Use `SearchSelect` from `@a3s-lab/ui`, `Combobox` when the
trigger must read as a text field, or the same anatomy drawn where
React is not available. The contract is `DESIGN.md` §6 "Picker
(dropdown)". The Radix `Select` list only shrinks.

**Enforcement.** Constitution principle XVI.
`apps/studio/src/renderer/__tests__/noNativeSelect.test.ts` fails on
a native dropdown in Aster's renderer and holds the Radix `Select`
list shrink-only. Component tests open the trigger and choose a
`role="option"` row.

## 16. Dialogs stay in place

**Rule.** A modal dialog, including a desktop side panel with
`role="dialog"`, appears and disappears where it rests. It fades
and scales in place. It does not slide in from outside the window,
and its motion does not animate `transform` or `filter`. An
anchored menu may rise at most 0.5rem. That rise composes with the
positioning transform and does not set `filter`. A phone-width
bottom sheet is the only edge travel. Durations and the rest of
the contract are `DESIGN.md` §6 "Dialogs".

The existing class names `.a3s-dialog-scrim`, `.a3s-dialog-surface`,
`.a3s-popup-rise`, `.a3s-row-enter`, and `.a3s-row-leave` stay.
They are implementation identifiers.

**Enforcement.** Constitution principle XVII.
`packages/ui/src/components/primitives/__tests__/dialog.test.tsx`
and `popup-motion.test.tsx` lock the in-place dialog and popup
motion.

# Aster Constitution

Distilled from the engineering practice of this repository. The full
rationale lives in
[`docs/development-standards.md`](../../docs/development-standards.md).
This document is the enforceable distillation the spec-kit phases
read. A principle marked **NON-NEGOTIABLE** may not be waived by any
spec, plan, or task.

One constitution covers this repository. A change follows the regime
of the path it edits. Crate identifiers that start with `a3s-` remain.

## Regimes

### Product regime

Paths: `apps/aster`, `apps/studio`, `crates/code`,
`crates/terminal`.

Obligations: a small hermetic test for new behavior; Tauri commands
for Aster desktop tenants; membership in the root Cargo workspace;
`publish = false`.

### Control-plane regime

Paths: `apps/cloud`, `apps/api`, `apps/auth`, `apps/billing`,
`apps/config`.

Obligations: bounded contexts (`domain/`, `application/`,
`infrastructure/`, `presentation/`, `published/`). Cloud schema
changes stay contiguous and bump `CLOUD_MIGRATION_COUNT` together
with `LATEST_CLOUD_MIGRATION_VERSION`. HTTP surfaces use
`#[controller]` with a guard and `auth.scopes`. A repository proof
is a dual-adapter proof: the same scenario runs on the in-memory
adapter and on live PostgreSQL. PostgreSQL harnesses use
`A3S_CLOUD_TEST_POSTGRES_URL` and `--test-threads=1`.

`apps/api` and `apps/cloud` keep their own Cargo workspaces. They
are not members of the root workspace.

### Shared-crate copies

Paths: `crates/acl`, `crates/boot`, `crates/orm`, `crates/event`,
`crates/lane`, `crates/flow`, `crates/sms`, and the same package
names under `apps/api/crates` and `apps/cloud/crates`.

A one-sided edit that grows the drift set fails
`tests/crate_drift_report.py`. Copies stay separate until a named
reconcile. A package is not moved across workspaces.

## Core Principles

### I. Fail Closed

Every refused condition names its reason. Denied and missing share
the not-found contract where the caller must not learn which one
occurred. An unset required value refuses activation instead of
defaulting. A misconfigured optional surface degrades to disabled
with an error-level log. It never takes down a process that can
still serve. **NON-NEGOTIABLE.**

### II. Evidence Retained

A landing that changes behavior records
`docs/evidence/<domain>/<date-slug>/OUTCOME.md` with the commands,
the counts, and an Explicitly not claimed section. Evidence
directories are not deleted, and a claim is not made without the
record. **NON-NEGOTIABLE.**

### III. Tests Follow the Path Regime

On a product path, new behavior has a small hermetic test in the
owning package. Ordinary desktop or CLI work does not require a
live PostgreSQL campaign.

On a control-plane path, a repository or authority proof follows
the control-plane regime: the same scenario runs on both adapters.
After a mass-failure run, re-run each distinct failure alone before
believing it. **NON-NEGOTIABLE.**

### IV. Closed Sets

Enums with `parse()` / `as_str()` pairs. Parse errors name the
refused set. Unknown values are refused at the boundary, never
coerced. **NON-NEGOTIABLE.**

### V. Workspaces and Published APIs

Library code does not depend on a desktop shell. On a product path,
Aster desktop tenants share the root Cargo workspace and lockfile
and do not grow another workspace. Cross-crate use goes through the
owning crate's public API. Preserve upstream package names and
public Rust APIs unless a task explicitly requires a rename.

On a control-plane path, `apps/api` and `apps/cloud` keep the
workspaces named in the control-plane regime. Domain code does not
import presentation or infrastructure. Cross-context data crosses
`published/` types.

### VI. Schema Changes Follow the Path

A schema change stays in the crate or app that owns the store.
Values are bound parameters. A raw query needs a documented reason
that the typed builder cannot express it.

On a product path the change stays in that owner. On a
control-plane path the migration identity follows the control-plane
regime. Do not add a second root Cargo lockfile.

### VII. Shrink-Only Ratchets

An existing allowlist (native dropdowns, facade debt, or any other
ratchet in this tree) may only shrink. Fix the underlying
condition. Never edit the allowlist to pass. **NON-NEGOTIABLE.**

### VIII. Replaceable Transports

A library that offers more than one transport keeps the choice out
of consumers. Transport fields do not leak into a shared envelope.
Product configuration of a transport is an ACL block.

### IX. One Configuration Language

ACL (`.acl`), parsed only by `a3s-acl`, is the only product
configuration language. Never create, restore, document, or parse
another product configuration format. **NON-NEGOTIABLE.**

Feature-consumed definition files are data, not configuration, on
the same terms as `SKILL.md`: closed-set fields, content shared
like source, and authority that the loading feature only narrows.
A definition must not name a provider, alter permission policy, or
join layered configuration discovery. Any new surface that answers
"how does the product behave" is configuration and goes in ACL.

### X. Commands, Controllers, and Test Files

On a product path, a Tauri command is registered and allowed by a
permission on the calling window's capability. Applet windows do
not receive host permissions they do not need.

On a control-plane path, an HTTP surface follows the control-plane
regime for `#[controller]`, the guard, and `auth.scopes`.

Tests live in sibling files behind `#[cfg(test)]`. Do not append
thousands of inline test lines to a production file.

### XI. Independent Judgment

Disagree when the evidence supports disagreement, and say so with
the reasoning. Do not implement a request that the evidence
contradicts without first stating the contradiction and the
corrected approach. Changing position requires new evidence, not
pressure. **NON-NEGOTIABLE.**

### XII. First-Principles Understanding and Adversarial Review

Before implementing, understand why the user needs the change.
A fix that leaves the cause in place is not done. After
implementing, try to break the change and look for what the tests
miss. A disproven finding stays recorded. A confirmed finding that
is not fixed names the exact follow-up. **NON-NEGOTIABLE.**

### XIII. One Repository

New Aster code lands in this repository. Do not create a Git
repository, a GitHub project, or a sibling checkout beside `aster`
for a library, product, or tool. Rust libraries go under `crates/`,
applications under `apps/`, and TypeScript or React libraries under
`packages/`. A second checkout of this repository is a git worktree.
The user-authorized desktop source boundary is the private submodule at
`apps/studio` (`git@github.com:kense-labs/studio.git`, `main`). It remains in
the root Rust workspace and uses the root lockfile; the parent tracks only
its gitlink, never desktop source files.
**NON-NEGOTIABLE.**

### XIV. Names Are Not Guessed

A name, entity, or alias comes from a model-supplied entity list,
a quoted span the author wrote, or an exact string already stored.
Do not infer names from capitalization, character classes, verb or
stop lists, or a regular expression tuned to an example sentence.
A missed example is not a reason to grow a matcher. Ranking tokens,
secret redaction by a known prefix, and a closed product word list
are not name extraction. Those lists do not grow to cover one
missed sentence. **NON-NEGOTIABLE.**

### XV. Meaning Is Not Matched

A decision about what the user means is made by the model or by a
typed closed set the host declared. A regex, substring, verb list,
or character class must not make that decision. Pattern matching
may only narrow fail-closed, rank candidates, or parse a mechanical
form. A missed phrasing uses the model path. **NON-NEGOTIABLE.**

### XVI. Pickers Are Drawn

No product surface ships an operating-system dropdown: no native
`<select>`, `<datalist>`, or a script-built `select` element. A
choice list is the picker in `DESIGN.md` §6. The Radix `Select`
list is shrink-only. A test fixture that exists to exercise a
native control is not a product surface.

### XVII. Dialogs Stay in Place

A modal dialog, including a desktop side panel with `role="dialog"`,
fades and scales in place. It does not slide in from outside the
window, and its motion does not animate `transform` or `filter`.
An anchored menu may rise at most 0.5rem. A phone-width bottom
sheet is the only edge travel. The contract is `DESIGN.md` §6
"Dialogs" and development-standards §16.

## Constraints

- Rust toolchain `1.97.1`. The root workspace, `apps/api`, and
  `apps/cloud` each keep their own lockfile. `publish = false`.
- Internal `a3s-*` crates resolve to a path in this repository.
- Do not restore an upstream binary update that replaces Aster with
  an A3S or Grok release.
- Production paths carry no `unwrap()` or `expect()` without a
  construction-level infallibility argument in a comment.
- Bearer comparisons use constant-time equality.
- Never commit another session's in-flight edits. Stage files
  individually and verify `git diff --cached --name-only` first.
  Do not commit unless the user asked.

## Development Workflow

A behavior change lands with its hermetic test and, when recorded,
`docs/evidence/<domain>/<date-slug>/OUTCOME.md`. A structural
migration lands as one commit. Bounded epics may use the spec-kit
phases under `specs/<NNN-slug>/`. The implementation evidence still
lands in `docs/evidence/`. Planning and acceptance are not two
copies of the same record.

## Governance

The constitution is amended through the same evidence discipline.
The behavior change lands first. The principle text follows.

# Aster

**Rust 编写的智能体执行内核与终端编程工具。**

Aster 连接你配置的模型，在项目中读取文件、修改代码并调用工具。
权限策略控制执行，事实日志记录过程，验证证据约束任务何时可以完成。
你可以直接使用 Aster CLI，也可以把内核嵌入自己的 Rust 应用。

[下载官网](https://aster-ai-lab.github.io/aster/) · [开始使用](#开始使用) · [运行机制](#运行机制) · [当前限制](#当前限制) · [参与开发](#参与开发)

## 从一个任务开始

在项目目录启动 Aster，输入你的目标，例如：

```text
修复配置解析的边界错误，只修改相关文件。
先说明计划，再完成修改并运行相关测试。
最后列出改动、验证结果和仍未解决的问题。
```

完成编程任务，需要把模型的建议接入实际执行，并保留可检查的结果：

| 任务中的问题 | Aster 的处理方式 |
| --- | --- |
| 哪些操作可以执行？ | 工具调用先经过权限判定，需要确认时等待用户回答。 |
| 执行过什么、结果如何？ | 模型、工具和控制事件写入同一份事实日志。 |
| 修改是否满足完成条件？ | 内核检查对应本次修改的验证报告，或宿主显式豁免，再判定能否完成。 |

## 开始使用

### 1. 下载 CLI

从 [最新发布页](https://github.com/aster-ai-lab/aster/releases/latest)下载对应系统的归档，或使用安装脚本（自动发现最新版本并校验 SHA-256）：

```bash
curl -fsSL https://raw.githubusercontent.com/aster-ai-lab/aster/main/scripts/install.sh | bash -s -- --prefix "$HOME/.local/bin"
```

Windows 使用 [install.ps1](https://github.com/aster-ai-lab/aster/blob/main/scripts/install.ps1)。

解压后，将 `aster` 和 `a3s-code-acp` 放在同一目录；Windows 对应两个 `.exe` 文件。
CLI 默认启动同目录的 ACP 伴随进程。需要指定其他位置时，设置 `A3S_ACP_AGENT_BIN`。

Linux 归档分两个 glibc 世代：`linux` 需要 glibc 2.32 及以上；`kylin` 是同样的一对
x86_64 二进制，针对 glibc 2.31 构建，适用于银河麒麟 V10 SP1、Ubuntu 20.04、
Debian 11 等较旧系统。安装脚本按本机 glibc 自动选择，`aster update` 使用同一规则。

已安装的 CLI 从 v0.1.2 起支持自我更新：`aster update` 会从本仓库的
channel manifest（`latest.json`）发现最新版本，校验归档摘要后原子安装
`aster` 与 `a3s-code-acp` 成对二进制；`aster update --check` 只报告不改动，
`aster update --version X.Y.Z` 安装指定版本。v0.1.1 的旧安装不含该通道，
请先用上面的安装脚本重装一次。

该版本为未签名构建。

### 2. 配置模型

创建或编辑 `~/.a3s/config.acl`。以下示例使用 OpenAI 兼容接口，
请把接口地址和 `your-model` 替换为服务实际提供的值：

```acl
default_model = "openai/your-model"

providers "openai" {
  base_url = "https://your-api.example/v1"
  api_key = env("OPENAI_API_KEY")
  models "your-model" {}
}
```

密钥通过环境变量提供。更多配置见 [ACL 示例](crates/code/agent.example.acl)；
`A3S_CONFIG` 可以指定其他配置文件，终端内的 `/config` 用于管理模型配置。

### 3. 启动项目

在解压目录执行，并将项目路径替换为实际路径。

macOS / Linux：

```sh
export OPENAI_API_KEY="你的 API 密钥"
./aster --cwd /path/to/project
```

Windows PowerShell：

```powershell
$env:OPENAI_API_KEY = "你的 API 密钥"
$env:A3S_CONFIG = Join-Path $HOME '.a3s/config.acl'
.\aster.exe --cwd C:\path\to\project
```
