目标

  • 每个聚合只有一个写权威；成员面（a3s-api）对 Cloud 聚合只做投影 + 四条联邦契约（SubjectLink / DirectoryProjection / ArtifactAdmission / EntitlementCompile）。
  • 每个 GA 地平线交付一条可用的窄价值流，而非多个组件级半成品；发布说明只载 Verified 项。
  • 执行底座唯一（Box / R0 / D0）；产品 lane（FN0 / WEB0 / MCP0 / CELL0 / I0 / AR0）全部编译到底座，零私有生命周期。
  • 共享 crate（a3s-boot / orm / acl / flow / event / lane / sms）单一上游，三仓漂移可度量、可收敛。

非目标

  • 不删除架构寄存器（preservation matrix 11 行为 normative；变更需单独迁移提案）。
  • 不砍四条联邦契约——它们是收敛的工具，不是收敛的对象。
  • 不恢复 Docker 路径、不引入第二调度器 / 审计库 / 工作流引擎（既有红线）。
  • TEE / SEV-SNP 硬件认证维持 physical-capacity stop，不进关键路径。

三条新增治理原则（P1–P3）

  • P1 WIP 上限：任何时刻「进行中」lane ≤ 8；新 lane 入场必须有一条出 Verified 或显式降级。
  • P2 组件级老化：组件级实现连续两个季度无新留档证据 → 自动降级 Planned 或删除，防止半成品库存。
  • P3 跨栈只读投影：成员面对 Cloud 聚合禁止第二写路径，落实为 CI 架构测试（扩展 apps/api 既有 admission_test.rs / architecture_source_tests.rs）。
工期为净工作周（每域按 1–2 人投入），并行时日历时间短于各任务之和；「负责」为角色而非个人；所有验收等价于 ROADMAP 的 Verified 语义——留档的真实 provider / 故障 / 恢复证据，component-only 不算完成。
