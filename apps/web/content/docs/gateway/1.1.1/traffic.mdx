Gateway 的请求路径为 `Entrypoint → Router → Middleware → Service → Backend`。每一层负责不同的流量决定。

`request_timeout`、流空闲期限和流总期限是不同约束。长流需要同时检查首响应、持续活动和结束状态。

## Gateway 与 Box

standalone 模式可以选择 Box 执行器。Box 提供就绪副本端点，Gateway 再原子替换实时后端池，并放行有界等待请求。

Box 排空并终止工作负载前，Gateway 先撤回对应端点。该自动扩缩能力仍是实验性，真实 MicroVM 工作负载符合性尚未完成。

`cloud-managed` 流量不调用 Box。Cloud 决定期望副本，Gateway 只执行收到的快照。

## 托管 Runtime Service

嵌入式 A3S 宿主可以使用 `Gateway::with_managed_service_state` 或 `Gateway::with_middlewares_and_managed_service_state` 绑定私有 Runtime 路由。

该路由只支持明文 loopback HTTP 入口和 loopback Runtime 上游。宿主负责 Runtime 配置与包授权，Gateway 负责私有路由、健康检查、准入关闭、排空和删除。

托管路由作为独立 overlay 保存。普通 reload 和托管快照 reload 不会删除该 overlay。它不是公共控制平面，也不是 ACL 修改接口。

## 验收

1. 用慢响应与长流分别验证首响应和空闲期限。
2. 停止一个后端，确认健康选择不会放行失败目标。
3. 在响应开始后停止后端，确认不会通过重放改变响应。
4. 应用无效快照，确认先前运行时继续服务。
5. 托管 Runtime Service 排空时，确认 Gateway 拒绝新请求并等待旧流结束。
6. 重启后，确认原执行代际和收据身份保持一致。
