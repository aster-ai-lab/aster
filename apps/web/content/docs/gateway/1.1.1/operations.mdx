Gateway 的安全边界覆盖监听器、上游、快照、Node API、凭据和本地状态。Cloud、Power 和 Box 各有独立边界，不能用 Gateway 的校验结果替代。

## 静态对象目标

standalone 的 `static_bundles` 支持密封 manifest、GET/HEAD、SPA、ETag、Range 和有界缓存。对象必须先通过大小和 SHA-256 校验，才能进入缓存或响应。

使用静态目标时必须配置 `local_digest_store`。缺少该目录时，校验失败。Cloud-managed 在共享对象权威接入前拒绝静态 bundle。

ACL 和快照不能携带 S3 端点或对象凭据。Gateway 只负责读取与响应，不负责对象写入、删除或发布。

## 用量投递

`managed.usage_spool` 保存无提示正文的有界用量记录。记录支持完整性检查、重启恢复、有序重放、连续确认和压缩。

推荐使用 Cloud node-control mTLS 上传。需要配置 `cloud_ingest_endpoint`、客户端身份文件和服务器 CA 文件。Bearer token 仅用于 fixtures，不能与 mTLS 字段混用。

Cloud 负责长期账本与汇总。Gateway 的本地 spool 和上传恢复不能替代 Cloud 的生产验收。

## 验收清单

1. 运行 `cargo fmt --all -- --check`。
2. 运行 `cargo clippy --locked --all-targets -- -D warnings`。
3. 运行 `cargo test --locked`。
4. 验证无效 ACL 不会替换当前运行时。
5. 验证认证、Redis 和上游故障分别返回对应错误。
6. 验证响应中间件失败时不会返回未检查的上游正文。
7. 验证 Node API 拒绝未授权访问。
8. 验证 Gateway 拒绝摘要错误、缺失文件和越界路径。
9. 验证用量上传失败后可以从原游标恢复。
