## 我们要做出的东西

这一系列从空的 Rust 宿主开始，做一个叫 `tutorial-agent` 的终端编码助手：在终端输入任务，看模型回复和工具进度，批准需要确认的操作，检查修改结果，并在退出后恢复会话。它使用 Aster Code 的 Rust SDK；模型推理、工具执行和事实日志都交给 Core。

先把一条只读任务跑通，再加入写入和执行权限。每章都继续修改 `apps/tutorial-agent`，不需要为每个能力另建一个 Agent。完成基础界面后，后面的章节按需求接入；没有配置的外部服务不会因为读过教程就变得可用。

## 阅读前准备

你需要能阅读 Rust 的 `async`、`Result` 和 `Arc`，并准备一份能够连接模型的可信 ACL 配置。所有 Cargo 命令都在本仓库根目录执行，沿用根工作区、锁文件和固定 Rust 工具链。练习包使用本地 `a3s-code-core`，不从包仓库安装另一个 SDK。

终端界面使用工作区已有的 Ratatui 和 Crossterm。教程会给出文件名和代码；其中 `main.rs` 的替换会明确说明，后续章节给出的函数则接入前面已经建好的运行层。

示例中的 `use` 合并到对应模块顶部，已有导入不必重复添加。第四章开始，运行层会保留一个 `Runtime`，统一持有 Agent、会话和确认通道；后面的存储与扩展继续加到这个对象上。

基础章节的任务统一使用“解释 README 和测试入口”。到了验证章节，再在可丢弃的练习项目中修复一个失败测试。这样能分别观察读取、权限、修改和验证，不会一上来就混在一起。

## 教程和接口参考怎样配合

想先了解组合接口的设计原因，读[设计哲学](../design/philosophy/)；计划研究递归自我改进时，再看 [RSI 与 Meta Harness](../design/rsi/)，了解哪些工作需要由宿主组织。

教程解决“这个能力放进应用的哪一层、下一步改哪个文件”。[Meta Harness 使用指南](../meta-harness/) 列出字段、限制和实现位置。遇到参数细节时先查参考，再回到当前章节继续组装应用。

不要把界面里的“回复结束”当成全部工作完成。后面会反复用同一条标准验收：工具结果完整、报告对应当前修改、原运行已退出、资源已经收尾。
