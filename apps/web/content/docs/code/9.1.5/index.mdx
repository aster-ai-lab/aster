## Harness 负责什么

假设你让 Aster 修复一个失败的测试。模型需要先查找代码，再修改文件、运行测试，根据结果决定是否继续。Harness 负责组织这些步骤：准备模型输入、执行工具调用、检查权限、记录结果，并判断任务能否结束。

在 Aster 中，这部分由 **A3S Code** 实现。它的核心库是 `a3s-code-core`，下文简称 Core。终端和桌面通过 ACP 协议与 `a3s-code-acp` 进程通信，由该进程调用 Core。Rust 应用也可以直接嵌入 Core。使用这套库的应用称为“宿主”。

Core 提供 Anthropic、OpenAI、智谱及 OpenAI 兼容接口的模型适配器。

## 事实日志如何支持恢复

`FactRun` 是执行任务的核心，底层使用 `a3s-effect`。用户输入、模型回复、工具结果等事件按顺序保存在“事实日志”中。执行组件读取这些记录，计算当前状态和下一步可以执行的动作。

例如，一次工具调用已完成并留下记录，恢复会话时就不需要重新执行这一步。运行时根据日志重建状态，继续处理尚未完成的动作。宿主通过实时事件或运行快照显示进度。子代理采用相同机制，但各自保存日志。

<Callout title="操作完成与日志写入之间，仍可能发生崩溃">
如果外部服务已经接受了一次写入，但本地还没来得及保存结果就崩溃了，恢复时仍需核实那次操作是否成功。直接重试可能造成重复写入。
</Callout>

## 可以组合的执行组件

Rust 宿主可以选择和组合执行组件，例如系统指令、工具目录、调用预算、上下文压缩和调度器。这套组合接口称为 Meta Harness。不指定组合时，会话使用默认组件。

<ComponentStrip />

自定义组件也从日志计算状态，由运行时执行动作。无论如何组合，工具权限和完成检查都由 Core 执行。Rust 接口支持自定义组件树；当前 ACP 入口只接受代码中预先列出的几套组合。

具体配方、自定义组件、工具接入和恢复接口，见 [Meta Harness 使用指南](./meta-harness/)。

## 默认包含哪些能力

Core 默认使用 `local-code` 构建，包含本地编码所需的执行循环、工作区工具和词法索引。高级工作流、研究与评估、浏览器搜索、S3 和遥测需要额外的构建开关。持久记忆和长期目标还需要宿主提供相应配置或服务。

<CapabilityCards />

例如，编译了记忆模块，并不意味着会话已经开始保存和召回长期记忆。宿主还需要指定存储、访问范围和激活规则。具体接入方法见“宿主接入”。
