## 一次修复的执行过程

以下示例修复日期导出的跨月错误。
输入包含目标、文件范围和验收条件。
模型读取代码并提出修改。
工具执行修改，测试产生检查结果。
Core 核对执行依据，再决定能否结束。

## 职责分层

<PeleAtlasDiagram name="meta-harness" />

拆解图中的层是职责层。
层间距离不代表进程、线程或机器。
底层检查仍然约束上层组件。
替换系统提示词，也会保留工具权限判定。

同一个修复例子的阅读顺序如下：

1. 阅读[提示词](./system-prompts/)。
2. 对照[上下文装配](./context/)。
3. 检查[单次运行](./execution/)。
4. 核对[完成依据](./completion/)。
5. 阅读[分轮执行](./long-running/)。
6. 核对[中断后的恢复](./recovery/)。

## 四种执行身份

| 身份 | 含义 | 区分原因 |
| --- | --- | --- |
| Session | 一段持续的会话 | 目标与记录跟随原会话 |
| Run | 一次接纳的执行 | 控制命令必须指向原运行 |
| Tool call | 一次具体调用 | 确认回答必须绑定原参数 |
| Goal | 跨多轮的目标 | 一次 Run 结束后仍可能有未完成步骤 |
