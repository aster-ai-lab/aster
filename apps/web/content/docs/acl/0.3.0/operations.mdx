## 诊断与截断

`parse` 与 `parse_with_limits` 返回首个解析错误。编辑器需要多条错误时，使用 `collect_diagnostics` 或 `collect_diagnostics_with_limits`。后者按确定性的恢复规则收集错误，不会把有错误的文本当成有效配置。

位置包含完整 `Span`。行与列从 1 开始，偏移按 UTF-8 字节从 0 开始。显示错误时应使用诊断代码与位置；不要把完整配置、凭据值或函数实参写入日志。

超过诊断预算后，报告以 `truncated` 标明仍有未返回的错误。预算为零也不能据此接受输入。见 <SourceRef path="crates/acl/src/diagnostic.rs" match="pub struct DiagnosticReport {">诊断报告</SourceRef>。

## 规范字节与摘要

`canonical_bytes` 输出无 BOM 的 UTF-8、LF 换行和恰好一个末尾 LF。`canonical_digest` 对这些字节计算 SHA-256，返回小写的 `sha256:` 加 64 位十六进制字符串。见 <SourceRef path="crates/acl/src/canonical.rs" match="pub fn canonical_digest(document: &Document)">摘要入口</SourceRef>。

属性和对象字段按规范规则排序；块、标签、列表元素和函数参数的顺序仍有意义。解析会丢弃注释与源码空白，因此这些差异不进入摘要。字符串与标签保留原始 Unicode 标量序列，不执行 NFC/NFD 归一化。

可信 Schema 可以用 `BlockSchema::unordered(true)` 声明同名重复块无序，再使用 `canonical_bytes_with_schema` 或 `canonical_digest_with_schema`。这两个接口使用 Schema 作为排序元数据，**不执行 Schema 接纳**；必须先调用校验接口。

摘要证明内容身份，不证明签名可信、调用获准、凭据有效或配置可以激活。

## 验证清单

1. 输入超过字节、深度、集合或 token 限制时，确认返回对应错误。
2. 未声明字段、错误值类型和标签数量错误必须被 Schema 拒绝。
3. 零诊断预算下输入错误仍不能被接纳。
4. 生成后重新解析，确认字符串与数字等值类型没有改变。
5. 核对属性重排保持规范摘要一致，而有序列表重排改变摘要。
6. 函数调用仍是 AST 数据；取值与授权由宿主显式完成。
