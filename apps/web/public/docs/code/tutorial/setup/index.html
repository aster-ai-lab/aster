01 · 跑通第一个工作区会话

建立练习包，接入可信 ACL，并用最小只读权限完成一次请求。

Aster Code 9.1.6 · 当前源码·2026-10-26

本章要得到什么

先做一个普通终端程序：接收 ACL 文件路径和项目路径，询问模型“README 和测试入口在哪里”，打印结果后退出。本章先确认 SDK、模型与工作区能够配合，再加入界面。

准备一个没有私人资料的练习项目。ACL 使用你已经验证可用的宿主模型配置，工作区使用练习项目的绝对路径。配置文件中的密钥从环境变量读取；不要把真实密钥写进教程工程。

建立工作区成员

仓库已提供完整参考工程 apps/tutorial-agent，也已加入根工作区。第一次阅读可以先运行无密钥演示，再按章节理解和修改实现：

cargo run --locked -p tutorial-agent --example offline_tui

输入一条任务后，演示会读取临时项目的 README，请求执行无副作用的 project_label，最后询问输出格式。F6 回答工具确认，F8 切换问题选项，F9 提交回答，Ctrl+C 退出。模型由固定响应替身提供，不访问真实供应商。

如果希望从空包逐章练习，第一章最小 Cargo.toml 如下。已有完整工程包含后续章节依赖，无需删成这个最小版本；两者都沿用根锁文件：

[package]
name = "tutorial-agent"
version = "0.1.0"
edition = "2024"
publish = false

[dependencies]
a3s-code-core = { path = "../../crates/code/core" }
anyhow = { workspace = true }
tokio = { workspace = true }

这里的路径以 apps/tutorial-agent 为起点。不要在练习包里添加新的 [workspace]，也不要单独生成第二份锁文件。初始化桌面子模块的仓库要求同样适用于后面的 Cargo 命令。

把打开会话放进运行层

创建 src/runtime.rs。把参数解析与会话设置放在这里，后面切换终端界面时继续使用它。

use std::path::PathBuf;
use anyhow::{Context, Result};
use a3s_code_core::{Agent, AgentSession, SessionOptions};
use a3s_code_core::permissions::{PermissionDecision, PermissionPolicy};

pub fn arguments() -> Result<(PathBuf, PathBuf)> {
    let mut args = std::env::args_os().skip(1);
    let config = PathBuf::from(args.next().context("缺少可信 ACL 路径")?);
    let workspace = PathBuf::from(args.next().context("缺少项目路径")?)
        .canonicalize()?;
    anyhow::ensure!(workspace.is_dir(), "项目路径必须是目录");
    anyhow::ensure!(args.next().is_none(), "只接受 ACL 和项目两个参数");
    Ok((config, workspace))
}

pub async fn open(config: &std::path::Path, workspace: &std::path::Path)
    -> Result<(Agent, AgentSession)>
{
    let config = config.to_str().context("ACL 路径必须是 UTF-8")?;
    let workspace = workspace.to_str().context("项目路径必须是 UTF-8")?;
    let agent = Agent::new(config).await?;
    let mut policy = PermissionPolicy::new().allow_all(&["read", "ls"]);
    policy.default_decision = PermissionDecision::Deny;
    let options = SessionOptions::new().with_planning(false).with_permission_policy(policy);
    let session = agent.session_async(workspace, Some(options)).await?;
    Ok((agent, session))
}

保留返回的 Agent 和 AgentSession，应用关闭前都不要丢弃。这里仅允许准确列出的读取工具；未列出的调用会被拒绝。提示里写“不要修改文件”有助于表达任务，但真正约束操作的是权限策略。

发送第一次请求

创建 src/main.rs：

mod runtime;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let (config, workspace) = runtime::arguments()?;
    let (_agent, session) = runtime::open(&config, &workspace).await?;
    let result = session.send("读取 README，并说明项目的测试入口。", None).await;
    session.close().await;
    println!("{}", result?.text);
    Ok(())
}

先保存 send 的结果，再关闭会话，最后处理错误。这样请求失败也会经过关闭路径。history: None 使用并更新会话自己的历史；每次请求都重新创建会话，则无法自然接续上一轮对话。

运行与验收

把路径替换成你实际准备的文件和目录：

cargo check -p tutorial-agent
cargo run -p tutorial-agent -- /absolute/path/agent.acl /absolute/path/demo-project

检查三件事：模型能返回文本；说明确实来自练习项目；要求它写入一个文件时调用被拒绝，磁盘也没有变化。不要只检查它是否在回复里说“我没有写入”。

如果模型连接失败，先检查 ACL 的默认模型引用、环境变量和服务地址。如果是工具拒绝，保留拒绝信息；不要把默认决策改成 Allow 来掩盖配置问题。如果是沙箱初始化错误，按目标平台准备沙箱，或选择宿主已经验证的后端。

下一章

send 要等待整次运行结束。下一章换成流式入口，观察回复、工具和终态如何分别到达。会话配置继续使用本章的 runtime::open。

完整参考实现

本章代码展示最小接入；后续章节逐步补齐运行层。完整版本可直接查阅 runtime.rs、main.rs 和工程说明。真实模型使用文章中的 ACL／项目两个位置参数；无界面模式另传 --headless "读取 README"，仅开放读取和项目标识工具，避免无人处理确认。
