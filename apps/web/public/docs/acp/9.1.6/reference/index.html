ACP 扩展与宿主元数据参考

标准协议之外，代理接受哪些请求、发出哪些通知，以及谁提供元数据。

Aster ACP 9.1.6 · 当前源码·2026-10-26

标准 ACP 与宿主扩展

标准入口见协议生命周期。下表对应当前 HostMethod 解析集合：17 个处理分支，共 23 个明确 method 或前缀族。compact_conversation 与 interject 保留源码定义的 x.ai 前缀兼容族；不能据此前缀为其他任意名称宣称支持。

未知 method 返回 method_not_found。扩展参数以公开的 typed schema 为准，不能以模型能理解某段 JSON 为兼容标准。operationId 用于标识这次宿主操作；遇到冲突先读取当前状态，不隐式放宽条件。

下面都是协议 _meta 的字段，不是 ACL 配置。用户提示文本不能授予同等权限。

单轮元数据

a3sTurn.directives 为有界的本轮约束，research 选择本轮研究约束，planFirst 仅本轮先计划。它们不改变存储的权限姿态，也不能替代 provider。常设 guidelines 上限 12,000 字符、role 500 字符；directives 最多八项、每项 500 字符，按当前实现裁剪和清理。

a3sExecutionObservation=1 与有效 promptId 打开只读执行观测，见流式展示。reasoningEffort 必须使用模型元数据允许的值。

构建与能力面

ACP 默认 svg-png、account-import；浏览器搜索另启 headless-search。原生插件、MCP sampling、Office、编辑器文本与知识编译各自需要宿主准入。Core 的全部公开合同见Core 能力索引，其中 Rust provider 注入不是通用 ACP wire 方法。
