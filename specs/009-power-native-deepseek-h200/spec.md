# Feature Specification: Power 原生 DeepSeek V4.1 八卡 H200 推理

**Feature Branch**: 保持当前分支。

**Created**: 2026-10-22

**Status**: 按规划实施 P0；构建接入与模型缺口审计已验证，完整原生实现与 GPU 验收尚未完成。

**Input**: 在 aster-power 自身推理路径中借鉴 DeepInfer，规划 DeepSeek-V4.1-Flash-1017 在八卡 H200 上的正确性、低延迟与吞吐优化，继续保留 XQ 权重目标。

**Execution request**: 用户已要求按规划实施，并在 H200 上完成 Power 原生 DeepSeek V4.1 Flash 部署后交付访问地址与临时 API Key。

**2026-10-23 goal update**: 用户进一步要求“必须充分压榨服务器性能进行极致的推理加速和优化，完成压力测试”。基本服务交付只是中间里程碑；完整目标还需要真实八卡性能对照、瓶颈归因、已测配置晋升及持续压力/故障恢复验收。

**2026-10-24 goal update**: 当前用户目标明确为 DeepSeek V4.1 Flash XQ 三值混合量化模型在八张 H200 上的**多个完整原生副本**。每个副本必须独立加载完整 40 层、拥有独立请求/KV 状态，通过 aster-power 执行真实生成；不能将一个跨八卡执行组的八个 stage 称为八个副本。比较 4×2 卡、2×4 卡候选和 1×8 卡控制组，最终多副本方案按相同权重/质量门槛下的实际吞吐、交互延迟、显存和主机成本选择。官方检查点保持独立参考身份，不能替代 XQ 完整生成证明。

**Gate context**: 延续 005 的测量合同，新增原生模型执行路线。Power 保持模型中立，DeepSeek 架构归模型所有者。SGLang 与 Xolotl 是参考执行器；转发成功与参考执行器的性能不作为原生完成证据。

## User Scenarios & Testing

### User Story 1 - 确认真正由原生路径计算 (Priority: P1)

操作者能够识别实际计算提供者、模型与量化身份，运行原生 CUDA 路径并知道任何拒绝原因。

**Why this priority**: 当前已验证的是 Power 代理到 SGLang，尚未证明原生 V4.1 适配。

**Independent Test**: 原生后端注册、能力与启动测试注入参考执行器不可访问的环境；原生请求仍能完成小模型计算。缺少模型适配、CUDA 构建或所需算子时必须拒绝启动，不能改走 HTTP 或 CPU。

**Acceptance Scenarios**:

1. 给定精确模型清单和 CUDA 构建，运行原生请求时，收据记录实际内核、设备、权重和模型图身份。
2. 给定仅启用 `server` 的构建，要求原生 CUDA 模式时，明确拒绝，不能把代理服务就绪当作原生可用。

### User Story 2 - 官方检查点原生结果正确 (Priority: P1)

模型所有者实现 tokenizer、CED/Engram、稀疏注意力、专家路由、KV 状态与生成循环，使用同一官方检查点验证数值与任务结果。

**Independent Test**: 微型、固定、无下载的架构与量化张量夹具，逐算子和逐层比较参考实现；覆盖 chunk/decode、一致性、错误布局、量化块边界、取消和回滚。

**Acceptance Scenarios**:

1. 支持的张量类型与布局按清单精确加载；未知布局、缺失比例因子、维度错误及不匹配 tokenizer 必须拒绝。
2. 单层可在单卡验证；完整官方模型使用满足内存条件的多卡放置，不能将“单卡单层通过”宣称为完整模型通过。
3. 在同权重、同输入 token 与预先冻结误差预算下通过数值对照及固定数学、代码、工具、长文检索用例；回复非空不构成正确性证明。

### User Story 3 - 八卡真实加速 (Priority: P2)

算子和状态尽可能留在 GPU，八卡按已实现的 TP/EP/attention DP 方案执行，通信、内存、队列均有界。

**Independent Test**: CPU 上的分片/路由模拟证明与未分片计算等价；可用 GPU 上验证实际 collective、peer copy、取消及故障恢复，完整性能在独占八卡 H200 验收。

**Acceptance Scenarios**:

1. 设备声明必须匹配实际参与计算与通信的设备；不能用枚举八张卡替代八卡执行证据。
2. 常驻预算不足时拒绝该放置，或使用事先声明并独立测速的分层放置；不暗中改精度、换模型、转 CPU 或移交其他服务。
3. 动态专家副本只改变放置，不能改变 router 选出的专家、权重或 token 顺序。

### User Story 4 - 多轮与推测解码保持语义 (Priority: P2)

连续批处理、KV 前缀复用和 DSpark 降低重复工作，错误、取消与草稿拒绝不污染状态。

**Independent Test**: ragged batch 与逐请求参考一致；跨租户、分叉前缀、模型换代、缓存失效均被验证。草稿全部接受/全部拒绝、部分接受及约束输出验证状态一致性。

**Acceptance Scenarios**:

1. 缓存复用按调用者、模型、tokenizer、模板与精确 token 前缀隔离；未知驻留状态不能当作缓存命中。
2. DSpark 的候选 token 由目标模型验证后提交；不兼容草稿、缺少 confidence head 或成本曲线时拒绝对应自适应模式。
3. SWA bounded replay 单列为模型相关的数值变更实验；未通过其质量门槛时，普通完整 prefill 保持可用。

### User Story 5 - 达标口径清楚 (Priority: P2)

用户分别看到单请求速度、并发总吞吐、TTFT、逐 token 延迟、错误和内存成本。

**Independent Test**: 测速工具以固定事件流核验计数和单调时间；拒绝帧数充当 token、脱敏取整计数、遗漏失败、混淆峰值和持续值。

**Acceptance Scenarios**:

1. 用户于 2026-10-24 明确：**单个请求生成速度必须达到 1000 token/s**。单请求 decode、完整请求耗时与并发总吞吐分别设置结果字段；并发合计、缓存重放或合成小模型结果不能替代该单请求验收。
2. 官方权重与 XQ 是不同模型/量化身份，分别对照、分别验收；不能通过换权重宣称同模型加速。
3. 硬件、检查点、输入输出长度、并发、缓存和思考模式不同的结果不得直接作为倍率结论。

### Edge Cases

- F32 静态图边界不支持的 FP8/MXFP4，以及 XQ 的 PTQ1_0/Q2_0/Q3_K 混合块。
- 全模型解量化导致 HBM 峰值超过预算；Engram 的 HBM/DRAM/NVMe 路径与真实传输开销。
- collective rank 失败、路由版本错配、batch 中途退出、草稿回滚、约束输出与普通请求混合。
- 长上下文、缓存碎片与前缀分叉；只剩少量 token 时的批处理饥饿。
- 缺少独占 GPU、控制连接失联或下载仍进行：保留可继续状态，不重复提交作业或重启下载器。

## Requirements

### Functional Requirements

- **FR-001**: 必须绑定构建 features、执行器、权重和设备身份；原生不可用时拒绝原生请求，禁止静默代理或 CPU 回退。
- **FR-002**: 必须保持 Power 通用运行时与模型架构的所有权边界；拒绝在通用缓存、调度和张量层猜测模型家族、张量名或层意义。
- **FR-003**: 必须按实际量化格式执行 SM90 可用算子；拒绝把全模型 F32 展开作为高效低比特执行。
- **FR-004**: 必须先完成单算子/层数值验证与完整模型正确性，再评估相应优化；不以构建或声明能力通过替代推理。
- **FR-005**: 必须对每个设备核算权重、KV、草稿、collective、图和 scratch 峰值；不足时拒绝该 profile。
- **FR-006**: 必须实现并验证真实八卡通信后启用对应 TP/EP/DP profile；拒绝未经实现的并行组合。
- **FR-007**: 必须复用现有 admission、执行批次、权重驻留和取消所有者；拒绝无界队列、后台失控任务及跨请求状态污染。
- **FR-008**: 必须用 H200 测量校准 prefill/verify 成本，成本曲线失效时采用已验证的固定策略或拒绝自适应模式。
- **FR-009**: 必须隔离 KV 复用，并给 SWA replay 与 DSpark 独立质量及回滚门槛；拒绝未验证候选提交。
- **FR-010**: 必须保留失败、超时和未达标记录；禁止依赖隐私取整 token 或不完整对照宣称加速。
- **FR-011**: 必须延续原 XQ 下载与准备状态；官方原生路径通过不构成 XQ 推理或优化完成。
- **FR-012**: 必须使用仓库内本地 Aster 依赖、ACL 和现有工作区规则；拒绝新增独立仓库、工作区、锁文件或机器缓存依赖路径。
- **FR-013**: 必须在 H200 原生服务完成正确性与运行验收后，从用户可用入口完成真实推理并交付准确地址、模型名和新生成的临时 API Key；明确到期时间与撤销方法。Key 仅保留在服务器任务私有目录及用户明确授权的交付回复，拒绝写入仓库、证据、进程参数或公共日志。未完成原生部署不得以参考服务地址交付。
- **FR-014**: 必须在同一独占八卡上按实际计算、HBM、通信及主机/I/O trace 归因瓶颈，比较受支持的并行/副本、量化驻留、batch、KV 与 DSpark 配置；不能以串行切层可启动、提高网关并发或 GPU 利用率单值代替充分优化。交互与吞吐分别选择经质量验收的最优已测配置，保留无收益/退化候选及剩余瓶颈。
- **FR-015**: 必须完成有界升压、持续稳定性、过载、长短请求混合、取消、缓存隔离及自有实例故障恢复压力测试，保留所有请求的真实 token、时延、失败/拒绝和资源峰值；测试范围、时长、数值门槛在 campaign 前冻结。健康检查或少量请求不能关闭该要求。
- **FR-016**: 必须部署至少两个完整 XQ 原生执行组，八张物理 H200 的 UUID 分组互不重叠；每组有独立模型、请求状态、缓存所有者/epoch、队列与故障边界。Power 按真实负载和精确会话/前缀身份路由，一次已准入生成固定在其组内；不以虚增并发、共享同一串行模型锁或未经验证的跨组 KV 迁移宣称多副本。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 小型原生夹具无需下载、网络或 GPU 即可验证格式、层语义、路由、状态、调度与拒绝合同；实际通过数随实施记录。
- **SC-002**: 官方检查点完成原生 GPU 计算、真实流式文本/工具、错误与取消验收，执行链不依赖参考 HTTP 服务。
- **SC-003**: 独占八卡上完成匹配基线/候选、至少三次重复的延迟与吞吐测量；持续目标与单请求目标独立报告。
- **SC-004**: 新 profile 通过预先冻结的正确性、数值、质量、峰值内存和延迟门槛才可晋升；最终完整 XQ 模型的真实单个请求生成速度必须达到 1000 token/s，计数包括真实接受输出及其验证成本。未达标时保留实际值及下个已测瓶颈，目标保持未完成；并发总吞吐达标不关闭此门槛。
- **SC-005**: XQ 下载完成后通过其自身格式、结果与性能验证，不能复用官方模型的完成标记。
- **SC-006**: 用户入口完成真实流式请求、鉴权拒绝、临时 Key 有效期与撤销验收；交付地址和 Key 与已测原生实例一致，重启后过期凭据不能重新有效。
- **SC-007**: 完成 FR-014 的同硬件性能矩阵及逐项至少三轮匹配对照、负结果与瓶颈 trace，分别晋升交互/吞吐配置；完整目标不在基本 XQ 服务启动时结束。
- **SC-008**: 两种晋升配置各完成至少 30 分钟持续负载；升压与过载演练保留全部成功、超时、取消及拒绝，准入容量内没有错误结果、状态串用、OOM 或未恢复的服务故障，资源/延迟门槛在实验前冻结并通过。真实故障只作用于本任务拥有的实例。
- **SC-009**: 八卡上至少两个独立完整 XQ 副本同时完成真实生成；记录每组模型/UUID/状态身份、逐副本与聚合吞吐、KV 亲和/隔离和单副本失败后的恢复。比较受支持的 2/4 卡组，未完成整模和压力测试前不得把 peer 小张量通过视为多副本部署完成。

## Assumptions

- 八卡 H200 是部署地点；本机承担源码、规划和客户端工作。
- 官方缓存与已测代理链路可作为参考，但不假定控制连接、独占资源或完整权重校验当前仍可用。
- 初始优先采用保留目标模型语义的优化；SWA replay 等数值变更单独标记与验证。
- 用户已明确 1000 token/s 是单请求目标；仍独立报告总吞吐、TTFT 和端到端成本，不将其合并或替代。
- 没有需要用户决定的澄清标记；算子能力、工作区接入及校准阈值是 T001–T004 的技术调查输出。

## Explicitly Not Claimed

- 原生 V4.1 已实现、8 卡 H200 已达性能上限、1000 token/s 已可保证。
- SGLang 的 65/383 token/s 属于 Power 原生执行成绩。
- Xolotl、普通 llama-server、官方 FP8/MXFP4 和社区 XQ 具有相同权重或能力。
- DeepInfer 的共享 KV 系统或服务负载均衡已完整公开或已被移植。
