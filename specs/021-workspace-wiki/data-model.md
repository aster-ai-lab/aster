# Data model: Workspace Wiki

## Ownership

宿主持有项目/任务到真实工作区的绑定与文档缓冲。Core/ACP 持有原 Run、权限与模型事实。OKF 持有既有知识维护任务、候选和发布产物；WikiIndex 检索同一发布结果。Studio renderer 仅保留显示状态/安全草稿。

以下关系扩展现有类型和维护账本，不另建业务存储。项目集合由原生 PlaneStore 的 `workspaces.json` 持有；旧 renderer 集合只作一次受保护的初始化输入，之后不再作为可写权威。归档只改变注册关系，不移动或删除项目源目录。

## WikiCatalogView

- 仅为弹层呈现状态：project/task 模式、原目录来源、查询/分页/滚动、所选对象和返回层级、触发点焦点。
- 目录项由既有项目/任务元数据与已发布 Wiki 状态投影，不保存第二份对象集合，不读取所有源目录来填卡片。
- 浏览目录不赋予任何工作区读取范围，也不触发生成；选卡后由宿主解析原 `WorkspaceWikiBinding`。
- 当前后台任务与草稿不受选卡影响；旧查询/组/对象的异步结果不能写入新视图。关闭/返回不是停止运行。

## WorkspaceWikiBinding

- 原租户/主体、project 或 task 的已存 ID、workspace ID、canonical root 与绑定代次。
- 读取范围/准入策略身份；任务根从原会话实际 cwd 解析，不从项目名推导。
- source root 与宿主确定的 output root 分离；个人 vault 继续走原 personal 模式。
- project 的合法子任务工作区来自原引用关系，不从 UUID 样式目录猜测；只纳入本范围实际拥有的读取权。
- 共享发布结果要求主体边界、canonical source root、读取范围、准入/egress 规则和源代次都一致。绑定不是新的权限来源。

## WorkspaceSourceSnapshot

- 已准入的文件/文本块、结构信息、可用符号/引用及它们的来源范围和内容代次。
- 代码行范围与现有资料提取器的页/段落/单元格范围；不将无法确认的转换位置伪装为精确锚点。
- coverage 包含本次纳入、跳过/拒绝/超限及不支持的文件；不默认携带聊天、执行状态、凭据或生成 Wiki。
- 可把有界源片段物化为既有编译 staging 的只读输入；宿主保存到原源文件的映射，模型不能重写映射或获得原目录写权限。

## WikiGeneration

- 复用原维护任务 ID、源代次、模型/运行事实、候选输出、发布代次及活动记录。
- 页面带模型提供的标题/主题、链接、引用和推断标记；概览是派生内容，不复制一份项目配置。
- 页面到源/符号/结构证据的关系用于失效；依赖未知时保守标记相关概览/页面过期，不推断其仍当前。
- 工作区机器生成页按校验后完整代次发布；保留上一可读代次。个人 vault 的人工笔记和审阅策略不改变。
- 输出目录/文件被 source admission 排除，避免自引用触发无穷生成。

## WorkspaceEncyclopediaRetrieval

- 不保留独立百科问答入口、会话或协议；普通任务通过原内置 `search_wiki` 检索已保存绑定的工作区百科。
- 原 WikiIndex 只收录该输出根的当前 `concepts` 页面，排除历史、候选及 `wiki/local`，不合并其他工作区或 personal/team。
- 路径与片段去重后返回真实页面出处；来源当前性由原宿主引用接口重新校验，生成文本不能自行认证引用。
- 普通任务的原文件 hybrid 检索沿用原 catalog、持久 aster-vec FTS 和异步向量构建。Studio 由受信 ACL 启用既有离线 `local_cpu`；受限编译/审阅会话跳过环境向量预热。没有第二个索引服务或模型客户端。

## Lifecycle invariants

1. 无绑定/无读取权时不扫描。读取状态不触发模型或自动创建可执行权限。
2. 首次打开可读缓存；用户发起生成后原维护任务执行。未变化时不重新调用模型。
3. 变更对账 → 过期 → 去抖排队 → 快照 → 原 Run → 校验 → 发布；每范围复用原单活动维护任务，失败等待明确重试。
4. 源/范围变更使陈旧候选拒绝发布，旧结果带过期标签可读；取消/重启不重复外部副作用。
5. 禁止任务拖入、拖出项目。项目归档、任务归档或合法目录改绑使旧范围的生成退休；恢复重新核验原 ID、物理根和权限，保留单独归档的任务及编辑器草稿，不把旧异步结果发布到新范围。
6. 源码/资料只读，Wiki 输出可重建；任何通用配置仍为宿主 ACL，不由 Wiki Markdown 控制模型、权限、预算或后端。
