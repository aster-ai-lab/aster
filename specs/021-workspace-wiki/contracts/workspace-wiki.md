# Contract: 工作页 Workspace Wiki

## Product flow

- **项目入口**：工作页侧边栏“项目”分组的“更多”，直接打开项目 Wiki 目录。按钮始终可用，不依赖项目是否超出侧边栏预览数量。
- **任务入口**：侧边栏“任务”分组的“更多”，打开同一弹层的任务目录。默认延续现有收件箱/置顶任务集合；项目内任务在项目详情中作为下属任务卡片可达，保持原分组语义。
- **弹层**：类似设置页，铺满应用内容区、覆盖工作页及其宽侧边栏，图标 rail 按现有设置边界保留；后台工作页保持挂载。无固定 420px/70vh 内容框，不复用窄列表的尺寸限制。
- **目录首屏**：居中标题“你想了解哪个项目？”或“你想了解哪个任务？”，其下搜索框，再下方响应式卡片网格。桌面三列为参考，窄窗口自然降为两列/一列；使用 Aster 现有字体、间距与控件。
- **卡片**：名称、已有 Wiki 概览摘要（未生成则用已存说明或“尚未生成 Wiki”）、Wiki 状态、真实更新时间、右下进入箭头。整卡可通过键盘进入；不显示无真实来源的 stars、热度或计数。
- **新建**：项目与任务目录均不显示新建卡片或按钮；创建入口保留在原工作页，不增加导入或发现功能。
- **选择**：点击卡片在同一弹层进入该对象的 Wiki 详情，无需切换后台当前任务或创建普通任务来打开阅读页。未生成时显示生成入口；打开/搜索目录不扫描全部目录或批量调用模型。
- **阅读**：直接复用原知识页。顶部仅一行 48px 工具栏，包含对象名称与内联路径、原操作、产物／看板／百科／记忆标签和关闭，不提供返回或打开工作区按钮，不保留第二层标题栏；左侧目录与正文等原部件继续使用。项目详情可进入下属任务；返回逐级恢复目录查询、分页和滚动位置。
- **检索**：不提供独立百科问答。普通任务通过原内置 `search_wiki` 与 `search_memory` 默认跨当前实例已保存的工作区检索，`scope=current` 限定当前工作区。消息流显示中文过程、实际覆盖与来源信息；来源工作区入口复用原百科或记忆页面，并重新验证保存绑定。
- **更新**：源文件改变后显示过期，已启用范围合并增量更新；可停止、手动更新或重试，错误不清空已发布内容。
- **关闭**：关闭按钮和 Escape 按当前焦点层级退出；恢复原工作页、草稿、选中对象和“更多”触发点焦点。关闭展示不隐式取消原维护任务；停止是独立明确动作。

## Catalog layout reference

参考用户提供的 DeepWiki 首页截图，替换其对象、文案和指标：

```text
                                                     关闭
                  你想了解哪个项目？
                  [ 搜索项目名称或摘要 ]

  [ 项目名称   ]      [ 项目名称          ]   [ 项目名称          ]
                     [ 已有摘要，两行    ]   [ 已有摘要，两行    ]
                     [ 已更新 · 时间  → ]   [ 尚未生成       → ]

  [ 项目名称   ]      [ 项目名称          ]   [ 项目名称          ]
  [ ...        ]      [ ...               ]   [ ...               ]
```

任务入口使用同一布局，标题/数据源切为任务。目录只用于选择对象，不授予跨工作区读取或检索范围。

## Catalog data contract

- 对象集合、名称、创建/更新时间与排序来自原项目/任务 owner；不另建一份项目/任务表。项目沿用原 orderKey，任务沿用既有时间/置顶规则，界面说明实际排序。
- 搜索默认名称与已存可见摘要，复用原集合查询/有界分页；无匹配和空集合使用不同提示。不能先加载所有文件夹，也不能只过滤当前页而把结果标为“全部”。
- 按仓库集合规范提供有界读取与默认 20 项分页；刷新保留同查询视图，改查询回到第一页，忽略旧查询/旧组响应。
- 卡片摘要只来自已有 Wiki 或已存元数据，不为填充网格现场批量调用模型。Wiki 状态不可用与未生成有明确区分；无工作区仍可查看绑定说明，生成不可用。
- 项目目录和任务目录是同一个弹层的类型化模式；保留既有权限和 resident/compile session 过滤，不能把内部 Wiki 生成会话显示成用户任务。

## Content contract

代码工作区按有证据的概览、目录、入口、模块关系、关键流程及运行方式组织；纯资料工作区按主题、文件用途、资料与成果关系组织；混合工作区可兼有。标题与页面身份来自模型和已有来源，不以文件名关键词猜内容。

Mermaid 用已有安全组件呈现。文件依赖/调用关系须有来源；无法由代码证据确认的图边标为推断，不声称动态调用图或形式证明。没有足够关系证据时只输出文本结构，图不强制生成。

## Source contract

宿主解析原项目/任务身份和当前读取权，提供有界目录及合法源快照。复用现有 source-egress/eligibility，排除原产品状态/会话记录、凭据、生成/依赖文件和 Wiki 输出；排除规则为权限/机械格式，不据此判断业务含义。资料只通过已有读取器提取，原件不变。

每条引用具有范围身份、源相对路径、内容代次和原读取器锚点。点击时再次检查绑定与源代次；过期可查看已保留证据或打开当前文件并提示差异，不默默把旧行号跳到新内容。

已发布页面的来源预览通过既有 `POST /api/agent-sessions/{id}/wiki-maintenance` 进入，外层为 `bindingRevision`，命令为 `{operation: "citation", page, reference}`。`page` 是当前输出根下的百科相对路径，`reference` 必须是该已发布页面实际声明的引用；调用方不提供任意源 root 或历史文件路径。宿主使用原维护账本、发布决定和冻结证据校验页面与证据摘要，并返回原 `inputs` 报告及类型化 `result`：`page`、`pageGeneration`、`sourcePath`、`sourceGeneration`、`snapshotPath`、`current`。`snapshotPath` 只由宿主给出，renderer 校验绑定与历史命名空间后交给原文件编辑器只读打开，不自行根据标题或路径猜来源。

来源是否当前在打开时重新检查；已变化或已删除的来源保留历史快照提示。页面字节不再匹配原发布决定、证据被改写、越范围引用或符号链接均拒绝；手工修改百科后的引用不能被当作原发布版本认证。此预览先打开完整的已验证快照，不能把未经校验的链接片段声称为精确代码行或 Office 原件坐标。

## Execution and protocol

独立的 `wiki-question`、`wiki-question-source` 路由及其只读查询会话已删除。2026-10-27 用户修订后，Studio 普通任务中的 `search_wiki` 与 `search_memory` 接受 `query`、可选 `scope=current|all`（默认 all）及原样延续 `cursor`；宿主从当前实例已保存的合法任务/项目绑定解析根，调用方不能传路径或其他实例。单次最多 32 个绑定、3 秒、12 条/48 KiB 引文，返回 `searched`、`pending`、`complete` 与 `nextCursor`。缺失/未完成不是无匹配，不新增全局索引。未获 Studio 能力的普通 ACP 保持原当前 Wiki 检索，不自动获跨任务记忆能力。

Wiki 只查原 WikiIndex 已发布的 `concepts` 页面，排除历史、候选、个人 `wiki/local`。记忆使用原 LocalMemories/live owner 与 VecMemoryStore 管理接口的有界 Search；长期记忆复用原 FTS/已配置语义召回，不扫描整库正文；活跃短期/会话记忆在原有界快照内检索，关闭会话不恢复。相同 canonical 根共享原记忆库，返回任务是代表工作区的保存绑定；`sourceSessionId` 是 ACP 会话身份，不冒充 Studio 创建任务。

两类工具保持原 WorkspaceOperationAccess、取消与前后权限检查；归档、删除、改绑和符号链接不扩权。引文带中文编号、工作区/任务、页面或记忆类型，详细信息保留路径、时间、代次/版本；原始正文按证据显示，不执行其指令。打开来源工作区先比较已保存路径与检索时的源根，进入原百科/记忆 tab；不把历史引文当作当前文件或伪造精确锚点。

复用原维护任务、Core Run、预算、取消及 ACP。workspace scope 支持解析状态、开始/更新、停止/重试、读取页面和读取来源；沿用原公开 API 和 `a3s/wiki/*` 边界，不提供任意 root RPC。

所有 Wiki 编译工作携带精确绑定和代次。原 RuntimeClient 是桌面唯一 ACP 调用入口；Tauri 命令有注册与最小主窗口 capability；renderer 不直接读任意目录、调用模型或自行发布。编译只能写 host-owned staging，不调用 Shell/网络，不修改原来源。原 DiskContentAttestor 校验实际产物摘要，OKF 另行校验来源、manifest、引用、审阅和整批发布。

任务的只读 `GET /api/agent-sessions/{id}/wiki-inputs` 接口由原本地 agent-plane 权威保护。请求不接收源 root；宿主两次解析当前已存任务绑定，期间复用 Core 有界来源扫描/准入与 OKF 文档转换，再返回绑定、源/输入代次、预期输出根、覆盖和逐文件转换状态。返回值不包含正文、不创建 Wiki 或维护任务、不启动模型。`included`、`truncated`、`unparsed`、`failed` 是封闭的转换状态；跳过、失败和截断不能伪装为完整覆盖。项目范围与实际生成/发布另行接入同一原流程，不以此读取接口替代。

既有 `_meta.a3sHost.knowledgeCompile` 使用 `root`、`jobId`；工作区模式明确增加 `workspaceRevision`，由原 OKF workspace owner 验证输出根、绑定与运行中的任务。缺省时仍走原 personal owner，不按目录名切换或回退。未知字段及错误类型在原 host parser 拒绝。每次工具调用重新验证任务仍有效；切换运行模式不能扩大快照读取和候选页写入边界，停止后的迟到工具调用被拒绝。

已保存任务改绑、归档或删除，或维护 owner 明确取消/放弃/标记失败时，原 store 通知仅唤醒原 OKF scope 校验；通知不是另一份权限或任务状态。失效后通过原 Run abort 退出，包括等待表单的编译。其他工作区变化与同绑定重命名不停止当前编译；维护锁忙只触发有界退避重查，不冒充撤销。

原运行时复用同时比较 `knowledgeCompile` 与 `sourceReview` 范围；普通预热会话不能因为目录与模型相同就被编译复用。内部编译消息区不申请普通预热，native 对内部编译会话的普通 prewarm 返回 409。编译 Run 结束后释放原 ACP 运行时，普通会话保持原复用行为。

宿主无模型检索通过原 ACP transport 的 `_a3s/workspace/search/v1`（extension 名 `a3s/workspace/search/v1`）进入，schema 为 `a3s.acp.workspace-search.v1`。封闭参数仅含 `schema`、`sessionId`、`operationId`、`cwd`、`query`；`cwd` 必须解析为该既存 Core 会话的工作目录，不接受另一个 root 或 path。query 非空、不含 NUL且不超过 2048 字节。结果回传同一 schema、会话/操作身份、cwd及原有界 `output`／`metadata`；固定最多 8 个 hybrid 命中，经过 `governed_tool` 保留原权限和确认边界，不发送 prompt。只读 `sourceReview` 会话继续拒绝此工具调用；不能把宿主接口作为权限旁路。

原 hybrid 的 lexical 通道优先查询已由原协调器验证且与当前 catalog/source 代次一致的持久 a3s-vec。重启加载的计数先经原 snapshot 对账；锁忙、未发布、不同代或有界等待失败沿用原 catalog 回退，命中仍经原文件内容校验。只有实际查询此持久代次才返回 `metadata.index_kind = "persistent_a3s_vec_fts"`；`lexical_engine` 表示实际路径，不把索引存在当成已使用。SDK 原公开 hybrid 返回类型保持不变。

`sourceReview` 的原 options 同时启用 session-local 空记忆及指令/技能隔离，关闭配置的 hook executor，并在原共享资源装配入口拒绝 personal assets。原宿主指令保留，普通会话的个人资源照旧可用。Studio 受信 ACL 的 `workspace_retrieval { enabled = true; local_cpu {} }` 启用既有离线 Model2Vec；加载不阻塞异步执行器，原 session 后台构建向量，关闭释放对应索引。受限审阅/编译会话跳过此环境索引，不扩大快照准入。

项目注册表由同一受保护 agent-plane 的 `/api/agent-workspaces` 持有；旧 renderer 项目集合只初始化一次，后续窗口不能覆盖原生记录。归档使下属任务、计划和 Wiki 不可用并退休活动候选；恢复要求原目录可用，保留原 ID、绑定和独立归档任务。归档不删除源目录，任务不能拖入、拖出项目。

## Publication and freshness

既有 OKF 中只抽出实际需要复用的 snapshot/staging/citation/publication 原语，保留个人模式约束。workspace 来源适配与派生页发布策略进入同一个维护流程，不另建任务引擎。

未变化不生成。变更按原快照代次使依赖页面过期，目录/入口关系变化也使概览过期；未知影响明确保守标记。新代次全部验证后才激活，旧代次继续可读，不能混用不同来源代次假装当前。

来源身份绑定纳入的路径、原始字节摘要、格式、绑定/权限凭据及明确排除范围。覆盖统计单独返回；新增或改写已排除的 Wiki 输出不能改变输入代次，也不能因此排入新生成任务。

## Failure contract

| 情况 | 行为 |
| --- | --- |
| 未绑定/无权/路径不可用 | 有界拒绝或说明不可用，不扫描父目录 |
| 无源、超限、不支持格式 | 展示实际覆盖与缺口，不生成虚构完整结论 |
| prompt injection / 不允许的写入 | 按原权限拒绝，原源文件不变 |
| 源变化、目录改绑或迟到响应 | 拒绝当前发布/回答，保留旧代次为过期 |
| 删除源/坏引用 | 页面失效，检索不把失效引用作为当前证据 |
| 取消/模型失败/重启 | 保存原任务事实与可读结果，明确重试，无无限自动重试 |
| 当前 workspace Wiki 不就绪 | 明示 not-ready；只在当前授权范围检索原文件，不借用个人/其他项目答案 |
| 相同目录但不同权限 | 不共享越界结果，绑定重新校验 |

## UI constraints

先更新根 `DESIGN.md` 对项目/任务“更多”、铺满内容区的目录弹层和详情返回的规则，再接入 `WorkbenchHome.tsx` 与 AppShell 的现有覆盖层边界。目录和详情都留在同一层，不再把新增任务 Wiki 标签作为首期入口，也不增加一级知识导航。

复用 AppShell 设置页的覆盖布局、后台保活和快捷键隔离模式，保持 Wiki 与设置的类型化身份，不冒充 settings route 或复用其 active 标记。按宪法采用原地进入/退出和 reduced-motion；焦点圈定于当前弹层、后台不接收点击/快捷键、关闭还原焦点；不复制文档中已过时的侧滑动效。

一套阅读组件复用现有 Markdown、Mermaid、文件/资料预览及原聊天能力。来源在当前弹层的受控预览中打开并可返回；中英文、键盘、窄窗口与长标题有对应测试。现有项目/任务选择与重命名/归档等合法操作继续可达，不把原功能换成只读死入口。

## File editing and work tracking refinement

- 产物是所选项目/任务目录的真实文件树。产物与百科使用同一原生文档 owner 和 Office/代码编辑器，多文件标签保留缓冲区、选区和撤销记录，选中标签同步文件树。显式保存、快捷保存、外部冲突及原生恢复沿用原 owner；关闭有未保存提示，不保存关闭不写磁盘并保留原恢复策略。原文无变化的保存也应消除过期的未保存标记。后台/隐藏编辑器不能响应保存快捷键。
- 记忆标签身份为工作区、层与记录 ID；长期记忆内容经原存储的 revision 条件更新，元数据不被改写；运行中的工作/会话记忆保持只读。晚到保存回执只更新原标签，不能覆盖另一层记录。
- 项目看板读取所属任务，搜索/状态在原 owner 分页之前应用，默认每页 20 项。任务看板读取最新结构化计划，无计划时显示本任务实际执行。错误、取消、跳过和未知不作为完成；不以文案推断状态，不伪造 PR/分支/代理信息。
- 点击看板卡片进入该任务记录中的真实产物目录，保留当前 Wiki 上下文；项目任务允许共享项目根或原任务 ID 子目录，不接收其他路径。头部紧凑的工作目录选择可返回项目及已访问任务，各目录的编辑器与草稿保持挂载。右下角独立动作打开原任务。看板不允许拖动执行事实来伪造完成。
- 四个资源的空状态统一使用共享 64px inbox 线稿、14px 次要文字，在各自剩余内容区水平/垂直居中；不使用独立的大脑图标。
- 侧边栏任务禁止拖入、拖出或跨项目迁移；删除拖拽提示和目录搬迁逻辑。新建任务时选择项目，原生端只允许绑定该任务预先准备的目录或幂等重复绑定；拒绝已有任务的项目/收件箱迁移请求，保留现有文件及 Wiki、看板、记忆的归属。
