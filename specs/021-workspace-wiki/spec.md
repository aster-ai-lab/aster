# Feature Specification: 项目与任务工作区 Wiki

**Feature Branch**: 当前工作区；未请求新分支或提交

**Created**: 2026-10-25

**Status**: Implementing；尚未完成或验收

**Input**: 用户明确：“我最想要的其实是 DeepWiki 的功能，就是针对工作页的每个项目和任务的工作区做 Wiki 理解”。本规格取代 020 的当前优先级。

**UI clarification (2026-10-25)**: 用户提供 DeepWiki 卡片目录截图，指定从工作页侧边栏“项目”和“任务”分组的“更多”进入，打开类似设置页、铺满页面的弹层。此交互替代早先项目行入口/任务 Wiki 标签方案。

**UI refinement (2026-10-25)**: 移除 ActivityBar 的“知识”，分组更多打开项目／任务 Wiki 目录，卡片在同层直接复用原 KnowledgePage。详情为一行 48px 工具栏，仅保留资源操作、切换和关闭；Escape 返回并恢复目录状态。项目与任务目录不含新建卡片，删除标题下与网格下的解释文字。资源依次为产物／看板／百科／记忆，沿用原文件树、搜索、编辑器、图谱与维护组件，并严格绑定所选工作区。四处空状态统一使用共享 EmptyState 的居中插图与文字。产物与百科复用实际文件编辑器，多标签保留缓冲区；记忆支持多标签及持久记忆修订保存，运行时工作记忆遵守原只读策略。切换资源保留草稿，关闭前确认未保存内容。看板从原任务及结构化计划投影真实状态，点击进入对应任务记录中的真实产物目录并保留 Wiki 上下文，头部可切回项目或已访问任务且草稿不丢失，另有打开原任务操作。已有能力保持可用，尚未接入的工作区整体生成不得伪造。

**Gate context**: 工作页 Product regime 与既有根工作区 OKF crate；复用 workspace 检索、代码理解、知识维护及 Core/ACP 执行。Wiki 的对象是当前项目/任务的文件工作区。个人知识库、团队百科和会话日志保持既有范围。

**Latest goal (2026-10-25)**: 深度完成工作区 Wiki 的开发与端到端测试，证明实际有效与效率；工作区同时提供给底层 a3s code ACP 检索，自动异步构建 a3s-vec 索引。复用原 manifest、catalog、a3s-vec 持久投影和原会话生命周期，不新增索引服务。默认本地 FTS／原 hybrid 检索；语义向量继续遵守已有 ACL 与 provider 选择，不隐式启用远端 embedding。

**User revision (2026-10-27)**: `search_wiki` 与新增 `search_memory` 默认跨当前实例的已保存任务/项目工作区检索，支持 `scope=current`，不跨实例/租户。百科为发布的 OKF 文件，产物为原源文件；知识编译复用原文档处理工具。看板置于最后，默认无需 Git，沿用执行、校验、审查、交付范式，已有 Git 项目按需走 CI/PR。消息流中的两类检索必须展示中文过程、实际覆盖情况及引文来源，来源跳转重新校验绑定。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从项目打开可阅读的 Wiki（Priority: P0）

点击侧边栏“项目”分组的“更多”，打开铺满内容区的 Wiki 卡片目录，展示已有项目；无需先创建普通任务。选择项目卡片后，在同一弹层阅读或生成其工作区概览、文件组织、关键模块/主题及流程说明；每页带来源。

**Why this priority**: 先让用户快速建立对整个工作区的理解。

**Independent Test**: 项目工作区解析与隔离测试；隔离代码/资料夹具经实际维护任务生成导航、正文及有效引用，原文件摘要不变。

**Acceptance Scenarios**:

1. **Given** 一个已绑定工作区的项目，**When** 点击项目“更多”并选择其卡片，**Then** 在同一弹层显示该项目范围、已有 Wiki 或生成入口，不要求创建普通任务或复制到个人知识库。
2. **Given** 没有可用源文件，**When** 打开 Wiki，**Then** 显示空工作区或不可读原因，不编造项目结构或自动扫描应用主目录。
3. **Given** 项目数量未超过侧边栏预览数或为空，**When** 查看分组头，**Then** “更多”仍可进入目录；关闭弹层恢复原页面、草稿和触发按钮焦点。

### User Story 2 - 每个任务理解自己的工作区（Priority: P0）

点击“任务”分组的“更多”进入同一弹层的任务卡片目录，延续该分组任务范围；项目内任务可从项目详情的下属任务卡片进入。Wiki 跟随所选任务真实 cwd 与当前授权，独立目录分别生成，同一目录且相同读取范围可复用已生成结果。

**Why this priority**: 项目归属不等于任务使用同一个目录，任务仍可能通过已有工作区选择器切换目录。侧边栏不再提供任务拖入、拖出项目的交互。

**Independent Test**: 独立任务、项目子任务、同目录、不同目录、切换目录、无 workspace 与跨租户用例；旧异步任务不得发布到新范围。

**Acceptance Scenarios**:

1. **Given** 两个任务使用不同目录，**When** 打开 Wiki 或由任务检索百科，**Then** 分别使用各自文件，不因同项目合并范围。
2. **Given** 相同工作区、来源规则、读取权限和源代次，**When** 第二个任务打开 Wiki，**Then** 可读取同一发布结果，无需重复调用模型。
3. **Given** 任务通过已有工作区选择器改绑目录，**When** 旧生成返回，**Then** 不写入新范围，不继续显示旧范围为当前结果。
4. **Given** 搜索并滚动后选中任务，**When** 从 Wiki 详情返回，**Then** 恢复原目录范围、查询、分页和滚动位置，不切换后台当前任务。

### User Story 3 - 阅读、检索与追溯（Priority: P0）

用户在全屏弹层的 Wiki 详情中从目录树阅读页面、原百科图谱和适用的 Mermaid 结构/流程图；图谱节点、页面和来源打开原多标签编辑器。普通任务自行判断是否调用内置 `search_wiki` 或 `search_memory`；默认跨当前实例已保存的合法工作区，也可限定当前范围，不提供单独问答入口或运行时。每条引文保留原合法绑定；证据不足时说明缺口。

**Independent Test**: 固定检索夹具与来源断言证明结果来自当前合法百科；图谱、过期锚点、缺失来源、重复片段和提示注入均有负对照。

**Acceptance Scenarios**:

1. **Given** 代码工作区，**When** 阅读入口与调用流程或由普通任务检索百科，**Then** 内容有源码依据；未确认的关系明确标为推断。
2. **Given** 文档/产物工作区，**When** 打开 Wiki，**Then** 根据内容组织主题、文件用途和成果关系，不套用不存在的软件架构。
3. **Given** 点击来源，**When** 对应文件已变更，**Then** 显示引用版本/过期提示，不把旧行号当作当前证据。

### User Story 4 - 文件变化后持续保持理解（Priority: P1）

生成后持续观察已启用工作区的文件变化；改变、删除、重命名会让受影响页面过期并排队更新。用户可立即手动更新、停止、查看失败和重试；未变更的工作区不反复生成。

**Independent Test**: 文件监视/对账、去抖、单个原维护任务、来源到页面关系、取消/重启和原子发布测试；验证 Wiki 输出不会被再次当作输入。

**Acceptance Scenarios**:

1. **Given** 页面引用的源文件改变或被删除，**When** 文件对账完成，**Then** 显示过期并安排受预算约束的更新，不继续宣称最新。
2. **Given** 生成期间源发生变化，**When** 准备发布，**Then** 拒绝陈旧候选，旧版本仍可阅读且标明代次。
3. **Given** 工作区未变化，**When** 反复进入/重启，**Then** 不新增生成请求；失败任务等待明确重试，不无限循环。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 从现有项目/任务绑定解析 canonical workspace 与读取范围；MUST 拒绝靠名称/路径相似性猜绑定、无目录时扫描父级，以及改绑后的迟到结果。
- **FR-002**: MUST 从侧边栏项目/任务分组的“更多”提供 Wiki 卡片目录，两个入口在少量/空对象时也可用；项目内任务可从项目详情进入。目录与项目 Wiki 使用原合法集合，任务 Wiki 只覆盖实际工作区。MUST 拒绝把目录范围扩大成跨项目、跨租户读取或父目录扫描。
- **FR-003**: MUST 复用有界文件目录、检索准入和 source-egress 策略，读取已保存代码、文本及现有读取器可提取的资料；MUST 排除凭据、运行日志/会话状态、依赖/生成目录和 Wiki 自身输出，不默认纳入聊天正文。超限/不支持 MUST 报告覆盖缺口。
- **FR-004**: MUST 生成持久的工作区概览、结构与关键主题页面，并依据实际内容补模块/流程/运行方式/资料与产物关系；标题与关系由模型结合证据提出。MUST 拒绝关键词猜业务含义或无证据填充模板。
- **FR-005**: MUST 使用原知识维护流程的快照、staging、校验和发布机制，编译只可读取获准快照并写入 Wiki 候选。MUST 拒绝修改原工作区或获得 Shell、网络和通用写权限。
- **FR-006**: MUST 为页面、图示和回答保存合法源文件、范围与内容代次；源码按行、资料按已有段落/页/表格锚点追溯。MUST 拒绝不存在、越界、陈旧或伪造的引用成为当前证据。
- **FR-007**: 按 2026-10-27 用户修订，MUST 删除百科独立问答及其专用代码。普通任务通过原 `search_wiki` 默认跨当前实例已保存、合法有效的任务/项目工作区百科检索，`scope=current` 只查当前工作区；MUST 排除 `wiki/local`、团队、历史、候选与其他实例/租户。模型不能传根路径，不得新增模型客户端或全局索引。
- **FR-008**: MUST 增量标记受影响页面、去抖合并并受原预算/取消约束更新，未知依赖影响至少标记相关概览过期；MUST 拒绝输出回灌、未变更重复生成和失败后无限自动重试。
- **FR-009**: MUST 以当前合法范围、源代次及发布代次提供只读快照；同范围可复用结果，权限/规则/源不同不得共用。MUST 保留上一可读版本并拒绝部分发布造成混合代次。
- **FR-010**: MUST 从分组“更多”打开类似设置、铺满应用内容区的弹层，先卡片目录、再在同层阅读 Wiki/图谱，复用 Markdown/Mermaid/文件预览；返回保留目录状态，关闭恢复后台页面和焦点，并隔离后台交互。MUST 拒绝窄列表弹窗、另建一级导航、第二聊天运行时或原生 select；更新根 DESIGN 的目录弹层规则。
- **FR-011**: MUST 保持个人 vault 的原目录限制、人工笔记和重要更新审阅语义；工作区机器生成页可经来源校验自动替换。MUST 拒绝把任意目录伪装成个人 vault 或复制整库进入个人知识空间。
- **FR-012**: MUST 使用类型化闭集、原单写者/Run 与恢复链和主窗口最小权限，配置继续用宿主 ACL；MUST 拒绝 UI 自主执行、未知值、旧绑定恢复或新存储/索引/调度服务。
- **FR-013**: MUST 用代码、纯资料、混合及多工作区夹具独立验证覆盖、引用和源文件不变，并保留原生/真实模型证据；MUST 拒绝把脚本模型和静态预览冒充真实 Wiki 理解效果。
- **FR-014**: MUST 以既有项目/任务集合及分页提供名称/已存摘要搜索、真实排序和可访问卡片；卡片显示名称、已有摘要、Wiki 状态与更新时间，目录不显示新建卡片或按钮，原创建流程保留在工作页。MUST 拒绝伪造星标/热度/摘要、只搜当前页却宣称全部、一次无界加载或打开目录即批量扫描/生成 Wiki。

- **FR-015**: MUST 在原 ACP 工作区会话中异步准备并增量维护原 a3s-vec 索引，不要求首次搜索才能启动。MUST 保持界面与会话打开不等待全量构建，冷启动保留有来源校验的检索回退，复用原文件监视与关闭/取消链；编译候选会话不索引来源工作区或混入个人/团队内容。必须验证延迟接入、文件更新、秘密排除、关闭后拒绝、重复进入与实际 ACP 检索；不得另建检索服务或仅以目录存在冒充有效命中。

- **FR-016**: MUST 向原 a3s code ACP 提供 `search_memory`，默认跨当前实例的已保存工作区，支持当前范围与有界延续；复用原长期记忆索引，短期/会话记忆仅查现有活跃 owner。结果保留工作区、代表任务、记录、独立层级/类型、时间与版本。MUST 保持只读、权限撤销与实例隔离，不唤醒关闭任务、不为未使用工作区建空库、不把不完整检索当作没有结果。
- **FR-017**: 两类检索 MUST 在消息流显示中文调用名、查询、范围、真实等待/执行/结果状态、可得的工作区覆盖数及编号引文；来源细节使用原宿主元数据，旧结果缺少字段时不得编造。来源按钮复用原工作区百科/记忆页面，改绑/删除/归档时重新拒绝，正文与路径不执行为 HTML 或任意跨工作区文件链接。

### Key Entities

- **WorkspaceWikiBinding**: 现有项目/任务身份、实际 workspace、读取范围与变更代次的精确绑定，由宿主解析。
- **WorkspaceSourceSnapshot**: 受准入/egress 限制的源与结构快照，带真实路径、范围、内容身份和覆盖报告。
- **WikiGeneration**: 原 OKF 维护任务发布的页面集合与出处，输出根由宿主拥有，不能与 source root 混同。
- **WorkspaceEncyclopediaRetrieval**: 普通任务原 `search_wiki` 的已保存工作区绑定、当前百科页面及去重结果，不创建独立问答会话。

## Success Criteria *(mandatory)*

- **SC-001**: 从项目和任务分组“更多”均可打开铺满内容区的卡片目录，选择对象进入同一弹层详情；项目内任务可从项目详情进入。少量/空集合仍有“更多”，无 workspace 的卡片有明确不可生成原因。
- **SC-002**: 小型代码、纯资料和混合夹具均产出概览、目录与有效来源；代码夹具能解释入口和一条跨文件流程，资料夹具能解释指定产物的来源。
- **SC-003**: 每条受测百科检索结果的文件/范围/代次合法且不重复；没有当前内容时报告缺口。点击来源可打开正确文件与锚点，源码变化时不会假装引用仍当前。
- **SC-004**: 原源文件摘要保持不变；越权/注入、目录改绑、同目录异权限、秘密文件、输出回灌均不能扩展读取或修改范围。
- **SC-005**: 未变更重开触发零新增生成；实际变更导致过期和可观察更新；失败/取消/重启不会重复发布或丢失上一版本。
- **SC-006**: 原生桌面完成更多 → 搜索卡片 → 项目生成 → 任务查看 → 图谱／多标签编辑 → 打开来源 → 返回目录 → 关闭恢复，以及源修改/更新和普通任务检索旅程；中英文、键盘与窄窗口可用，目录状态/后台草稿/焦点正确。
- **SC-007**: 未选对象只浏览/搜索卡片时新增生成请求为零；非当前分页对象可搜索到或明确显示搜索范围；每张卡片状态来自合法已有记录，后台快捷键不会穿透弹层。

## Assumptions

- 用户已授权开发；未请求提交或部署。真实模型验证使用隔离夹具，不批量发送用户工作区。
- 首期主要支持本地已保存文件；已有资料转换路径可复用，不新增 OCR/转换服务；无 Git 的工作区也可生成。
- 首次从 Wiki 入口发起生成。随后该范围可按原预算与生命周期增量维护；新建每个任务不会立即全量调用模型。
- 019 的原运行时/会话边界作为实际集成依赖，不复制其未收敛路径；不要求完成 020。

## Explicitly Not Claimed

- 业务验收、自动修复、安全审计和生产回滚；020 保留为后续备选。
- 自动理解全量仓库、动态真实调用图、全格式资料支持或无来源的历史业务意图还原。
- 默认导入所有聊天/记忆、跨实例/租户的全局索引、公开 Wiki 托管与团队云端同步。
- 新知识引擎、向量服务、调度器、数据库、知识库复制或第二 Core/Review 运行时。
