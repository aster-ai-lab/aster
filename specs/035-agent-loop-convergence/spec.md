# Feature Specification: 自主循环与长程任务去重机制融合

**Feature Branch**: 当前 `main` checkout；不创建分支、worktree 或提交。
**Created**: 2026-11-01
**Status**: 035首轮已实施并评估；US5/US6优化续篇正在实施和验收。
**Input**: 将 DeLoop 的重复动作信号用于 Aster 长程任务优化；先审查既有机制，再制定详细开发计划，避免重复机制和无效设计。
**Gate context**: 根工作区的 `aster-core` 与 `aster-effect`。承接 `017-acp-long-horizon-e2e` 的 FR-005、FR-006、FR-011、FR-014，并沿用 `010-unified-progress-model` 的进展契约。本规格只拥有循环机制融合，不接管这两个规格的验收。

## User Scenarios & Testing

### US1 — 拒绝重复调用时保留真实副作用（P0）

用户需要工具拒绝、输入钩子和取消的结果可解释。宿主不能把已经发生或尚未查明的副作用标记成零副作用。

**Why this priority**: 当前静态审查发现准备后覆盖回执的路径。必须先用真实准备流程复现，才能确定修复范围。
**Independent Test**: `aster-effect` 调度测试及 Core 的实际 `ExecutorTools` 准备测试。检查钩子/工具执行次数、原始拒绝、回执 completeness 和未解决副作用。
**Acceptance Scenarios**:
1. Given 调用已在执行输入钩子前因重复被拒绝，When 调度完成，Then 钩子和工具均不执行，拒绝绑定原调用身份。
2. Given 输入钩子已经产生副作用，When 随后拒绝或取消，Then 回执保留已观察变化或不确定状态；不得重写为完整空效果。
3. Given 权限拒绝或参数错误先成立，When 同时存在重复候选，Then 不掩盖原始拒绝，也不扩大权限。

### US2 — 压缩和恢复不刷新重复额度（P1）

长任务压缩历史后，已发生的重复仍计入当前工作区间。更换调用 ID、重开会话和摘要文字不能创造进展。

**Why this priority**: 压缩是长任务的常用路径，不能削弱既有消耗边界。
**Independent Test**: 有界受控模型驱动真实事实日志。分别运行保留全部消息和反复只保留最新工具对的压缩场景，比较实际调用与终态。
**Acceptance Scenarios**:
1. Given 阈值为 3 且工具始终返回相同观察，When 每次压缩丢弃早期调用消息，Then 重复仍在原额度内触发现有拒绝和终止机制。
2. Given 日志重放或重新打开同一会话，When 继续相同工作区间，Then 统计与连续执行一致。
3. Given 用户明确追加输入或出现符合现有契约的真实进展，When 重新判断，Then 按原规则允许继续；不得为防循环取消合法推进。

### US3 — 新观察与必要复验继续执行（P1）

相同参数不必然代表无效操作。新外部观察和修改后的复验不得只因调用次数被拒绝。

**Why this priority**: 降低重复消耗时必须保持合法任务完成能力。
**Independent Test**: 相同参数连续返回 7 个不同的受控观察；另测稳定观察、A/B 状态回访和文件修改后的复验。
**Acceptance Scenarios**:
1. Given 7 次相同调用各产生新观察且总预算足够，When 无本地文件变化，Then 允许完成；不得只按参数次数拒绝。
2. Given 输出、结果状态与有效参数均重复，When 没有真实进展，Then 消耗既有重复额度；不同 ToolCall ID 不刷新额度。
3. Given 文件字节改变，When 再次执行同一验证，Then 保留既有复验行为；同字节重写不制造进展。
4. Given 已观察状态 A/B 反复切换，When 无新信息，Then 保留现有状态循环终止。

### US4 — 自主续跑和消耗统计保持原契约（P1）

工具级融合不能给 Goal、子任务或失败重试增加预算。用户需要实际消耗和完成结果分别可核对。

**Why this priority**: 每个 Run 单独停止仍可能留下跨 Run 的无效消耗。
**Independent Test**: Core 原有 Goal/ChildRun 测试及 ACP `unattended_e2e`。比较实际模型请求、工具执行、settlement 和完成回执。
**Acceptance Scenarios**:
1. Given 无进展 Goal 达到限制，When 再次 tick 或重开会话，Then 仍需要输入；不得因新恢复计数器获得机会。
2. Given 已接受的新计划，When 现有规则准许一次续跑，Then 只使用这一机会，仍受原预算约束。
3. Given 合法宿主等待、取消或未知副作用，When 检测循环，Then 继续使用原有类型化处理，不能猜测命令含义或伪报完成。

### Edge Cases

JSON/图像结果、空输出、不同退出码、附加宿主提示、重复批次、钩子改写参数、旧日志、截断观察、Unknown、后台子任务、非 git 工作区、空格与非 ASCII 路径、工具轮数为 0、取消发生于准备边界。

## Requirements

### Functional Requirements

- **FR-001**: MUST 先以真实实现复现三个静态审查发现；无法复现的项 MUST 记录为推翻或未确认，不得为满足原结论修改产品。
- **FR-002**: MUST 保留准备和终态回执的原调用绑定、拒绝来源与副作用；MUST NOT 在输入钩子可能执行后直接生成完整空效果。
- **FR-003**: MUST 让现有去重统计从原始事实恢复并跨压缩保持；MUST NOT 将模型可见消息或摘要作为统计的唯一来源。
- **FR-004**: MUST 使用工具、生效参数、宿主观察、outcome 和退出状态判定机械重复；MUST NOT 将耗时、调用 ID、附加提示或工具自报元数据当作新信息。
- **FR-005**: MUST 贯通新信息判据与既有调度准入；MUST NOT 拦截预算内持续新观察，并保留真实修改后的复验和 A/B 状态循环检测。
- **FR-006**: MUST 复用既有重复阈值、Goal continuation、完成门和预算；MUST NOT 添加独立恢复状态机、额外恢复额度或新的产品配置。
- **FR-007**: MUST 保留 `aster-effect` → 通用效果类型、Core → `aster-effect` 的依赖方向；MUST NOT 让 effect 依赖 Core 或识别 Core 私有结果封装。
- **FR-008**: MUST 保持现有公开 Rust 调用和结构体构造兼容；必要的扩展只能是有默认实现的兼容接线，不得新增必实现方法或必填公开字段。旧日志保持可读，缺少可比较观察不能冒充新进展。
- **FR-009**: MUST 覆盖父任务、ChildRun、压缩、重放和 ACP 的真实入口；MUST NOT 用旧循环测试代替主事实路径证明。
- **FR-010**: MUST 分别记录任务正确性、实际请求/工具次数、provider usage、轨迹字节与耗时；MUST NOT 用估算 token、提早失败或缺失 usage 宣称节约费用。
- **FR-011**: MUST 冻结输入、模型、预算、grader 与首轮结果；MUST NOT 调整已有冻结测试或重试覆盖失败以获得通过。

### Key Entities

- 原始 `ToolPreparedV1` / `ToolExecutionResultV1`：沿用 `aster-effect` 所有权和身份契约。
- 新信息身份：沿用 Core `information_identity` 的规范化观察含义。通用比较原语如需共享，由 effect 拥有；Core 负责私有封装解析。
- 去重统计：现有 scheduler 的派生状态，可由事实重放，不建立第二份持久化账本。
- Goal slice：沿用 V3 进展基准和既有 continuation 配额，不新增恢复生命周期。

## 用户追加：验证闭环与真实GLM失败优化

授权实施上一轮评估后的优化。US5：同一完成门的当前验证状态应紧邻最新工具观察，明确exit 0不等于当前修改已经验证；模型系统前缀不因可派生验证状态变化，原事实/观察身份不变。无工具尾部时保留原system投影。完成后再修改仍必须重新验证。

US6：沿原relay有界观察原生Messages响应的usage与stop reason，缺失/截断/冲突仍Unknown/Invalid，不存reasoning正文。原模型、fixture、grader、600s/1800s/40/4096预算不变。独立新预算实验须另行预注册，不覆盖旧结果。用冻结pair分别比较五个Rust任务与新观察/压缩任务，复核原有恢复机会但不增加机会。

US6实测补充：输出因max_tokens截断且存在未验证修改时，原完成门错误不能掩盖已捕获的ForcedStop::ResponseTruncated；SDK错误保留两种typed来源，既有错误前缀和恢复含义不变。失败仍失败，原效果债务不被结算。

### 实测续篇：压缩与截断保真

当模型长度截断且仍有验证/未知效果债务时，SDK错误保留两项原因，不伪造完成。摘要调用只整理已经观察的事实及已经算出的中间值；非空但长度截断的输出不成为可靠摘要。两个现有压缩入口一致处理，并使用原失败回退。验收继续使用原GLM路由、原任务和预算，原失败保留。

### 用户追加：通用优化与防过拟合

目标：继续深度优化并确保不存在过拟合优化。复用既有事实日志、压缩器、预算、工具呈现和完成门，不添加独立控制器或持久化状态。优化规则不得识别模型名称、任务文件名、订单字段、已知公式、fixture seed 或预期答案。

- US7：自动事实压缩复用现有 `CompactionBudget`，为实际固定提示和保留尾部预留空间。成功摘要与失败回退服从同一可用摘要预算；原用户目标、开放约束和可信来源仍由原 seal 保护。预算不可满足时如实报告，不把摘要长度冒充完整提示长度。
- US8：仅在有可回收历史时调用摘要模型，避免对固定前缀造成的压力反复支付摘要费用。保留压缩重放、取消、必要新观察、批次边界和原有预算；不能靠提前失败或跳过必要工作获得收益。
- US9：新验证跨上下文容量、固定前缀占比、Unicode、摘要成功/失败/截断、再次压缩和原始日志恢复。保留原算术失败任务及其完整验收；独立工程和原生文件任务事前注册。无可靠配对版本时不宣称因果收益。
- US10：原生文件的格式/保存字节验证与任务语义正确性分别报告。模型公开推导中的公式错误不由宿主硬编码修补。业务正确性仍由原独立验收器判定。

新增成功门：通用回归无降低；真实同模型任务正确交付并正常结束；全部首次失败计入消耗；冻结输入和验收器未变；独立任务未出现为单个用例调优的退化。不存在过拟合只能通过实现约束和独立覆盖提供证据，不能由一个通过用例证明。
