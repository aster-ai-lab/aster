# Evaluation contract

每项 case 使用显式 ID，包含题目来源、允许/禁止输入、输入 SHA-256、输出合同、评分依据、超时及独立作业路径。任务 JSON 只用于测试，不影响产品权限。

每次尝试保留构建来源与摘要、实例/PID/窗口、受测模型的公开 ID、会话与原 Run、开始/结束/终态、产物摘要、每项断言、后台动作回执、耗时和可获得的 token/调用计量。凭据、用户会话、答案和源材料正文不进入公共证据。

成功需要同时满足：真实原生 Aster 路径、当前原 Run 收尾、后台动作合格、输入未变、产物格式与内容合格、独立评分和预算。缺一项则失败或未完成；不将不可用、取消、超时、未冻结评分或豁免换算成通过。

Office 检查保留数据与行/实体的关联，并实际打开或解析输出；PPT/图表还需检查实际图形与数据。仅声明“已生成”或文件存在不合格。T01 检查原始数据、精确整数、事件顺序/去重、确定性及变化输入；最优行动小夹具用独立穷举核对。正则按原契约测试跨行与边界；Git 同时验证恢复、清理、合法历史和工作树完整性。

答案与参考解法只在评测侧。不得把它们提供给 Aster、根据其内容代写输出或修改任务、断言、超时来消除失败。
