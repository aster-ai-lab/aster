# Aster 剩余对齐路线图

更新：2026-11-03。此文件记录本轮提交之后的工作顺序，不启动新的开发任务。
沿用 [tasks.md](tasks.md) 的任务编号、[能力清单](contracts/capabilities.md) 和
[UI 复用映射](ui-reuse.md)，不重建第二套功能清单或设置入口。

## 已完成的本轮基线

- 修复原有服务商配置状态、重新加载和隔离备份后重置的接线；保留租户策略。
- 修复 MCP HTTP+SSE 的配置地址、服务端端点通知、POST 202、SSE 响应匹配及取消清理。
- 修复密钥显示/隐藏按钮的可访问名称，更新必要调用方与测试 fixture。
- 真实 Aster ACP 文件任务通过 12/12 项目测试与未修改的 8 项外部验收；原生输入/发送、工具暂停、上游取消、服务商保存/探测/设置页重开和用量展示已验收。

具体命令、失败历史和验证边界见 [P0 验收记录](../../docs/evidence/desktop/2026-11-03-p0-stability-e2e/OUTCOME.md)。
文件任务通过原生 HTTP API 提交，原生输入/发送另有独立检查；不能合称整次文件任务全部经原生界面提交。
设置页重开已测，完整退出并重新启动应用的手工验收尚未做。
这些结果不关闭全部 CAP 或历史任务，也不构成 Magpie 全量替代声明。

## 已停止的范围

- Aster 不继续开发 Hermes、OpenClaw、DeepSeek Harness 或其他第三方运行器的托管、安装、配置同步、启动/停止、专用 dashboard、Profile 或机器人传播适配。
- 历史 CAP14–CAP17 及相关任务中依赖第三方运行器的部分停止推进，不能标为已实现。Aster 自身 Agent/ACP、CLI 与通用 provider、协议、工具能力继续保留。
- 共享宿主中其他租户仍使用的代码不能仅因文件名含第三方产品名而删除；先证明 Aster 入口/产物隔离，再清理确无调用的代码。
- 不复制已有页面、模型选择器、配置 owner、预算/计量引擎或安装状态系统；不为对齐清单新增 Aster 产品账号。

## 每轮更新规则

只接一个可独立验收的用户流程。先列已有入口、owner、实际缺项和失败用例；完成必要调用方、权限与 fixture 后运行所属检查。
回填现有任务和证据，保留未测/失败状态与原始编号。跨平台、真实账户、性能和发行分别声明，不能互相代替。
