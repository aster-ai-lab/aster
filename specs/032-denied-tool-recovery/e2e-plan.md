# Aster 目标恢复系统性端到端测试计划

**范围** Core、ACP stdio、CLI 真实 PTY、无人值守、安装版 CLI/ACP。Mac 原生 Terminal 用 `agent-desktop` 验证可见交互。Core 继续负责执行权限、核验与预算，ACP 投影结构化状态，CLI 在同一会话呈现可操作的状态。安装和升级使用现有发布契约。E30–E53 保留原样本与判定，E54–E62 补验关键状态转换、并发、长时间运行和新 Shell 启动。 [规格](spec.md) · [E01–E29](plan.md) · [执行任务](tasks.md)

## 共用验收条件

- **任务连续。** 从观察、批准到完成，可在 Core 事实、ACP 更新与 CLI 历史中关联到同一 Session、Goal、步骤和适用的 Run。冷加载新增模型请求和工具启动均为零。显式继续后使用原有预算与已核验产物。
- **执行可证明。** 拒绝、过期输入和会话错配导致的启动为零。受控的一次性执行由独立计数和产物字节证实。未知效果保持待核验。只有匹配当前工作和证据的可信决定可以结算对应义务。
- **停止有边界。** 服务器 HTTP 尝试、模型决定、工具启动、自动切片及回合终态分别计数。硬停生效之后新增推理和执行为零。取消后，旧连接、子进程和待答交互按既有生命周期收束。普通下一轮仍可运行。
- **完成有验收。** 同时核对 Goal 事实、当前变更的有效核验和独立产物。独立步骤完成时，必做的依赖步骤继续保留。模型说「已完成」、ACP 返回 `EndTurn` 或终端出现成功文案，均须与原始验收证据对齐。

## P0 · 确定性合入用例

每行先以最小 fixture 验证首个失效边界，再通过绑定相同验收的真实 ACP 或 PTY 验证。用 loopback provider 控制时序，使用真实 Core、工作区、存储与进程。破坏性故障只打在新建的隔离 fixture 上。

| 用例 | 操作和注入点 | 通过条件与落点 |
| --- | --- | --- |
| E30 · 完整恢复自动等待 | 带两个依赖步骤的 Goal 先独立写入并核验，再在真实问题或审批已显示、尚未答复时硬停 ACP。对照同一条件下由宿主显式登记的 Goal 等待。分别执行 `session/load`、显式续做、拒绝或有效新答复。 | 冷载入保留前缀、原步骤、预算和阻塞信息。旧答复的执行增量为零。问题有已支持的恢复入口。需审批的写入按实际有效参数获得新授权且最多执行一次。无人值守返回可操作的待输入状态。Core Goal waits、ACP `shipped_tui_e2e`、PTY。 |
| E31 · 本机进程启动与结算 | 分别在本机工具准备凭据落盘且目标进程未启动、写入已观察且回执未落盘、成功回执落盘且 Goal 未结算时中断。由本机进程生命周期和文件记录独立标定。MCP 工作启动边界作单独对照。 | 报告三处各自的启动、写入、回执和结算计数。启动前区分已证明未启动与未知；效果未知时，同操作、新参数写入和其他写入的启动增量均为零，允许已授权的观察或核验；成功回执后只补结算。以现有恢复契约证明解除核验后可继续。Core 事实回放、安装版 ACP。 |
| E32 · 不完整观察推动重规划 | 精确扫描得到完整零匹配、截断零匹配和截断部分匹配。截断组把有效证据放在独立的后续可读取路径。在一组重复原查询，在另一组按允许路径补取证据。 | 回执、模型输入和用户能看到的结论一致。重复不完整结果在既有预算内终止。补到真实证据后允许继续，使用独立产物确认最终结果；交互与无人值守均测。Core 搜索、`unattended_e2e`、ACP stdio。 |
| E33 · 原权限和工作区隔离 | 用用户明确拒绝、宿主策略拒绝和获得一次性审批的三个对照。同一调用经现有 hook 改写有效参数，分别检查匹配批准与需重新审批的情况。覆盖可信与未受信工作区配置，以及两个独立临时工作区。 | 原授权与当前有效参数、会话和工作区一致才执行。改写或过期后的旧审批执行为零；允许的替代步骤仍可继续。两个工作区的审批状态和产物互不影响。Core 权限、ACP `approval_rules_stdio`、`workspace_layer_trust_stdio`。 |
| E34 · 消息与回合交接 | 让真实 ACP 连接在运行、等待、结算前后分段关闭，分别覆盖 CLI 排队后续输入、用户取消当前轮、主动退出并 `--resume`。由既有 ACP relay 在已观察事件处切换。再用基础 ACP 客户端忽略可选恢复字段运行相同任务。 | 已显示的工具行和待答状态在原会话各结算一次。队列按现有行为推进。协议仍可解码，当前端缺少交互能力时有稳定的失败或等待状态。后续正常提示能完成。ACP conformance、`shipped_tui_e2e`。 |
| E35 · 持久故障后的再续做 | 在加载或接受新操作前，用实际临时持久目录制造写锁冲突、只读写入目标、损坏尾部和工作区身份不符。每种故障使用独立 Session 和同形完整日志对照，另测可恢复故障消除后再续做。 | 按现有格式契约恢复或给出稳定错误。可读已验证前缀保留；从加载开始到报告持久化故障，或到只读加载完成，推理／执行增量为零。清除可恢复故障后，结算只发生一次。Core store、ACP `protocol_commands_stdio`。 |
| E36 · 原期限对传输与反复拒绝生效 | 拒绝后让 loopback provider 分别停在首字节前、输出半段响应、返回可重试状态、按脚本反复拒绝。用事件触发切点，另在真实工具运行中取消并观察进程退出。加一次压缩和冷恢复。 | 每种故障记录重试与模型决定的实数，按原预算和绝对截止结束。申请重新规划、压缩和重开保持原额度。已取消或硬停后再发请求／启动为零。原会话下一轮仍能响应。`unattended_e2e`、ACP 真实进程、PTY。 |
| E37 · 多阶段目标与依赖 | 脚本让第一阶段通过实际检查、第二阶段等待可信输入、第三阶段依赖第二阶段。在相同初态分别走有效输入、用户拒绝、预算耗尽、核验不匹配。另跑直通编码对照。 | 第一阶段只写一次。等待时保留独立工作，依赖步骤保持未启动；有效输入后按原权限继续。真实匹配核验与全部必做步骤完成才有最终完成事实。接受时检查精确 diff、可执行检查和对照文件摘要。Core Goal、`unattended_e2e`、PTY。 |
| E38 · 持续可用性与资源回收 | 在同一 PTY Session 用确定性 provider 连续交替运行五对回合。每对先触发拒绝恢复或可控故障，再读取一个新值。在运行时取消，在轮间固定插入 `/compact` 和冷重开。额外保留无故障对照。 | 十次提示各有一个匹配终态，全部结束后无遗留子进程、等待卡或连接，原预算守恒。记录每回合墙钟时间和请求数。最后一次读到新的原始标记，前面的已完成写入次数不变。复用 `shipped_tui_e2e` 和现有十回合 PTY 驱动方式。 |

### Kimi 样本与超时归因

- 冻结提示、工作区初始摘要、模型 ID、投影入口、允许的工具及产物核验脚本。E39–E41 各登记三个首轮样本。新短回合沿用每个提示 120 秒、测试端收到问题或审批后 10 秒内答复，长任务的总预算与切片上限在运行前登记。现有套件使用其自身已冻结时限。凭据只经现有 ACL 配置入口加载，原始记录使用合成工作区。
- 为每轮建立单调时钟时间线。可观测点包括推理请求发起、响应首字节、可解码的模型决定、客户端收到问题或审批、答复、工具启动／退出、回执持久化与终态。模型目录查询单列。同步记录尝试次数、已报告用量和每段耗时。缺失字段保留未知，少量样本逐个报告。
- 首轮保留原始结果，复跑和判定变更用独立记录。超时后仅在受控环境重放同一可解码决定，使用相同 fixture 和权限核对链路。若在相同决定下重现停滞，按最先失效的 Aster 层定位；若链路正确且决定未满足冻结要求，记模型行为；HTTP 或流故障按可见事件记供应商／传输；缺关键节点则归因未定。测试 fixture 和环境失败单列。

## E45–E50 · 恢复状态与复合故障

每个变体使用单独的临时工作区、Session 与进程，预先保存一个已核验的前置产物及其摘要。先跑正常对照和已知失败，再从下表指定的事件切断连接或进程。用已持久化事实、实际 ACP 消息或由 fixture 持有的进程标定切点。没观测到指定事件时，记录该变体未执行并保存原因。等待观察的超时属于夹具时限，产品预算和终态单独记录。

| 用例与现有入口 | 首轮变体与切点 | 独立判定 |
| --- | --- | --- |

## E51–E53 · 真实模型、可视化与安装版补验

### E51 · Kimi 首轮样本

每行预登记一个独立首轮。使用 `../config.acl` 中的 `kimi-01/k3.1-pro`，固定实际选用的模型、初始文件摘要、提示、可操作范围、核验器和时限。E39–E41 原样本继续使用原有判定。新增样本允许额外合法只读探索，验收绑定实际审批、当前 Run 核验和独立检查。

| 样本 | 实际入口与任务 | 通过所需证据 |
| --- | --- | --- |
| E51-01 | ACP stdio，经过一次确定的工具拒绝后完成小修复 | 有确定拒绝回执，原操作启动 0 次，允许的替代动作满足原验收 |
| E51-02 | macOS CLI，遇到可选路径受限的正常编码任务 | 正常代码改动、精确 diff 和测试通过。单列合法直达或实际改道 |
| E51-03 | macOS CLI，模型产生真实问题后冷开，继续依赖步骤 | 保留同一 Session、已核验前置产物和原问题，通过恢复入口采用匹配答案，仅完成后置阶段 |
| E51-04 | ACP stdio，模型提出真实审批后冷开，提交旧回复再给新审批 | 旧回复启动 0 次，新许可只对应实际有效调用，新增写入与核验各 1 次 |

E51-01 至 E51-04 每次新提示上限 120 秒。收到需要答复的当前请求后，10 秒内执行预登记操作。断点样本先按计划中断，重开后再答复。冷加载与外层清理各使用独立的夹具时限，开跑前登记。E51-05 和 E51-06 各用 360 秒产品预算与 390 秒外层时限，Goal 切片和重试限制按冻结配置记录。E51-03、04 依赖 E45 的对应交互路径。E51-05 依赖 E37 的匹配核验与不匹配负对照，E51-06 依赖 E30 的无人值守待输入分支和 E37 的依赖门槛。供应商首字节慢、模型决定偏离、Core 拒绝、ACP 投影缺失、终端输入失配及夹具校验出错分别归因。未出现预登记触发事件时，保留该首轮及其覆盖缺口。复跑另记样本。

### E52 · 用户实际看到的状态

## E54–E62 · 跨边界验收

覆盖单位是一次可观测的状态转换。从接纳、模型决定、待答、准备、启动、效果、回执、核验到 Goal 结算，每个会改变权限、工作区或终态的节点都跑正常对照和一个相邻故障。表中指定的高风险组合逐一执行。其余变体用最少的用例让每种有效入口、平台特有行为和工具类别都出现，并在登记时注明对应覆盖。相邻切点用事实序号、实际启动标记、客户端收发事件或持久目录字节确认。共享失败先用所属包密闭用例固定，再经受影响的实际入口复验。

## 交付证据与验收决定

每个样本记录 `E 编号 / 样本 / 候选 / 平台 / 入口 / 命令 / 注入事件 / 首轮判定 / 原始证据路径`，附事实前缀、用户可见终态、推理／审批／执行计数、各段耗时和产物摘要。对照用同一个 Session、Goal、步骤、Run、调用和审批身份关联事件，重连时将新旧连接分开标记。失败样本记录首个偏离预期的事件、所属层和最小复跑入口。运行结果进入 `docs/evidence/code/<日期>-<场景>/OUTCOME.md`，附真实检查数量和 `Explicitly not claimed`。原始附件保留在现有本地证据目录，逐项移除凭据、授权头和非 fixture 数据。

P0 逐用例及适用入口决定合入验收。P1 逐模型样本、视觉场景和原生发行件决定发布资格。每个适用变体按 `通过`、`实测失败`、`未触发`、`环境阻塞` 或 `待执行` 记录，设计上不适用的组合需附契约依据。Core 的 Goal 终态、ACP 的回合终态和终端画面分别核对。业务正确但被旧判定拒绝的首轮继续保留原结果。修改验收条件前，先登记新的样本编号。E45–E53 的当前执行状态见实测记录。原生 Windows x86-64、Linux x86-64 GNU 与 musl 的发布资格等待对应归档的原生运行记录。 [扩展实测](../../docs/evidence/code/2026-11-26-kimi-tool-recovery-e2e/OUTCOME.md#additional-e45e53-observations)
