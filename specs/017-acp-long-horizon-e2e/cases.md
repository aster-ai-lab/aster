# ACP 长程 E2E 用例目录

**状态：全部 PLANNED，未执行。** A–L 是 120 个产品场景；M 是 10 个测试系统自证场景，单独统计。参数变体不会偷偷增加基础用例数。真实模型、TUI、GUI 和 soak 都不能从同 ID 的本地模型通过自动继承资格。

每例继承 [plan.md](plan.md) 的基础前置 B、F0–F8 故障屏障、实际进程边界、deadline 与精确 owner 清理。表中“前置”是 B 的补充，“动作”按分号从左至右执行，oracle 是必须同时满足的断言。P0 表示安全/状态/交付可信度或发布必需，P1 为完整资格/耐久要求；C0/H0/H1/R/U/S 定义见计划。每个变体单独记录 `case_id + variant_id + seed + attempt_id + surface + feature + backend + platform`。

证据组：E0=冻结身份/前后 hash/命令 cwd/能力/终态/cleanup（每例必需）；W=有界 wire 与 ToolCall 回执；A=权限/信任/批准绑定；F=文件差异/当前 digest/副作用账本；S=提交代、历史、usage/Goal；N=受控网络请求和上游原始错误；R=单调时钟、资源/进程/队列；U=真实用户可见状态及必要截图/VT/打开文件；O=独立 oracle 与其负对照。不可采集的必要证据必须形成缺口，不得默认通过。

合法重试、恢复或降级的 oracle 只要求系统已承诺的行为；尚未提供的接纳上限、对账接口或进程边界将产生 RED/BLOCKED 的实现项，不能由测试私自创造产品能力。未知资源身份、权限与封闭字段按锁定契约拒绝；版本按协商规则处理，schema 允许的扩展字段可忽略但不能授予能力，不靠错误文本关键词猜意义。

## D — 工具执行与副作用

实施补充（2026-10-24）：C01 增加 `native-data-multiturn-real-diagnostic` 诊断 variant，6 个用户回合分别改变数量、单价、税率、折扣和币种；每轮验收当前 JSON、源文件与用户草稿。它不需要命令执行，不代表 LH01 的 Rust 编译/测试旅程，不与原自由修复/显式顺序变体互相替代，也不构成发布可靠性样本。需要命令的变体须先通过当前 sandbox backend preflight。

后续独立 variant `native-data-multiturn-disk-attested-real-diagnostic` 明确使用既有宿主 `completionAttestation=disk_content`：产品只绑定当前字节摘要，外部 checker 另验语义。没有宿主 attestor 且禁止命令的默认 profile 已实际命中 completion gate 拒绝（首轮和 SOLO 证据保留）；不得用新 profile 改写它的结果。规范 v2 明确 units 为数量总和。B04/F03 已按当前实际 TurnQueue 的 32 个等待槽修正规划，原 busy 假设不是产品契约。

C01 / LH01 的 Rust 诊断 variant `rust-multifile-host-contract-real-diagnostic`：fixture seed 2401，交互 ACP 默认严格完成门；显式宿主合同为 `rustc --edition=2021 --test lib.rs -o checks && ./checks && test -s CHANGELOG.md`，覆盖三个可修模块、CHANGELOG 和实际编译测试程序 checks。先失败、允许一次修改多个文件、再通过；不使用 disk_content 或 waiver。H1 用一个 completion 的四个独立 write 验证合法批量修复；R1 使用真实模型自主修复。R1 预算 40 次实际上游调用、每次最多 4096 输出 token、单 prompt 600 秒、旅程 1800 秒。H1 prompt 上限 180 秒。受测进程回收后，将当前有界文件快照放入另一个已资格化 compiler VM 执行隐藏验收；不在宿主执行模型代码。宿主保护文件与隐藏 checker hash 均须保留，当前完整 runtime 的文件/权限/链接摘要须前后一致。该单 seed 是诊断，不代替剩余样本、fault variants、TUI/GUI 或发布可靠性。

后续 H1 `masked_verification_is_repaired_with_the_admitted_exact_command` 先故意追加 echo，使一次成功的测试执行不符合精确宿主合同；脚本必须在实际下一请求收到当前可覆盖改动的合同诊断，才允许发出不带附加内容的原命令。随后必须收到 bound Verified、最终答复及独立 guest oracle 通过。该路径保留前次不合格核验，不新增宿主 waiver，也不通过重发整个用户目标完成修复。R1 后续 cohort 的 fixture、提示与通过条件均不降低，首次失败保留，合同引导修复和纯观测改动分别记录。
