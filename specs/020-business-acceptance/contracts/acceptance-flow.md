# Contract: 任务内业务验收

## User flow

1. 用户发起原任务；模型通过既有 Goal/Plan 路径提出少量业务条件和未决问题。
2. 用户查看条件与检查关联，确认精确修订。没有可用宿主合同则显示未配置，不执行候选命令。
3. 通过原 Run 执行已绑定检查；原权限询问和沙箱判定保持独立，业务确认不能代答执行许可。
4. Core 投影逐项结果；桌面在原 Goal 区域显示摘要，展开后查看原始证据。CLI 消费同一摘要。
5. 用户对失败项发起修复；沿用原 Review/Run 路径，并用当前实现执行同一已确认检查。
6. 后续任务显式选择历史条件作为新 proposal，重新确认绑定并取得新证据。

## Command and event boundary

- 复用 `aster/goal/*` 的类型化宿主边界；确有缺失时增加闭集操作和 owning-package 测试，不新增通用 RPC 分派器。
- 确认操作带 session/workspace、Goal/Plan 修订、proposal/sequence 和 operation identity；按原 Goal admission 验证。
- 规则草稿/提案通过既有模型调用和事实记录，不新增 Studio HTTP 模型请求。
- 执行只能走原 Run admission 与工具路径；读状态不能启动执行或重建丢失的权限。
- 状态及证据来自 Core 快照和 ACP 类型化输出；保留既有 terminal 语义，附加视图不能自创完成判定。
- Studio 经 `RuntimeClient` 调用。Tauri 入口由现有主窗口 capability 最小授权；不授予 applet 该权限。
- 所有读、证据片段和历史选择有界；超限显式拒绝/分页，错误与日志不携带凭据或用户敏感测试数据。

## Failure contract

| 条件 | 用户能看到的结果 | 必须保持的边界 |
| --- | --- | --- |
| 未确认、无绑定或部分绑定 | 未检查与下一步 | 不能全部通过 |
| 旧修订/迟到回执/输入变化 | 已过期 | 原历史保留，不静默换修订重试 |
| 未配置合同或无合格后端 | 无法执行及配置/资格原因 | 不改权限、不绕过沙箱 |
| 原检查非零退出 | 检查失败与真实回执 | 不从失败文本猜业务结论 |
| 取消/超时/断流/无原始回执 | 执行未完成 | 不当作检查通过或已知业务缺陷 |
| 模型伪造报告或自改标准 | 拒绝当前证据 | 需新确认和真实执行 |
| 重复 operation | 原幂等结果或冲突 | 不重复执行 |
| 外部工作区/租户引用 | 既有 not-found/refusal 合同 | 不泄露资源存在 |
| 用户显式豁免 | 已豁免及范围 | 不能标为已验证 |

具体错误码复用既有 Goal/Verification/权限错误集合；确需新增时先在 Core 定义闭集并同步 ACP、Studio parser 和测试，不在前端拼接推断。

## Acceptance fixture

首条旅程使用隔离的订阅权益夹具：重复事件只能发一次额度，取消生效时间由已确认规则决定。用固定输入和独立断言验证真实状态；不接真实支付、邮箱或生产数据库。后续补一个双用户隔离夹具检查作用域，但不宣称提供通用安全扫描。

## UI contract

复用 `WorkbenchProjectTray` / 原 Goal 区域及 `useStudioGoal`；不新增一级导航、第八个右侧页签或退休的 `AgentTaskDetailPanel`。错误保留草稿，确认须对应当前修订；异步旧结果不写入新任务。状态有文字与图标，键盘可操作，中英文可用。涉及布局变更时先更新根 `DESIGN.md` 对应规则，再提交 UI。
