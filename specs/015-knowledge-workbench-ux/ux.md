# 本地知识工作区：统一信息架构与交互

**版本**：2026-10-24 第三版，替代第二版的两级资源导航及不同页面布局。  
**状态**：三个资源与审核的主要表现层已迁移，列表操作已改为横排透明图标；整体验收未完成，空工作区初始化仍有真实失败。[实现检查点](../../docs/evidence/desktop/2026-10-24-knowledge-unified-implementation/OUTCOME.md)。  
**范围**：015 知识工作台及 [018 本地记忆](../018-local-memory-studio/spec.md) 的表现层。  
**设计权威**：[根 DESIGN.md](../../DESIGN.md)，特别是第 6、14 节。

## 1. 三个对象，一套工作台

中文导航固定为「知识 → 笔记 / 百科 / 记忆」。百科对应 Wiki；具体页面称为百科条目。

| 同级入口 | 对象 | 真实主动作 | 边界 |
| --- | --- | --- | --- |
| 笔记 | 用户记录、导入的原始资料 | 新建、查找、编辑、手动保存 | 移动/重命名继续经现有影响审核；冲突不覆盖 |
| 百科 | 根据原始资料整理的已发布成果 | 阅读、查看来源、整理与审核 | 已发布正文只读；候选不冒充发布成果 |
| 记忆 | Agent 在当前范围保存的事实与经验 | 内容搜索、类型筛选、查看、确认删除 | 不支持手动新增/编辑/批量删除/撤销时不画这些按钮 |

资料是笔记的原始内容，百科是整理成果，记忆是 Agent 的持久记录。
普通新增内容仍可按现有策略自动发布；需要审核的修改先进入候选，不能为了改版更改发布策略。
不再增加与笔记含义重叠的“知识库”入口，也不把三个 owner 的查询拼成虚假的统一结果。
分类使用明确 owner 身份，不从标题、关键词或内容推断。

```text
知识（当前工作区）
├─ 笔记：记录 → 查找 → 编辑 → 保存
├─ 百科：阅读 → 查看来源
│  └─ 整理与审核：资料状态 → 候选比较 → 采用 / 保留
└─ 记忆：查找 → 查看 → 确认删除
```

整理与审核属于百科的生命周期，不是第四种内容；不再打开另一套全屏管理后台。

## 2. 固定的位置契约

```text
应用栏 │ 知识                                   当前工作区 [范围信息]
       │ [笔记] [百科] [记忆]
       ├──────────────────────┬─────────────────────────────────────
       │ 对象名称     主动作  │ 当前对象身份          状态   对象动作
       │ 搜索框              ├─────────────────────────────────────
       │ 已生效条件（有才显示）│ 标题
       │ 内容列表             │ 正文 / 详情 / 当前与建议修改
       │                      │
       │ 局部状态与续页       │ 来源 / 附加信息（按需展开）
       └──────────────────────┴─────────────────────────────────────
```

- 页头只有标题、当前范围和三项资源 Tab。工作区选择由现有应用外壳负责，不另加一个选择器。
- 左侧首行固定对象名称与一排图标按钮，其后为整行搜索框、条件标签、列表、局部状态及续页。新建、文件夹、快速打开、刷新和筛选直接可达，不再收进更多菜单或竖向堆叠。
- 右侧首行固定对象身份、状态和对象动作；正文起点不随资源切换改变。没有选中对象时不画假的路径或保存状态。
- 搜索、筛选、刷新作用于列表；保存、删除、采用修改作用于当前详情。视觉一致不意味着把不同 owner 合成一份数据模型。
- 常见动作优先使用图标按钮：新建、搜索、筛选、刷新、保存、返回、更多。每项保留明确的无障碍名称及键盘可见的 house tooltip；确认删除、采用修改等结果敏感动作保留文字。
- 图标按钮静止时透明、无边框，不使用主按钮填充；悬停与键盘焦点沿用工作区的中性反馈。去掉资源列表的介绍文字和重复的空态引导，仅保留标题、搜索、真实内容及必要状态；失败状态使用简短文字与重试图标。
- 筛选使用 house Popover，垂直排列条件，不在 240px 侧栏塞四格下拉。没有可用条件则不画筛选按钮。
- 列表使用同一选中背景、图标、文本层级与滚动区。路径用于确切身份或同名区分，不机械重复标题和文件名。
- 关联信息、图谱、更多字段和存储路径按需打开。重要的保存、冲突及恢复失败始终可见。

| 固定位置 | 笔记 | 百科 | 记忆 |
| --- | --- | --- | --- |
| 列表动作 | 新建笔记、文件夹、快速打开、刷新、筛选 | 刷新、整理与审核、筛选 | 刷新、搜索、类型筛选 |
| 搜索 | 现有标题/正文查询 | 独立的 published scope 查询 | 实际内容字段；保留显式提交 |
| 筛选 | 现有目录、标签、排序 | 只呈现 owner 已支持的条件 | Core 的四类真实记忆 |
| 列表行 | 标题、必要路径、匹配摘要 | 标题、来源或身份 | 原文摘要、类型与记录时间 |
| 当前对象动作 | 保存、现有显示模式、文档信息 | 只读标识、来源 | 确认删除 |
| 正文 | 现有 Office 编辑器 | 已发布正文与来源 | 纯文本、类型、时间及有值的标签 |
| 附加信息 | 关联/图谱 | 引用资料/版本 | 折叠的更多字段/存储信息 |

搜索文字、条件、选中身份及列表位置属于各自资源，切回来恢复原位置。
保留现有笔记防抖/IME 与记忆显式提交的不同读取成本约束。

## 3. 整理审核留在百科工作台内

进入后保持页头、三项 Tab、左侧宽度、搜索位置及详情起点。
左侧动作变为“返回百科”，列表变为候选队列，右侧显示当前内容与建议修改。

```text
知识 / 百科
├─ 左侧：更新审核 [返回百科]
│        搜索待审核修改
│        候选标题 + 确切来源
└─ 右侧：候选身份、版本、待审核状态
         当前内容 / 建议修改
         [保留当前内容] [采用此修改]
```

默认进入待审核内容。资料状态、运行记录使用明确的次级入口进入与返回。
没有候选且整理中断时，以 owner 的事实显示中断及现有恢复动作，不把遗留状态称为正在整理。
每项决策仍绑定显示中的确切候选和版本；失败保留比较，过期重新核对，成功选择下一项。
不增加全部采用、自动发布、第二个调度器或模型调用；后台状态不能自动切换页面。

## 4. 阅读、查找与写作的完整交互

### 进入、浏览与新建

1. 进入笔记，恢复当前范围内最后阅读的确切对象与位置；对象已删除时解释原因并展示最近打开/笔记列表，不按标题替换。
2. 空集合保留列表主动作，主区只保留简短空态标题；不在中央重复新建按钮。无匹配、未选择、加载失败与真正空集合分别呈现。
3. 点击笔记打开正文。新建后焦点进入标题/正文；失败保留填写内容，不悄悄创建第二份。
4. 文件树行内按钮、右键菜单和键盘菜单统一动作。移动/重命名继续使用已审核影响及恢复日志，不简化为直接文件操作。
5. 草稿恢复提示只在确有未处理草稿或读取失败时出现；与当前笔记有关的问题靠近文档，不长期占用文件树大段空间。

### 搜索与快速打开

- 一个常驻全文搜索框，结果在原浏览器内替换树；清空恢复原树展开与位置。
- 笔记与百科仍有独立 owner scope。搜索框名称反映当前范围；顶层 Tab 明确当前范围，不再叠加一个范围下拉；各资源恢复自身文字、条件和续页。
- 第一版不承诺混合跨范围结果。若未来合并，必须分别保留覆盖、续页和计数，或先由 owner 提供统一契约；不在浏览器端拼成虚假的全库精确总数。
- 常用操作只有输入和选择；排序、目录/标签筛选放入一个“筛选”入口。已生效条件必须显示为可移除标签，不能藏在面板里。
- 行首为标题，其次为路径；搜索时补一条匹配摘要。只有同名才提高路径视觉强调，不堆叠无关标识。
- 快速打开继续使用 `CommandOrControl+Shift+O`，只查标题/路径。通过列表首行的搜索图标和现有快捷键直接打开，关闭后返回触发按钮。
- 复用现有 200ms 本地查询防抖与 IME/单在途请求约束；记忆保留显式提交。不给两种成本不同的查询机械地统一请求频率。
- 准备搜索不阻塞编辑；旧结果可见但标明过期且禁止使用错误版本定位。部分覆盖不显示“全库无结果”；超时、失败、续页失效给出实际可执行的刷新。
- 全文结果进入正文时继续校验源版本和字节范围；已修改的草稿不使用旧位置强行选中。

### 写作与连续性

- 默认复用 Office 可视化编辑；“可视化 / 分栏 / 源码”放进一个有当前模式名称的显示菜单，保留快捷键。
- 文档标题不再与页面标题争夺同一层级。仅一个保存状态位置；未保存/失败/冲突必须有文字，不能只靠点或颜色。
- 手动保存和 Cmd/Ctrl+S 保持现有行为。只有完成现有退出、重启、恢复与 IME 安全门之后，才启用自动保存。
- 切换文档、记忆、审核和图谱均保留草稿；返回恢复焦点、模式、滚动与选择。不为布局重构而销毁有未保存内容的编辑器。
- 顶层 Tab 用方向键选择后，焦点保留在 Tab 栏，遵循标准键盘导航；文档光标与滚动仍然保留。从明确的“返回阅读”或辅助视图关闭路径恢复阅读焦点，不抢走 Tab 的方向键操作。
- 多文档标签/后退前进在后续阶段接入 T009/T013；单文档不展示空标签栏。编辑或明确固定后保护文档；“固定标签页”不冒充书签功能。
- 若 Office 没有公开工具栏/模式控制 API，在 Office 原有 owner 增加最小能力和测试；不复制编辑器，也不使用宿主 CSS 隐藏内部按钮。

## 5. 记忆管理：先回答“记住了什么”

- **范围**：复用统一页头的当前工作区与范围信息入口，不在列表重复解释；详情中的存储信息显示 owner 返回的真实路径。没有读取的旧目录不能被宣称为当前数据，也不自动导入。
- **列表**：内容首句/两行摘要、存储类型、记录时间；摘要只是原文截断，不调用模型生成标题。默认稳定 ID 顺序，界面不标注“最新”或“最相关”。
- **查询**：只搜索实际支持的记忆内容；四种类型使用 Core 存储的情景、语义、过程、工作记忆。筛选依据枚举，不从内容猜测分类，也不暗示工作记忆会自动过期。
- **详情第一层**：完整纯文本、类型、记录时间和有值的标签。检视内容不作为可执行 HTML/Markdown，不执行记忆里的操作指令。
- **更多字段**：重要度、访问计数、最近访问及已有元数据。重要度不是正确率，访问次数不是效果评分；不增加无依据的质量色条。
- **存储信息**：确切 ID、存储路径、工作区范围、原始元数据。信息不丢失，只改变默认展开层级。
- **删除**：在详情中明确命名“删除记忆”。确认展示内容摘要与范围，说明没有撤销；由当前版本进行条件删除。冲突先刷新核对，超时后先确认结果，不能自动重放删除。
- **刷新**：保留仍然存在的选中 ID；已不存在则说明并回到列表。删除后选相邻项，列表空了才显示空态，焦点返回可理解位置。
- **无记忆 / 无匹配 / 无法访问 / 被占用 / 超出查看限制**：分别呈现。服务不可用不伪装为空库；不能靠把内容复制到第二份数据库解决锁冲突。
- **能力边界**：本期不展示手动新增、编辑、批量删除、导出或撤销按钮；如果以后需要，先扩展同一个 SDK owner 的真实能力。

## 6. 更新审核与关联信息

### 知识更新

打开后是百科内的整理审核目的地，保持同一工作台，提供“返回百科”；位置契约以第 3 节为准。
保留共用页头与工作区范围；原编辑器不参与第二份实例化。

```text
[返回百科] 更新审核                          3 项待审核
候选列表              当前版本 │ 建议修改
完整标题/路径          修改原因、对应来源、版本提示
                       [保留当前内容] [采用此修改]
运行记录 / 来源管理（次级入口）
```

- 待审核修改为默认视图；来源管理、运行记录按需进入，不与核心审核铺成三组常驻大面板。
- 原始资料、当前已发布内容、建议修改分别命名；候选不是已发布结果。
- 每次只对显示中的确切修改/版本决策；沿用已有“采用此修改 / 保留当前内容”的 owner 语义。
- 成功有可读结果与下一项焦点；失败/过期保留对比依据。后台整理只更新入口状态，不自动抢走阅读焦点。
- 不增加“全部采用”、自动发布或新的维护调度器。

### 关联信息与图谱

- 关联栏主要回答“这篇笔记有哪些章节、引用谁、被谁引用”。目录与链接分组展开即可，不再默认罗列七八种技术属性。
- 图谱入口放在关联栏，打开后是完整目的地，提供“返回笔记”。还原视口与原阅读状态。
- 图谱默认当前笔记。部分加载时准确写“当前已加载笔记”，不能把 200 篇阅读缓存叫作完整知识库。
- 有键盘可操作的列表替代视图；同名节点显示路径。全库关系覆盖需完成现有 owner 工作，不能只改文案宣称完成。

## 7. 状态、响应式与视觉规则

| 情况 | 放在哪里 | 反馈及动作 |
| --- | --- | --- |
| 保存/恢复保护未就绪或失败 | 当前文档，始终可见 | 说明编辑/退出为何受限；重试、比较、保留草稿，不隐入更多菜单 |
| 外部修改/原文件删除 | 当前文档 | 对比磁盘与草稿、明确另存副本；不静默覆盖 |
| 搜索准备/部分覆盖/续页过期 | 搜索结果区域 | 保留可用内容，说明范围与原因，提供对应刷新 |
| 后台知识整理 | 百科的整理与审核入口 | 真实进行状态/待审核数量；不弹全页通知 |
| 记忆读取失败/被占用 | 记忆列表与详情 | 保留已看内容并标明过期，禁止依赖旧版本删除，提供实际重试 |
| 工作区权限或范围失效 | 受影响的整个工作区 | 停止写入并按现有权限边界撤回数据；明确恢复路径 |

**视觉**：使用 Page `#ffffff`、Ink `#171717`、Body `#3f3f3f`、Field `#f5f5f5`、Selected `#f2f3f5`、Hairline `#efefef`。
沿用 UI 字体、24px 页面标题、13px 控件、12px 次要信息、36px 行、8px 控件圆角、16px Lucide/1.7 描边。
正文保留 Office 排版与可读行宽；不改字体体系、引入品牌色填充导航或给静态区域套卡片。
关键路径、范围、失败原因使用有足够对比的 Body，不依赖浅灰小字。

| 知识内容区域宽度 | 布局 |
| --- | --- |
| ≥1120px | 260px 浏览器 + 主内容；关联栏约 280px，仅在用户打开且正文仍可读时并排 |
| 800–1119px | 240px 浏览器 + 主内容；关联信息通过现有原地对话框打开，不挤出三窄栏 |
| <800px | 单主视图，浏览列表与详情按层级进入/返回；保留查询、选中项与滚动，不额外常驻两栏 |
| 320px / 400% 放大 | 控件换行，审核对比纵向排列；外层页面不横向滚动；源码/长表格在自身区域处理 |

记忆使用相同的列表/详情响应式规律。弹层使用 house dialog/menu，原地出现，焦点有明确返回。
普通动作无需指针；IME 组合态不触发查询、选项确认或关闭；减少动效设置有效。
